# Four-corner through-hole topology: bounded research contract

This describes the next single-solid rectangle case only. The input is a checked horizontal rectangular prism with an existing centered through-hole, followed by the four separated, equal-diameter corner holes produced by the data-only planner. It does not describe arbitrary profiles, patterns, booleans, or assembly references. No existing centered-hole validation is relaxed.

The Boolean worker must independently resolve its live same-mount parent and verify the original profile, centered-cut request, current revision and ordered four-tool plan. Geometry validation cannot establish this ownership. The same native Boolean operation must return a complete response-local topology and history for the exact parent and all four actual input tools. Face, edge, and vertex numbers are local to that response; they are not durable identities.

## Proposed native additions

Keep the existing bounded analytic face/ordered-loop/coedge, mesh, vertex and parent-face history data. Add `fourCornerTools`, exactly four entries, each `{inputIndex, faces}`. `inputIndex` is a unique integer in 0–3 bound by the worker to its corresponding checked planner input. `faces` records the native history of that tool's cylinder and two caps as `{type, same, modified, generated, modifiedEdges, generatedEdges}`. These relations must come from the same operation, not a later geometric match or separately executed Boolean. The precise native shape remains subject to confirmation by the actual authored worker result.

For the currently expected simple case require one valid solid, 11 faces (six planes and five analytic cylindrical walls), 27 response-local edges and 18 vertices, plus the expected analytic volume and profile bounds. The two planar support faces each have an outer loop and five circular inner loops. Each cylinder has two circular rims and one seam represented by two oppositely oriented coedges. Check closed chains, opposite shared coedges, circle frames/ranges, rim elevations, face orientation, analytic cylinder axis/radius/center, finite bounded triangles, manifold incidence and expected signed volume. Triangles are display data and an independent coarse check, never an authored CAD replacement.

Require seven distinct authenticated parent-face descendants, including the previous center wall; check its geometry and its rim incidence against the existing center plan. Require each of the four tool cylinder histories to establish one distinct new wall and two distinct rim edges. The two support-face histories must independently contain exactly the corresponding four newly generated rims each, and each tool rim must actually occur on its claimed wall and the appropriate support inner loop. Refuse missing, duplicate, ambiguous or contradictory provenance. Cap history must match what native proves for this operation, with no unaccounted descendants. Do not infer identity from coordinates, list order, or tessellation.

The geometry validator may return bounded response-local evidence only. A separate adapter must authenticate the same live parent/result handles, map parent traversal to qualified parent semantic IDs, bind each input index to the authored corner role and feature, enforce occupied-ID/collision checks, and attach a synchronous publication guard. The previous center wall/rims and inherited parent faces can only retain semantic identity where operation-local history and parent ownership prove it. Untested transient edges and vertices remain transient. No semantic identity or publication is authorized by this document or a successful geometric test alone.

## Required controls

Use actual authored-prism → center cut → four-tool native output, plus at least a resized case, with independently calculated volume and positions. Fail closed on missing tool history, duplicated input indices/walls/rims/parent descendants, swapped tool bindings, malformed or forged ancestry, wrong hole center/radius/height, broken seam, nonclosed coedge chains, wrong loop winding, missing inner loops, incompatible mesh/bounds/volume, nonfinite or excessively large payload, and cross-owner/stale-parent binding at the later adapter. A fixture with only the first tool history is useful as a mandatory rejection control, never as proof of the other three roles. Save/reopen, dependency regeneration, cancellation and atomic publication require separate real-worker/craft tests.

## Initial ancestry-only control

`provenance.mjs` is a deliberately incomplete research check over the actual native fixture `fixtures/authored-native.json` (SHA-256 `99d2cc7a2433b944e0a8d1479736d62de0f0dc7c3d0eee7d75cb01291e6ffab5`). It rejects absent or ambiguous per-tool and support-face history and checks basic wall/rim incidence and input positions. Its three executable controls are `node --test research/four-corner-topology/provenance.test.mjs`. It does **not** validate the entire geometry, seam/loop orientation, mesh, volume, bounds, resource limits, hostile accessor objects, ownership or publication; it is not production-ready and must never be used as the sole gate. The actual fixture is the initial 100×50 case; a resized actual native fixture is still needed. Additional controls above remain outstanding.

## Bounded full-response candidate

`validate.mjs` checks the exact versioned native envelope, snapshots and limits data before reading, rebuilds both plans, validates the centered parent with the existing centered gate, and checks the five-hole geometry and same-operation ancestry. It tests circular frames and planar winding, seam/coedge pairing, wall/rim agreement, support face ancestry, inherited parent surface frames, analytic volume computed independently from the source polygon, closed mesh incidence, face-surface points, coarse mesh volume and bounds. It remains research-only and unregistered. The actual versioned 100×50 and 150×30 native fixtures are `normal-versioned.json` (SHA-256 `a7545e096ed767beb86366f74e7b730c05c9c63acf62c3d6cdbb2b088b95a51d`) and `resized-native.json` (SHA-256 `a224c68e33def74d131ab3a80e6d012b5df15d88a2e30e4975e5546e1186730e`). Run `node --test research/four-corner-topology/{validate,provenance}.test.mjs`.

The native outputs are standalone authored-prism research, not an authenticated live-worker capture. This validator cannot prove that response-local history came from the claimed operation, that the parent is current, or that projected IDs and model data stay unchanged through publication. Those require the separate same-mount owner and guarded adapter, followed by craft/history and save/reopen tests. Analytic geometry checks are intentionally limited to the documented horizontal rectangular case; they are not a general B-rep verifier. Mesh verification is bounded, coarse display consistency, not exact CAD geometry. No production registration has been made.

## Boundary validation correction

The shared `modules/engine/mount/boundedPrismBoundary.mjs` now verifies finite ordered UV bounds against actual boundary extrema, boundary vertex incidence on each analytic surface, outer line endpoints against authored prism corners and side adjacency, and paired line range ordering/length. Both centered and four-hole validators use it. Tests reproduce and reject moved outer vertices, reversed UV, reversed line ranges, altered UV extents and wrong line length on actual native fixtures. The native line records do not currently carry an analytic line origin or direction: a consistently translated parameter interval of identical length cannot be mapped to endpoints from this schema. Complete parameter-endpoint validation remains blocked on a versioned native schema carrying those values. The helper must be included in any worker package that imports the centered validator.

## Four-corner native line frames

The research four-corner result now requires `lineOrigin` and unit `lineDirection` on every line coedge. The validator evaluates the native range at both endpoints according to the coedge orientation, compares the paired uses' frames and ranges, and refuses old results missing the fields. Actual normal and resized native outputs (`normal-lines.json` SHA-256 `c815d9f493c3ab965744df3490df95c32525b21afc218660d919b85d04b32ee0`; `resized-lines.json` SHA-256 `97f2671c5a420f1911f8ce662500c4bf9cacc1cb27de772c7ac2e13b3b8930ed`) pass. An actual native three-cut result with a disjoint fourth tool (`partial-lines.json` SHA-256 `87764533848322fc8732824ae732cce3d4b8fd1ea915a94ce31d1f237377f940`) is refused; it is a valid ten-face solid, not a successful four-hole result. Earlier fixtures remain for provenance and negative controls. The centered parent still uses its old schema and therefore retains the separate absolute line-parameter limitation above. These standalone fixtures do not authenticate a live worker result or authorize publication.
