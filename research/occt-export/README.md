# Source-backed OCC tessellation research

This is an isolated prototype, not an installed engine or 3MF feature. Apply `occt-interpreter-5efaf53.patch` only to exact upstream source commit `5efaf53accb45bac475155fc4d5552642c19e91e` of https://github.com/Autodrop3d/occt-interpreter. It exposes `ExportTessellationCopy(int shapePtr, double deflection)` to trusted in-process callers. It deep-copies OCCT topology and geometry with no triangulation cache, meshes the copy, applies each face location and reverses triangle order on reversed faces. It emits finite 17-significant-digit JSON triangle soup; return code must be checked before reading the global callback, which otherwise retains stale output. Requested deflection must be between 0.0001 and 100 in model units. It has a post-meshing limit of 10,000 faces and 250,000 triangles; the mesher can allocate substantially before this limit is checked. The raw pointer must stay valid. No browser/UI/file API is exposed.

Do not assume this soup is welded, manifold, free of self-intersection, suitable for 3MF, or adequate for physical manufacturing. OCC's angular defaults, requested versus achieved error, holes/cavities, special orientations, singular surfaces, multiple shells, degenerate triangles, high precision, resource exhaustion, thread isolation, current-context lifecycle, security policy, and modified/disposed shapes remain unqualified. BRepBuilderAPI_Copy's geometry and topology-copy semantics support avoiding original TShape cache mutation; the current test only observes original JS IDs and pointer unchanged, and does not independently fingerprint original kernel caches. Full no-mutation verification still needed.

Reproduction used the previously built OCCT static libraries from this exact interpreter source with Emscripten 2.0.30 (`f782b50a7f8dded7cd0e2c7ee4fed41ab743f5c0`), Node 24.19 and CMake 3.28.3. `example-r730-build.sh` records the isolated test's exact paths and four-CPU affinity, 900-second timeout and 15 GiB free-disk guard; it reuses immutable static libraries rather than rebuilding the kernel. It is a receipt, not a portable build system. Existing OCCT component notices and source must accompany any distribution; no clearance is asserted. The resulting modified research artifacts were SHA-256 JS `f294fb3465e330679084dcc3e563ba25a6156822dd82eca850fb0aa188b3cb17`, WASM `3592c2745f180dfc6b8985d4d9e1f258ea1286d2b0cbdce7264f8dd68ff18cf9`; these differ from both published and earlier source builds and must never replace them without qualification.

`export-tessellation-browser.cjs` needs a separate locally served jSketcher runtime containing those modified artifacts plus Puppeteer and a loopback-only Chromium CDP. It is not a production CSP test. In that runtime, a 10×20×30 box yielded 12 triangles, bounds [0,0,0]–[10,20,30], signed volume 6000; a 90-degree rotated/translated box yielded bounds [-17,4,5]–[3,14,35] and volume 6000. A radius-10 sphere yielded 306 triangles at deflection 2 and 2,004 at 0.05; zero deflection was rejected. This proves a difference in tessellation density, not a rigorously measured maximum geometric error. Test user state and live sites were not touched.

## Narrow indexing experiment

`web/app/cad/export/occBoxSoup3mf.mjs` accepts only a single exact axis-aligned box (eight distinct corners, twelve triangles, two triangles per planar face with the proper diagonal). It coalesces numerically identical coordinates only. `minimumSeparation` is an explicit positive model-unit threshold for **rejecting**, never merging, unequal nearby vertices; it rejects shapes too thin to meet the threshold. The 3MF writer then independently checks edge orientation and vertex fans. Rejecting invalid geometry is deliberate: OCC triangle soup contains no source-topology identifier, so approximate welding could fuse distinct nearby walls or components. General seams, rotations not aligned with model axes, curves, cavities, distinct touching objects and numerical tolerance selection are not solved. Do not bypass these checks to export them.

The opt-in loopback-only `box-to-3mf-browser.probe.mjs` calls the copied-shape OCC entry in Chromium, moves its triangle soup to the Node-side narrow indexer and writer, then invokes `validate_occ_box.py` with the consortium lib3mf strict reader. The real OCC 10×20×30 box was accepted without warnings as a valid oriented 8-vertex/12-triangle object with correct bounds. Altering one seam vertex by 1e-8 with a 1e-7 threshold failed rather than welding. `tests/3mf/occ-box-soup.test.mjs` also tests thin-box and flipped-triangle rejection. This does not establish a browser-bundled writer, app integration, 3MF-wide mesh validity, or manufacturing readiness.
