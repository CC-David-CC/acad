# Root-owned complete execution, source prepared only

`example.mjs` is a reusable public recipe built on the retained real four-bore
recipe. `desktop-driver.mjs` authors both fixtures through registered public
commands. Private `__CAD_APP` reads are regression observations only. `check.py`
is the AFTER-WHOLE independent source/equation/material/projection/cap/interval/
SVG/.cad oracle. None was executed in this source lane.

Prerequisites: compose the Core product, Desktop compact drawing adapter and
source graph; repin/regenerate normal common Worker graphs; make one exact
signed fixture with full `static/shell/` pins (all new helpers) and the unchanged
Shell pair57b74074… /60dc956b…. MFG/circular are not section substitutes. The
public actual Shell available-build row must advertise drawingSectionVersion1
and drawingDetailVersion1. Existing other views/detail may use their separately
staged supported cohorts. All role/schema/PM/validation/export consumers must
be in the same normal build before new capabilities are advertised.

Root alone invokes one future whole application run, serially, for example:

```sh
CODI_DESKTOP_SOURCE_ROOT=/absolute/frozen-desktop \
PUPPETEER_CORE_PATH=/absolute/puppeteer-core \
CODI_TEST_URL=http://127.0.0.1:PORT/ CODI_TEST_CDP=http://127.0.0.1:19329 \
CODI_SIGNED_PINS=/absolute/exact-pins.json \
CODI_EXPECT_SOURCE=EXACT_CORE CODI_EXPECT_DESKTOP=EXACT_DESKTOP \
CODI_EVIDENCE=/absolute/NEW-evidence \
node test/section-detail-drawing-public-workflow/desktop-driver.mjs
```

Only after that entire attempt settles, retain its original receipt/log/source
snapshots, then run the artifact checker once:

```sh
python3 test/section-detail-drawing-public-workflow/check.py /absolute/NEW-evidence
```

First failures stay immutable. No unit/probe substitutes for the complete
workflow. No timeout, expected geometry or scope is changed after a failure.
The driver never force-closes a submitted Save/export/sync; a pending real write
keeps its owned context for settlement. It disconnects its shared CDP connection
and retires only its own normal contexts. It never restarts a fixture or changes
accounts outside its own normal signed test sessions.

The existing isometric/four-bore folders and evidence are untouched. New
six-role discovery is an explicit capability expansion; any separate retained
workflow with exact old view-capability-list assertions needs a root-owned
current-source compatibility copy, not edits to historical receipts.
