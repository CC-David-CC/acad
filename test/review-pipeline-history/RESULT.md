Reviewed `a47f57449` plus freeze follow-up `acaa01792`, without product edits. Existing focused tests and `ownership.test.mjs` pass in Node. Additional controls cover 10,000/10,001 history entries, 128/129 depth, detached deep-freezing, own `__proto__` as data, key-order-independent comparison and caller-owned input remaining mutable. The helper does not serialize or hash the full history. It cannot enumerate a single container's own keys incrementally: `Reflect.ownKeys` remains one synchronous allocation/pause, so this is not a fully worker-first bound or a measured million-node latency guarantee.

A concrete precondition matters for comparison: without a `check` that detects in-place changes, a field already visited can change during a later cooperative yield and `assertPipelineHistoryCurrent` can return successfully while the current original differs. `ownership.test.mjs` demonstrates both that outcome and rejection when the check observes the mutation. Log `/tmp/codi-pipeline-history-review-r1.log`; independent minimal repro `/tmp/codi-pipeline-mutation-probe.mjs`. This does not establish a production bug without evaluating the caller's actual ownership and mutation guards. Stream identity alone is insufficient for arbitrary in-place nested mutation.

A Proxy around an ordinary object also passes prototype/descriptor checks and its traps execute; JavaScript has no general reliable Proxy detector. The helper avoids invoking ordinary accessor properties, but cannot promise inert traversal of arbitrary hostile same-realm objects. The production boundary must establish trusted data provenance/ownership and authoritative currentness; this test is not a request to weaken data checks. No product source was changed.
