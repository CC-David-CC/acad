# Private Worker sketch projection research

Source base CAD `4ad6a174b`. The private Worker entry `prepareAcceptedSketchProjection` calls the existing `solveSketch` once. An optional internal callback captures actual solver constraints' stage/index, type, object references, constants and admission at the point their residuals are checked. Ordinary solver callers do not pass that callback and retain the existing result schema. The Worker compares those intrinsic records to the final strict native serialization, checks source/current geometry and frame, and returns an ordered witness tied to the captured revision and source. Generator records and geometry remain in the canonical native bytes; the witness includes per-stage generator counts. There is no live Viewer model, public validated flag, or skip-solve path.

`createAcceptedSketchProjectionOwner` is a private lifecycle prototype. It assumes its supplied replay transport is the pinned Worker client; it cannot itself establish a trusted Worker origin. It snapshots bounded source, frame and external parameters, checks a caller-owned source/frame/editor/document/account lifetime guard around the Worker and during cooperative response capture, rejects mismatched reply identities, and binds frozen bytes and witness to an owner-private ticket. Replacement and close abort the pending Worker through its signal; foreign, stale and retired tickets refuse. Its explicit cache state is `unprepared` and DOF remains null/unknown. Tests use both a synthetic transport for forged/missing/swapped witness and lifecycle faults and a real strict-CSP Worker for the solver/witness path. No production client transport, editor installation or publication is wired.

The source's saved staged objects, labels, dimensions, generators, branch metadata and IDs remain authoritative in exact serialized bytes. An actual installation still needs detached real model construction, complete witness-to-live-object identity mapping, guard checks immediately before one atomic publication, one owner/ID-generator policy, notifications/rollback, and a mechanism for all live consumers to refuse or route operations while cache is unprepared. ConstraintExplorer and several actions read conflicting/redundant sets; drawing uses fullyConstrained; drag/prepare/solve, mutation/removal, generators and directional relations depend on live solver state and projectedLastValid. Worker evidence is not a transferable polynomial graph, isolation graph, projected state, or proof of DOF. Do not mark the constructor's default success as validated.

`construction-observation.cjs` measures an isolated actual Viewer on the earlier pinned 2bb app and real Worker; it is not an exact current build. Receipt `construction-receipt.json` records one instrumented run with 514 segments, 512 LockPoint constraints and one SegmentLength annotation: Worker 1158 ms, strict load 703 ms, Segment.read 4.5 ms, Constraint.read 1.1 ms, annotation layer add <0.1 ms, admission 425 ms (prepare 418 ms nested), three notifications 233.5 ms inclusive and one repaint 5.5 ms. These overlap, are not additive or representative of all annotation types, and omit other construction/index/stabilization work. The later current closed-agent path has separate root measurements; this observation does not qualify current app performance.

A separate Worker-only dense control (`dense-worker-browser.cjs`, `dense-worker-receipt.json`) used the same actual 8719 Worker and fixture, the saved rectangle plus 512 independent authored LockPoint/Segment pairs: 141,281 UTF-8 source bytes and 523 intrinsic witness rows. One fresh-context run took 1165 ms Worker roundtrip; the 5 ms main-thread interval fired 223 times with a maximum observed gap of 46.3 ms. This is an instrumented single run in a shared Chromium process, covers Worker replay/transfer only, and does not measure client witness copying, editor hydration, or accepted-history publication.
