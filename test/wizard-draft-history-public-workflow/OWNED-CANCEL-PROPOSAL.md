## Proposed narrow signatures and authoritative association

These are proposed source interfaces, NOT implemented methods or registered commands:

- `captureHistoryReviewCancel(ctx, request): HistoryReviewCancelCapture | null` in wizardBundle. The opaque object is registered only in that module's private WeakMap; it captures the actual origin, owner service and lifetime/requestKey. No public constructor or caller-supplied request/body is trusted.
- `readHistoryReviewCancel(capture, ctx): Readonly<...>` authenticates that private capture, the current actual request's descendant-origin membership and current document/stream state. It returns only the actual references needed by Craft; it never infers ownership by field equality alone. It is an internal named export, not a host API.
- `craft.cancelHistoryReviewDraft(capture): void` captures/rechecks the existing authoritative history/J/head/source/material identities, checks the predicate above, then invokes `discardHistoryReviewDraft(capture, ctx)` on that same captured wizard. No async queue or fallback pointer update. The discard function uses the actual wizard stream reset and refuses if its private origin is no longer current.

Use current Craft's existing `authoredJournal$`, `journalHeadDefinition`, `journalHeadSignature`, `fullTipSignature`, `fullTipSketchRevision`, `fullTipMaterialSurfaceRevision`, epoch/pending/failure state and existing document/source/material capture routines. The history control's accepted publication already owns those associations; do not create a second remembered signature, boolean or journal. `captureManufacturingEditContext()` itself is full-tip-only and must NOT be called at the prefix or weakened for this purpose. The narrow predicate reads the same owner-scoped authoritative state directly. The journal association is the *applied* entry at `cursor-1`, not the latest array entry (Redo tails may exist). Matching only pointer, type or params is insufficient.
