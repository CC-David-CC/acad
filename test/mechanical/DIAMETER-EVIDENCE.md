# Driving diameter research

The `DiameterLength` sketch relation stores the authored diameter and contributes the polynomial `2r - D = 0`. It accepts one circle or arc, requires a positive bounded resolved value, displays a diameter annotation, and shares `addDiameter` between the selected-object UI action and revision-checked ID action. Named constants remain authored as names. A conflicting addition rolls back constraint membership, geometry and the pre-attempt undo metadata; a redundant relation remains explicitly classified and can become active when the original is removed. The ID action verifies the serialized revision, actual object identities and caller validity immediately before mutation. It is not itself a desktop command registration.

Seven R730 bundled mechanical/headless tests passed: selection, circle and arc solving, conflict rollback, redundant removal, positive domain, named values, stale/replaced/cancelled command checks and native sketch intent replay. The isolated real Chromium `test/webos/diameter-browser.test.cjs` passed using the actual sketcher action and editor: negative UI input was refused without changing radius, Ø12 displayed and drove radius 6, the revision-bound action applied Ø14 to an arc, a conflicting addition left sketch bytes unchanged, undo/redo and removal worked, and native sketch IO plus a fresh project snapshot restore retained the two diameter constraints. UI selection/geometry creation used the existing test helper; it is not a physical-pointer-only, signed desktop, external-agent bridge, or manufacturing qualification.
