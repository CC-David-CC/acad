# Shared sketch transaction recovery

`runSketchTransaction(viewer,{mutate,validate,rollbackExtra})` reuses the existing strict history checkpoint, bounds its UTF-8 size to 1 MiB, starts one synchronous parametric transaction, and invokes the caller's validation before finishing. LengthRelation, signed/projected distance and the bounded segment measurement role conversion use the same helper. The caller keeps its existing pre-submit lifetime/revision checks and post-success refresh. A numerical or domain failure is rethrown as a failure; this helper does not classify it as proven inconsistency.

On failure the helper attempts transaction rollback and optional caller-owned layer cleanup, restores the prior history metadata and checks the serialized sketch plus PM/stage transaction flags. If rollback or cleanup is incomplete or cannot be verified, it retains the pre-edit checkpoint in `history.recoverySnapshot` and reports that recovery is required. This reuses the existing explicit recovery path and prevents a partial sketch from being treated as safely saveable. Strict checkpoint creation still serializes on the UI thread; the size cap is checked after serialization, so it is not a proof of responsive behavior for arbitrarily large sketches. It does not establish crash/power-loss durability.

Five Node controls pass for commit, normal rollback, changed data, unfinished stage, failed extra cleanup and UTF-8 byte size. The 29 signed-distance/revision controls and 13 affine-length real-solver controls pass. `test/webos/sketch-transaction-recovery-browser.test.cjs` passes in the actual combined app for both LengthRelation and SignedDistance: injected stage rollback failure holds the previous sketch, `history.recover()` restores it, and a subsequent valid edit succeeds. `test/webos/length-measurement-roles-browser.test.cjs` passes the actual fast-pointer measurement/native project reopen, UI+ID conversion, undo/redo and injected attachment/double-rollback/stage-rollback recovery controls with the shared helper. These are deliberate fault injections, not claims of a real kernel crash.
