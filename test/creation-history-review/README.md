## Existing machinery to reuse

`craftBundle.ts:944–1058,1097–1258` already owns immutable pipeline definitions, fresh full-prefix evaluation, epoch/document currentness, per-candidate registry and sketch overrides, prepared workspace/model/history/journal publication, accepted-state preservation on command failure, and resource retirement. Publication preflights all participants, then commits without an asynchronous/observer gap. A requested history without command callbacks may instead publish explicit stale failure status; the new public travel path needs command callbacks and a prepared transaction, not a raw stream write.

`evaluationResources.mjs:7–14,61–77,123–133` bounds at most three owners and three total mounts, and detaches native mounts after accepted publication. A journal must retain no resource owner, native handle, mesh or evaluated model. Undo/Redo reconstructs from authored intent; it cannot reuse an old detached native shape. Reject/cancel closes only its candidate and preserves accepted history/bytes/model/journal. Cleanup failure remains blocking.

`storage/storageBundle.ts:149–187,229` and `volatileWorkspace.mjs:70–149` **already** support atomic `prepareWrites([{key,value:null}])` deletion as well as string writes, with key/version/lifetime guards and notification after commit. No new storage format is needed for undoing a source-plane creation. Prepared maps copy references, not immutable string contents.

The current edit journal has 64 entries / 8 MiB aggregate retention and a one-MiB sketch-source limit. Full replay uses owned immutable records through `capturePipelineHistory.mjs` (10,000 entries and cooperative traversal), while `captureAuthoredHistory.mjs` is a smaller 256-entry/256-KiB edit capture. Do not impose that narrow serialized capture on every native project or introduce full history/model snapshots to implement creation travel.
