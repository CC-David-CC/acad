Read-only ledger assessment
---------------------------

No additional blocking flaw was found in this bounded review:

- `solidLedger.mjs` captures profile sourceBinding as exactly three own data
  fields, matches the origin feature/region, and stores the live face plus
  real result handle in the candidate owner's private sources map. Consuming
  the source's visible output removes the output entry, while retaining its
  source handle for replay within that owner.
- Hole admission requires the current exact target model/producer and a
  matching retained source feature, face, region and runtime. The current
  target's v2 sourceContexts must carry that origin. The operation separately
  requires an owned independent plane with current face/root relationships.
- Dispatch sends the captured authored intent and private target/source
  handles. The origin selected-profile handle is not substituted with the
  current drilled target. Shared native code remains responsible for actual
  ancestry, through-all tool derivation and removed-material evidence.
- Result contexts must equal the input contexts; derived tool profiles do not
  become authored sketch contexts. Unavailable naming remains an explicit
  observation and prevents a later dependent hole from claiming a source.
- Only a measured valid single-solid result can become the candidate model.
  Publication rechecks output/parent/source handles, source face identity,
  placement, display ownership and lifetime. Failures after native dispatch
  close the candidate owner; pre-dispatch relationship refusals allow healthy
  retry without consuming the candidate input.

The local through-hole guard captures storage revision, services, generation,
history, expression script/list/error stream revisions and plane identities.
It does not independently reconstruct sketch data or capture the physical
parameter table/stream-object identities. In the real supported pipeline the
earlier `workerSelectedProfile.operation.ts` registers a stronger source,
frame, storage-namespace, table and stream guard on the SAME resource owner.
`owner.requireCurrent()` executes all prior publication guards before later
operations and sealing. This is part of the integration contract, not a
freshly established guarantee from the reduced model fixture. The ledger is
private evaluated-state custody, not a replacement for that source operation.

`craftBundle.ts:runRequest` passes original `request.params` as the third run
argument even though materialization can add absent optional values to its
separate params object. The new adapter captures that original raw argument,
so centered intent stays exactly 12 fields. Schema/materialization, source
reconstruction, ledger custody and native verification retain their distinct
responsibilities; no second authored model is introduced.
