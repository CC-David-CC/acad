# Proposed current-solid native point observation

Read-only design against CAD db34c89f1. No product/native/browser change or qualification. Native component observations alone do not qualify this public replay boundary.

One new public command `classify-worker-solid-points` / Craft `classifyWorkerSolidPoints(input, options)` can use existing inspect-worker-solids metadata. Exact input:

```
{revision,version:1,unit:'millimeter',engine:'occ',engineRevision,
 bodyId,featureId,points:[[x,y,z],...]}
```

Initial bounds:1..64 dense finite world-space points, exactly3 own numbers per point, coordinates within the existing native observation domain ±4e6mm; revision≤256/bodyId≤1024, safe positive producer featureId and exact lowerhex136 build pin. No caller handle, source bytes, history prefix, mount, replay callback or allocator ID. No mesh ray test/display-unit conversion. Unknown remains unknown. Initially support current nonempty valid single-solid outputs of the explicit sweep build (other V3 OCC builds only after separate approval); empty/consumed/legacy/placed/other-engine targets refuse explicitly. The fresh actual mount descriptor must bind solid.point.classify/version1.

Data-only result: `{version:1,unit:'millimeter',revision,bodyId,featureId,engine,engineRevision,quality:'native-re-evaluation-observation',points:[{point,classification}]}`. No shape/handle/index/Worker or publication marker escapes. This reports the pinned kernel's observation, not a continuous distance or mathematical boundary certificate.

## Existing real seams and necessary changes

- `web/app/cad/craft/craftBundle.ts: evaluatePipeline` is the genuine full-prefix replay. It already captures immutable history, reconstructs source planes/registry, runs actual registered operations and source/semantic Workers, and owns temporary native resources. `runPipeline` and submitPreparedReplay are unsuitable: their normal callers advance epochs and publish. Add a private read-only replay wrapper, not a second feature executor.
- Same file: `pipelineTail`, pendingPipelines, isCurrent/requireCurrent and engineResources provide the exclusive lease. A query may have a transient busy lease, but must not increment evaluationEpoch, allocate a project feature ID, change accepted modifications/models/registry/journal, assign acceptedResources/lastCompleteResources, or call cancelCandidates on entry. Recheck captured revision after queue acquisition. Queries and writers must not concurrently use global model-ID contexts.
- `MObjectIdGenerator` in `web/app/cad/model/mobject.ts` is currently reset by evaluatePipeline. Existing pushContext('') / finally popContext can isolate it under that exclusive lease; preserve the exact old context/map/project counters. This pattern is already used by partImport/remotePartsBundle, but needs public-query fault tests. An unscoped reset is not read-only.
- `capturePipelineHistory` / assertPipelineHistoryCurrent provide cooperative capture/currentness without a main-thread canonical hash. Initial query scope:≤256 supported entries, only the real standard PLANE descriptor plus registered AUTHORED_SOLID_KINDS, one exact backend,≤32 cumulative native results and current100000-triangle work policy. Capture/recheck actual descriptor/run/admit identity: membership alone is not validity. Refuse unsupported legacy/assembly/repair/typed paths before native allocation.
- Reuse createCandidateSketchStorage, ReadSketch and cadRegistry.createEvaluationRegistry with COMPLETE captured native sketch bytes/frames and a frozen read-only base reader. Existing candidate storage returns live source for empty overrides, and missing overridden IDs fall back to live source; it is not automatically a frozen source view. Capture all required source IDs and forbid fallback. Existing sketchSourceFrames verifies reconstructed source planes. Retain operation64KiB native-source limits. Bind source membership/version/bytes/frame, history/pointer, expressions, project/document signal, service/stream identities, requested accepted output/placement/build through cleanup and delivery.
- `modules/engine/solid/solidLedger.mjs` privately holds candidate output→mount/handle mappings. Add `classifyCandidateWorkerSolidPoints` taking owner/private candidate registry/bound model and IDs/build/points/currentness. Use ledgers.get(owner), require candidate state/exact output/model/registry/build identity and actual descriptor capability; never create a missing ledger or borrow retired accepted handles. Return only classifications. Expose no generic handle map/callback API.
- evaluatePipeline seals its owner but leaves it in candidate phase. The ledger may use its existing mount (not getOrCreateMount) before finally close. Return candidate registry privately from evaluatePipeline for this lookup. Classify only the requested CURRENT output, never consumed ancestors retained incidentally in native memory. Require reconstructed producer/build/result kind and measured native facts agree with captured accepted output, otherwise REPLAY_RESULT_MISMATCH. Scalar agreement is an integrity check, not geometric equivalence proof; exact definition/source binding remains essential.
- `worker-controller.mjs: classifySolidPoint`, SolidKernel.ts ClassifySolidPoint/PointClassificationResult and oci-verified-worker.js already perform the genuine strict token-bound ClassifyOwnedPointV2 call. Use64 sequential reads; no new C++/Worker clone/geometry math. The current native classifier tolerance is1e-7mm; unknown remains unknown. Point reads reserve0 native result names and add no repeated triangle charge.
- evaluationResources.mjs already supports begin/seal/close, signal fencing and cleanup latch. Query owner is never accepted/detached. Close in finally; require cleanup established BEFORE returning success. close may latch cleanupFailed without throwing, so inspect/report that existing fence and preserve operationError plus cleanup cause. No successful classification receipt after uncertain termination. Exceptional cleanup-status fencing may legitimately change the existing failure stream; ordinary successful queries must leave accepted state unchanged.

Important limit: existing replay instantiates source/model/preview objects and hydrates ReadSketch on the main thread. This proposal adds no classifier, solver, geometric algorithm or hash there; native geometry, solves/digests and point observations remain in existing Workers. If even existing main-thread model hydration is forbidden, evaluatePipeline is not sufficient as-is: a shared Worker replay/projection seam is a larger prerequisite. Do not conceal it with a fake registry/model or call the current evaluator fully Worker-only.

## Acceptance needed

1. Genuine shared replay/native observations for straight disk/annulus/polygon, quarter disk/annulus/asymmetric rectangle, reversed/major Arc. Independent cap/side/bore/material/exterior/roll-sensitive expectations, no tessellation/engine-agreement oracle.
2. Signed public two-plane authoring→query exact current body using inspected revision/body/producer/build. Accepted history/source bytes/models/registry identities/journal/counters/material/presentation/document token unchanged; no Save/write. Source/path edits change subsequent observations correctly.
3. Wrong revision/body/producer/build, consumed/empty/unsupported/placed target, malformed/nonfinite/out-of-domain data and typed/legacy unsupported states refuse. Unknown remains unknown.
4. Full32-result part remains observable: require withinLimit, not canAppend or remaining≥1. Replay existing32 results; point reads cost0 names. Preserve cumulative triangle charging once per replayed output.
5. Genuine held reply through supersession/New/Open/account/Close/abort/timeout; no stale observations escape. Queue rechecks after lease; no collision with writers/global ID context. Cancellation before allocation creates no Worker.
6. Success/failure cleanup restores exact old ID context/project counters and settled resource usage. Repeated cycles bounded; accepted owners remain detached/unmodified. Inject termination/cleanup failure and reject success with the existing fence.
7. Measure replay/init/query time, transferred/display work and WASM heap CAPACITY separately. Current replay still creates temporary display projections; do not infer used-memory/RSS/reclamation. Optimize that shared seam later only if measured, not by bypassing native validation.
