# Enclosure worker operation

solid.enclosure.create version 1 accepts a strict millimeter plan with width, length, height, wall, clearance, lidThickness and lipDepth. It requires a fresh pinned OCC candidate mount. The +Z open body and separate full-size cover with inset locating lip are returned together as BODY and LID mount-owned handles. The lip overlaps the cover internally by 1% of the smallest wall/lid/lip dimension. Neither role nor handle is a durable document ID. A pinned Manifold mount supports the same operation through its own mesh kernel, without conversion or fallback.

A dedicated worker internally replans, builds six uniquely named box/Boolean shapes, checks both mesh bounds/volume and native BRepCheck, exactly one solid and native volume before exposing either token. Any native failure shuts down the candidate worker; an abort terminates its candidate mount. Validation failure before native allocation is rejected without touching it. An already accepted document must own a separate mount; document/history integration remains outside this package. There is no editable topology, stable face naming, authoring/undo/reopen, 3MF or manufacturing integration yet.

Run node --test test/enclosure-worker/{plan,capability}.test.mjs. For browser proof, run prepare-fixture.cjs with empty output directory, pinned OCC wrapper and 13617 WASM; serve with modules/engine/mount/strict-csp-server.py using CODI_ENGINE_TEST_ROOT, CODI_ENGINE_TEST_PORT=19972, then run browser.test.cjs with test Chrome CDP 20055 and Puppeteer on NODE_PATH. The fixture injects a command failure and disjoint-cutter no-op into two separate fault-only workers; neither is in the actual worker. Browser evidence: both sizes passed, failures/abort returned no handles and candidate mounts closed, while an independent accepted mount remained usable. Browser automation is not a full native-model or physical-print qualification.

Mesh read: readEnclosureMesh with op solid.enclosure.mesh, version 1 and a live body/lid handle returns its role, millimeter unit, bounded oriented Float64 triangle coordinates in an ArrayBuffer and quality kernel-display-preview-unqualified. Native faces are interrogated once per role and transferred from the Worker; the mount validates count, exact byte length, finite nondegenerate vertices, bounds and signed volume, caches privately and returns detached copies. Dispose/close clears the association. This is a preview mesh, not a tolerance-qualified manufacturing/export mesh, durable face identity, or editable topology. The pinned native Interogate implementation allocates native interrogation data without freeing it; one read per role per bounded Worker limits this overhead and full Worker termination is the disposal boundary.

Run node --test test/enclosure-worker/mesh.test.mjs; mesh-browser.test.cjs uses the same strict-CSP fixture recipe. Its fault-only workers inject a nonfinite transferred value and delayed read: both close the affected candidate, while a separate mount remains usable. It also covers live body/lid, bounds/volume/winding validation, cross-mount and disposed handles, cancellation, returned-buffer mutation and closed mount refusal.


Manifold uses a pinned source-built Manifold JS/WASM pair. The new builder embeds the verified JS glue statically into the Worker and rewrites its three import.meta.url references to the current Worker URL; WASM bytes are still fetched same-origin and hashed before initialization. Strict self + wasm-unsafe-eval CSP needs no blob permission. The wrapper must be published with matching plan/mesh modules. Source and notices remain the existing Manifold/Clipper2 package inputs; no new upstream code is introduced.

Manifold preview vertices originate as Float32 and are returned losslessly converted to Float64. The quality is manifold-float32-preview-unqualified; this is not manufacturing tolerance. Each non-clearance dimension must be 0.1..10000 mm; clearance must be 0.01..1000 mm; wall, lid thickness, lip depth and clearance must each be at least eight times max(1e-6, max(width,length,height+lidThickness)*2^-21) mm. Smaller features refuse with UNSUPPORTED_PRECISION. Manifold result volume accepts max(1e-6 mm^3, 1e-6 relative); bounds accept max(1e-6 mm, largest absolute bound times 2^-21). OCC tolerances are unchanged. The returned nativeVolume field is the Manifold engine mesh volume, not OCC analytic BRep volume.

assertEnclosureBinding(bodyHandle,lidHandle) synchronously checks that both live handles belong to the same private result and have BODY/LID roles; it does not expose native tokens and is available on both engines. It refuses stale, reversed, foreign, pending, or closed binding.

The strict-CSP Manifold browser control uses prepare-fixture.cjs with optional fourth and fifth inputs for the pinned Manifold JS/WASM after its three OCC fixture arguments. manifold-browser.test.cjs tests valid dimensions and edits, precision refusal, pair identity, no-op, malformed mesh, cancellation and bad WASM; pair-browser.test.cjs also checks actual OCC pair binding.
