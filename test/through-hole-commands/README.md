# Public through-hole command facade

This source-level qualification tests the real TypeScript command facade and real registered engine/cost/authored-intent helpers. Explicit service/model/selection/publication doubles isolate routing and custody. They do not solve sketches, evaluate geometry, execute native Workers, or qualify the browser app, signed host, undo/redo geometry, or file workflows.

`workerThroughHoleCommands.ts` exports four shared-Craft methods: inspect/create/history/edit. Creation accepts exactly revision, version, unit, engine, engineRevision, bodyId, sourceFeatureId, kind and diameter, plus offsetX/offsetY only for four-corner-through. The facade infers the producer from the current owned body; source face/region come from the unique captured selected-profile history entry and matching immutable version2 source context. The original source solid may already be consumed. Its retained current source plane, exact saved sketch text (at most65536 UTF-16 code units), frame, namespace/key versions and captured authored source intent remain bound through candidate publication.

Discovery advertises separate rows for each eligible body/source origin, with per-kind `creation` availability and full native result cost. `canCreate` means a currently admissible request and budget, **not** a qualified rectangular profile or feasible hole placement. Both global and target metadata explicitly say `sourceProfile:'selected-rectangle'`, `sourceQualification:'requires-worker-validation'`. The real Worker still decides rectangle eligibility, placement, through-all geometry, valid output and last-valid failure. No source shape is parsed on the main thread. Project typed/global expression bindings are unsupported here.

The registered build must support throughHoleVersion1 and selectionPlanVersion2. History and all current generic outputs must keep the same registered runtime. Centered holes reserve2 cumulative native results; four-corner holes reserve8. The tests include24/25/30/31/32 existing-result boundaries and prior hole costs. Read-only source discovery remains available when creation capacity is full. The facade allocates the new feature ID only after complete request/cost preflight; both producer and source IDs are excluded. No public native handle, index, new feature ID, source face override, copied tool, tool coordinate or termination depth is accepted or saved.

Numeric editing forwards only revision/index/featureId/diameter, adding both offsets for a corner feature, to the existing `authoredThroughHoleOperation` owned replay/journal. This file implements no alternate history or undo/redo.
