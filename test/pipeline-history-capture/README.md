# Pipeline history capture prototype

`capturePipelineHistory(history, check)` returns a deeply frozen, detached, data-only history; caller-owned input is never frozen; `assertPipelineHistoryCurrent(history, snapshot, check)` compares the current original with that snapshot without serializing either. Objects retain their key enumeration order; equality does not depend on object key order. Arrays must be dense, plain and free of extra own properties. Accessors are never invoked. Non-finite numbers, symbols, cycles, non-plain objects, depth over 128, over 1,000,000 visited nodes and over 10,000 history entries refuse. Currentness is checked before and after each scheduled yield and at both endpoints. Text is bounded to 256 MiB of UTF-16 storage: twice the 128 MiB UTF-8 native file ceiling, preserving the possibility of all valid text from such a file. Node/object overhead is separate and depends on the JS engine. There is no whole-history canonical string or hash.

One important limitation: JavaScript exposes no incremental API for enumerating all own property keys, including non-enumerable or symbol keys. `Reflect.ownKeys` for each single container is synchronous and allocates its complete key inventory. Per-key traversal yields, but a very large single container can still create a main-thread pause and transient allocation. The helper does not claim this operation is fully worker-first; a future worker-owned validated input protocol or explicitly qualified container limits are needed to eliminate that exposure. Large strings remain immutable JS strings and are not copied into a new encoded buffer.

Focused checks: `/tmp/codi-files-move-node/bin/node --test test/pipeline-history-capture/capture.test.mjs`. Real Chromium loopback test (isolated context, strict self-only CSP): `NODE_PATH=/tmp/codi-occt-release-control/node_modules /tmp/codi-files-move-node/bin/node test/pipeline-history-capture/browser.cjs`. On 2026-11-05 the 512-entry, 524,288-character fixture completed capture plus comparison in 309 ms with 82 interval callbacks. This establishes cooperative opportunities for this fixture, not a maximum-pause or general 1-million-node guarantee. That original helper benchmark predates integration. Runtime5f8 now uses the helper in the common evaluator; see test/closed-sketch-publication-review/PIPELINE-OWNERSHIP.md and the independent ownership review for caller-provenance and cooperative-comparison limits.

Legacy operations that try to mutate the published raw request must fail and be corrected through an explicit normalized mutable candidate; they must not silently change accepted authored intent. The separate edit-command capture remains mutable for staged edits.
