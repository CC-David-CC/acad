# Four-corner owner/projection research

The browser test is a strict-CSP actual-worker integration: authored sketch → retained prism → centered-hole candidate association → four-corner worker → projected 11-face model. It covers the 100×50×20 and 150×30×35 cases, forged centered-feature refusal and mutation guard. The worker fixture was copied from `/mnt/data10tb/codi-four-corner-actual-worker-fixture`, whose embedded worker is SHA-256 `4588588f2ab5fb7bc1dfe254b020bb113d34a0906534e9657f1c6312214cb758` and incremental WASM is `0e08888f09c34f79b858cefc2859cbb59fbea1af6505b04686343eac7f9efc5b`. This is a research runtime, not the newly built clean-library runtime. Test-only `test-oci-mount.mjs` selects that runtime and must not be released.

Build using `node node_modules/webpack/bin/webpack.js --config test/engine-four-corner-adapter/webpack.config.cjs`; copy its `entry.js` and `semantic-worker.js` into a disposable copy of the public worker fixture's `static/` directory as `adapter-entry.js` and `semantic-worker.js`, and serve it with `test/engine-hole/serve-worker-fixture.py`. Run `browser.test.cjs` with `CODI_TEST_URL`, `CODI_TEST_CDP` and `PUPPETEER_CORE_PATH` pointed at isolated loopback services. The fixture HTML includes `/lib/verb.js`.

The operation factory is intentionally unregistered. It requires a source-validated producer for four persistent side IDs; its form currently has no such producer. Actual craft history, UI execution, cancellation during history evaluation, failed edits, undo/redo and native save/reopen remain untested. Prior center rim edge IDs deliberately become transient because the four-cut native history does not prove their individual edge ancestry. The runtime test does not establish compatibility with a clean production package.
