# Local Jacobian estimate — research only

The opt-in no-task sketch Worker request adds `localJacobian: {version:1}`. Existing requests have unchanged results and admission behavior. Only after the existing solve succeeds, finite residual/domain checks pass, and strict serialization preserves authored intent does the Worker collect fresh, original (unsubstituted) polynomials for all nonrejected constraints, including internal geometric equations. A failed solve returns its existing error and no rank diagnostic. This is a read-only report: it does not reclassify constraints, alter geometry, retain pointers, modify saved history, or decide inconsistency.

The Worker collects parameters from stage-owned geometry and constraint-owned auxiliary parameters. Parameters of external-stage objects are treated as fixed; a parameter shared ambiguously between local and external objects makes the report unavailable. A parameter with inequality/penalty constraints makes the report unavailable because equalities alone cannot describe that domain. Gradients come from the existing polynomial/monomial derivatives evaluated at current object values, with no `SolverParam` mutation. The maximum is 128 unique variables, 128 equations and 4096 parameter visits; excess, nonfinite, unsupported or failed-solve cases report `status:'unavailable'` without invalidating an otherwise successful solve.

For numerical estimation, each row is normalized, nonzero columns are equilibrated by their maximum absolute coefficient, then rows are normalized again. Pivoted modified Gram–Schmidt uses two projection passes. Normalized pivot thresholds are `1e-8` and `1e-12`; the reported `rankLower` and `rankUpper` are estimates using those thresholds, **not mathematically certified bounds**. A threshold disagreement returns `status:'ambiguous'`, null exact `rank` and null exact `localNullity`; nullity estimates form the complementary interval. An exactly zero gradient row returns `status:'zero-gradient'`, which can mean a singular equation or a tautology and proves neither. Otherwise `status:'estimated'` is only a local differential estimate at the current solution, in the scaled solver-variable parameterization. Solver variables include internal geometric and auxiliary variables: `localNullity` is not yet a user-facing physical DOF count. Any rank can change away from this point; conditioning, coordinate scale and threshold choices may change the estimate.

`dependentRows` are rows not selected by one pivoted numerical basis; this list is nonunique and must not be presented as the set of logically redundant or guilty authored constraints. `rowOrigins` maps every row to `constraintIndex`, `authoredIndex` (null for internal equations), type, internal flag and `constraintId`. The constraint ID is the existing debug counter and is **response-local only**; authored index is meaningful only against the exact captured sketch snapshot. Existing authored `accepted`/`redundant` statuses remain separate. UI or agent clients must authenticate revision/lifetime and explain these limits; there is no UI/agent integration in this checkpoint.

## Ordered-prefix follow-up and active capture

The research follow-up adds `orderedContribution`: a baseline of internal equations followed by authored constraint groups in captured order. It equilibrates the full matrix once and reuses those exact scaled rows for both threshold factorizations of every prefix. Each group reports its prefix rank interval and, only when all preceding prefixes are stable and no zero/near-zero gradient was seen, a numerical rank increment. Unknown results carry no increment. The real Horizontal plus SignedDistanceY=0 case gives local increments 1 and 0, respectively, without changing either accepted admission status. This is still a pointwise linear estimate, not logical redundancy or a proof of a regular solution; especially, normalizing a near-flat nonlinear equation can make an approximate singular point look independent. The `1e-12` raw-gradient warning is a conservative scale-dependent alarm, not a universal singularity test.

Independent review identified two faults in the first checkpoint: normalizing extreme finite coefficients can underflow a nonzero entry, and polynomial term/derivative work was not included in the earlier 4096 visit limit. The follow-up refuses detected scaling underflow, includes polynomial parameter visits in that limit, and caps derivative work at 262144 estimated term operations before evaluating derivatives. This does not certify against all floating-point underflow inside a nonlinear derivative. Regression tests exercise the exact matrix `[[1e308,5e-324],[1e308,0]]`, pre-evaluation work refusal and near-zero gradient uncertainty.

A private active-editor capture helper now checks strict bounded current sketch serialization, viewer/IO/solver/history/tool identity, realm-local mutation epoch, no active tool, no solver transaction and no pending history recovery. It is not a complete current-document API: the coordinator must bind face, source, boundary, document/account/window, expressions and full history, compare the Worker solution against current geometry, and verify exact bytes again before returning. Strict capture still serializes up to 1 MiB on the UI thread. Saved mode, typed-v2 dispatch, public UI/agent and integration are not implemented. See `ORDERED-INSPECTION-PROPOSAL.md`.
