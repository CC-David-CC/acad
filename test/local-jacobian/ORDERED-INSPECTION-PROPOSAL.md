# Ordered local rank and current-sketch inspection proposal

This is a proposal for review, not an implemented public API or admission policy. Preserve existing accepted/rejected/redundant admission statuses, geometry and native history. Numerical dependence at one solution is not a global redundancy proof; an unsuccessful solve is not proof of inconsistency.

For a successful, residual-checked candidate, collect the bounded original equations, stage-local and constraint-owned auxiliary variables, with external references fixed. The internal equations form the baseline; visit authored constraint groups in exact serialized order, keeping every polynomial of one constraint together. Equilibrate once using the **whole captured matrix**, then use the same scaling for every prefix. Independent low/high-threshold, twice-reorthogonalized incremental factorizations report an estimated baseline rank interval and per-group incremental intervals. If preceding uncertainty makes a contribution indeterminate, a group has zero/near-zero-gradient equations, scaling underflows, or arithmetic violates prefix monotonicity, the contribution is unknown. A zero increase means only no additional *local linear* rank at this approximate point; never label a group logically redundant. Row normalization can promote a near-flat nonlinear row at an approximate singular solution, so threshold agreement alone never certifies regularity or semantic independence. Constraint identity binds to captured authored index, type and exact referenced IDs; the existing debug ID is response-local. Pivot rows are nonunique and are not assigned blame.

A later `inspectSketchDiagnostics({revision,mode,faceId?},{signal,valid})` may use the existing pinned same-origin disposable Worker. For `mode:'saved'`, select a current saved face/sketch from captured authored history and exact storage key bytes/version. For `mode:'active'`, require the current actual in-place editor, default/idle tool, no solver transaction or history recovery, and strict bounded serialization of the current unsaved sketch; do not force save or close. The private `captureActiveSketchForDiagnostics` prototype brackets serialization with the sketch mutation epoch and records viewer/history/tool identity; inexpensive `quickValid` checks can be polled, followed by an exact strict reserialization before return. The serialization is bounded to 1 MiB but still runs on the UI thread, an existing separation/performance limitation. A coordinator must separately capture the editor context/face, active streams and history, document/account/window lifetime and source/parameter dependencies; that coordinator is not implemented here.

Both modes must capture exact sketch and boundary/frame, full-tip history, expression source and stream revisions, storage namespace/key where relevant, and service identities. Typed sketches must use `evaluatePhysicalSource` with the selected v2 configuration and the same typed-dependent preparation as actual replay, preserving supported named field dimensions; never flatten a live generic scalar table. No caller may inject raw Worker results, arbitrary tables or history.

After every await and immediately before returning, recheck those guards and exact source/history binding. Compare returned authored intent, identity and boundary with the captured source. Compare all admitted solved coordinates and solver-relevant geometry against the captured **current** sketch within an explicit, independently reviewed tolerance. If the Worker moved geometry beyond that tolerance, source or boundary changed, active tool/transaction is unstable, or freshness is not established, refuse explicitly; do not silently present a candidate estimate as current. Never write sketch storage, mutate the model, force an editor save, or consume journal state.

UI and agent clients must receive local-estimate wording, limits, internal baseline, authored group order, rank interval and uncertain cases, alongside unchanged admission state. Distinguish failed solve, zero/near-zero gradient and threshold uncertainty from contradiction or proven redundancy. `n-rank(J)` includes internal and auxiliary solver variables and is not automatically physical sketch DOF. The 128 variable/equation and bounded work limits remain research-only, not general geometry/performance guarantees. Full scoped host operations, actual UI/agent integration, typed v2 Worker dispatch, same-geometry verification and real active-editor tests remain unimplemented.
