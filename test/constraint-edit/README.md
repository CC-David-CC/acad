# Existing constraint edit — candidate

`editExistingConstraint` is the common synchronous path for editing an already retained constraint. It validates allowed/editable fields with the current parameter resolver, snapshots constraint constants and resolved caches, and uses the existing sketch transaction/rebuild/rollback boundary. If the edited constraint or any previously nonrejected constraint, including a redundant one, becomes rejected, the edit is refused and constants, cached values, geometry, solver state, backlinks and history are restored. A previous rejected constraint may remain rejected. The editor distinguishes a retained request from a new, not-yet-admitted relation; only the former uses this operation. A postcommit refresh or dialog-notification exception does not roll back an accepted edit.
