# Begin centered-parent repair candidate

`beginWorkerCenteredParentRepair({revision,index,featureId},{signal?,valid?})` uses the revision from `inspectWorkerHistory()`. It is an explicit view transition: the selected centered-hole target is inspected in the current full history; the prefix is privately replayed, and only a successful prefix is published. It returns `{revision,index,featureId,reason,candidates:[{bodyId,lidFaceId,parentFeatureId,regionId}]}` where the new revision binds the changed view and the candidates are current supported semantic LIDs. The captured failure reason may be null. Save while the prefix is displayed remains refused. This is not a read-only call and is not yet a general reference repair API.

`repairWorkerCenteredHoleParent({revision,index,featureId,faceId},{signal?,valid?})` uses the new revision and an explicitly chosen LID. The wizard's parent field and typed command share the same full-suffix candidate replay. Current success is `{changed:true,index,featureId,faceId}`. A dependent reference that cannot replay is refused with the dependent history index. Undo of a deleted-parent repair restores unresolved authored history, displays the retained repaired-revision model as stale and refuses Save; redo privately replays.
