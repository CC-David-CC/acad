# Sketch revision guard performance investigation

Tested `353fdc843` sketch source on the strict-CSP `aadc2426` app build, SHA-256 `e282632d4536af7bb964abe44f2ab6c7fef05e23b2d2120396b87e95ce2b6ca6`; the commits differ only in documentation and a camera test, with no `web/app/sketcher` changes. The live viewer and supported LengthRelation inspect/invoke paths were used, not a mock DOM or solver. Reproduce `sketch-revision-performance-browser.test.cjs` with `JSKETCHER_TEST_URL=http://127.0.0.1:20312/ CODI_TEST_CDP=http://127.0.0.1:20311 PUPPETEER_CORE_PATH=/tmp/codi-occt-release-control/node_modules/puppeteer-core /tmp/codi-files-move-node/bin/node`. Desktop Chromium, 1 run, 5 sequential edits per fixture; timings are observations, not performance guarantees. Test instrumentation wraps the real serializer to time it, uses a browser long-task observer and a 10 ms main-thread heartbeat; no sketch computation was transferred to a Worker.

The 17,112-byte 64-segment sketch inspected in 0.6–1.4 ms; full invokes took 33.9–45.7 ms and maximum heartbeat interval was 55.9 ms. A near-limit 1,047,695-byte sketch contained 64 segments and 102 legal labels with 1,020,000 total repeated characters: inspection 5.8–7.9 ms; full invokes 69.3, 2528.3, 94.9, 90.9, 89.6 ms; a 2535 ms long task and maximum 2601.7 ms heartbeat interval occurred. Per-call strict serialization was 1.1–2.7 ms in those near-limit samples. The full invoke includes validation, solver, history and rendering; these measurements do not attribute the entire delay to the guard. Full samples and a sanitized debugger stack are in `sketch-revision-performance-evidence.json`.

A single legal 1,037,000-character label plus two segments caused a separate initial run to exceed 70 seconds. That first harness had no phase markers, so it did not identify the stage at which work stopped; only its owned page was closed. A subsequent 8-second profiled single-edit run completed, with sampled native `measureText`/`fillText` time; it did not reproduce the stall. The five-edit diagnostic `sketch-large-label-stack-browser.test.cjs` then showed load, serialize, first inspect/invoke and second inspect completing, but second invoke still active at eight seconds. A CDP debugger pause captured `diff_match_patch.diff_commonPrefix → diff_halfMatch_ → diff_main → HistoryManager.getDiff → _checkpoint → runSketchTransaction → addLengthRelation`. Raw pause file `/tmp/codi-sketch-large-label-paused.json`, SHA-256 `d0e3ccb1d7c51078d7931904c360807140be77cbc91bb61706887cf8eda0255c`; the profile stop could not finish while that long synchronous task ran. This identifies synchronous history diff as the sampled blocking path, not proof that text layout is free or that every large sketch behaves similarly. Large text was deliberately adversarial but accepted by current strict native sketch validation.

The guard still captures one exact strict serialized snapshot and reserializes it at verify; a realm-local mutation epoch supplements it. The supported length relation, length measurement role, signed/projected distance, line relation, whole-entity fix and rigid-group operations use this shared guard. Epoch hooks cover parameter changes, constraint membership/constants/rollback, stage/generator membership, layer add/remove, IO reset, roles, object translate and explicit spline mutation methods. Label/dimension text and offset fields, shape internals and future mutation entrypoints still require an authoritative audited ownership model; raw direct field writes must be distinguished from ordinary UI paths. Snapshot equality detects changed persisted data, but not an unhooked change followed by an exact ABA restoration; hidden nonserialized state additionally depends on the epoch. No claim of complete epoch coverage follows from these controls.

Next bounded fix: make large history entries use exact before/after string snapshots with explicit total-byte and entry-count eviction, while retaining compact diffs for small entries. Compute any future expensive compression/diff in a cancellable Worker only when publication ordering and stale revision checks are preserved. Snapshot fallback must preserve existing undo/redo, branching, strict restore/rollback, authored text and lifetime semantics; no narrower input limit. Release evicted strings and bound retained history independently of the existing one-MiB command guard. Qualify mixed entry/branch behavior, failed checkpoint atomicity, actual long-label repeated operations and save/reopen, memory, long tasks and 390px emulation. UI-thread strict capture/verify remains an open worker-first issue until a complete authoritative mutation protocol and bounded snapshot extraction are demonstrated.
