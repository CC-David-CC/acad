# Bounded large sketch history

Source `41bb3ea0c4a543fe10a17e024b968933ee5c27d8` includes `2f2182240` and follows the pre-fix evidence in `SKETCH-REVISION-PERFORMANCE-20261105.md`. A checkpoint with either serialized state over 2,048 UTF-16 code units uses exact before/after authored strings, not `diff_match_patch`; smaller states retain compact reversible patches, with library `Diff_Timeout` set to 25 ms. That deadline is not a preemptive guarantee inside every library loop; the 2,048-unit input bound also applies. A conservative retained-entry charge counts two bytes per UTF-16 unit. After a new entry is ready, oldest entries are evicted to 100 entries and 8 MiB of charged entries. One newest transition may exceed 8 MiB and is retained alone so a valid larger sketch is not rejected or stripped of its latest undo. This is a `max(8 MiB, one transition)` entry budget, not an absolute memory bound; current state, caller data, recovery state and engine overhead are additional. Reset and viewer disposal clear retained history. Text is never truncated and no raw geometry/native handles enter history.
