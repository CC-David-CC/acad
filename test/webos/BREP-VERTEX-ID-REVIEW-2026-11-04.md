# BREP vertex ID correction

Base `870f7e8d2154f561134180b51b90c5a466b72166`. Before the change, the real browser test constructed an OCC BOX and a Native Mesh BOX, and failed `BREP vertex IDs must be strings: 'object' !== 'string'` on the OCC model. `MBrepShell` passed the BREP vertex object itself as the MVertex ID. The immutable baseline fixture's `index.bundle.js` SHA-256 was `11377842e2be590141931bfe17030fb96f301a8003cb85ad66a5564350eae2e3`, `sketcher.bundle.js` `85a038b2ef773e79617cda56cf3087ab1c3bddc8960c2c052e4cbbd890347a99`.

The narrow `mshell.ts` correction creates string IDs scoped to the shell ID at construction. A valid producer-supplied topology label is encoded under a producer-specific prefix; an absent label receives a separate ordinal prefix. Both forms are disjoint; duplicate producer labels, IDs colliding with that shell's face/edge IDs, and malformed/non-string/whitespace-surrounded supplied labels are rejected instead of silently rebound. Producer labels are carried in `vertex.ext.vertexIdentity` with stability `unqualified`; ordinal fallback is explicitly `unstable`. This metadata is runtime-only and does not establish persistent topology identity. Native Mesh's existing later feature-scoped vertex ID assignment is unchanged. Uniqueness assumes distinct containing shell IDs; it does not repair any preexisting global registry collisions between separately supplied shell, face or edge IDs.

The positive browser test `brep-vertex-ids-browser.test.cjs` uses actual OCC and Native Mesh BOX operations, the real CAD registry, two models and fresh native snapshot/replay. It checks eight string vertex IDs per model, registry resolution, cross-model uniqueness, producer-label retention in shell-scoped IDs when rewrapping real Native Mesh topology, rejection of duplicate and malformed labels, and equal regenerated IDs for this unchanged two-box fixture after native history replay. It also creates an authored rectangle and actual EXTRUDE prism, verifies its eight string vertex IDs resolve uniquely, and confirms VERTEX selection is not exposed. Equal IDs on this one replay are not proof of durable identity under edits, topology changes, reordering or other runtimes. No vertex reference is stored by an actual user feature in this test. Vertex selection, durable vertex references and their save/replay validation remain a separate queued capability.
