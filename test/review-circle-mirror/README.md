# Circle Mirror Save compatibility

The b4 direct app's real Circle tool and registered Mirror action created a source circle away from the reflection axis and its mirrored circle. The actual editor Save and fresh-context native snapshot restore preserved the serialized objects, radius and generator references (`baseline-browser.test.cjs`, `actual-circle-mirror.json`). This is a direct local app fixture, not a signed-host or printer test. A prior staged Worker built before Circle support refused that real source as `UNSUPPORTED` (`prior-refusal-browser.test.cjs`); its code for this policy is equivalent to the 9418 segment-only policy, but it was not rebuilt from exact 9418.

The bounded stage policy now admits Circle-to-Circle Mirror pairs with the same strict owner/order rules as Segment, and verifies reflected center, positive finite radius, matching radius, generated IDs and `:C` ownership. Arc and other curve Mirror types remain explicitly unsupported. `Circle.mirror` now copies source radius as well as reflecting the center; the generic SketchObject mirror visits only child points, which otherwise leaves a changed radius stale.

The actual strict-CSP Worker (`b36a2144aa61c8343e6c4bf3b85eef4199dee4ba28025a004e4ed03aa84a4989`) solved the captured source after adding a diameter edit and moved center, regenerated radius and reflected center, and solved a later-stage point attached to the generated `:C`. It refused stale output radius and center. Six pure Circle/stage controls, the existing segment-Mirror Worker controls and TypeScript pass. The current app's UI Save/native reopen with this patch remains untested; Worker constraint changes are direct fixture inputs, not an interactive diameter-edit qualification.
