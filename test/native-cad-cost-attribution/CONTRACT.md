## Timing and observer authority

The driver marks public operation, sync-metadata polling, audit-copy, state/oracle and idle phases separately. Public Save/Open/export wall intervals include the actual host/model/codec/Files behavior needed by that command; they are not codec-only CPU or exact hydration timings. Expensive detached state collection and browser/server byte collection happen outside the corresponding public-command interval and are explicitly labeled harness work. Background sync may overlap phases; do not infer disjoint CPU time from these boundaries.

* Passive own-page/document-start PerformanceObservers record bounded long tasks and RAF intervals for outer and CAD/staging frames. Snapshot/drain while frames exist; removed-frame/startup gaps, unsupported APIs, throttled hidden RAF, overflow and sampling errors remain visible. No monkeypatch of production functions, postMessage, timers, model, Files or renderer; no debugger pause/interception/global cache clear. Cross-frame overlapping tasks are not additive.
* CDP sessions attach passively only to the exclusive browser's own page/Worker targets. Record bounded request/response/cache/completed encoded-byte facts without request/response bodies, headers, credentials or payload capture. Missing/unfinished requests are unknown, never zero. Each CDP scope is separate. Observers can miss a fast Worker/startup request; this must remain a coverage gap.
* Sample actual CDP V8 heap-used/total independently from actual available Native `HEAPU8`/`HEAP8` ArrayBuffer capacity. Capacity is read only from existing own data in the actual Worker, never a Native call or guessed initial allocation. Missing access is unavailable, not zero. Neither counter is physical RAM and no forced GC is used.
* A Linux process-tree sampler verifies root's provided Chrome PID, start time, exact existing user-data-dir and CDP port. It reads only that process/descendants, with bounded PID/sample/record limits and root-selected 250..1000ms cadence. Record per-process RSS/PSS/private and unavailable/new/exited processes. Summed PSS is a sampled process-tree estimate, not a continuous peak; RSS is not unique physical memory. Node/server/OS caches remain outside it. Root must use a dedicated owned process; the driver refuses a preexisting live page rather than closing foreign pages.
* Record Worker create/destroy, observed codec identities, bounded frame resource counts and read-only Native buffer capacities. Stop observers and detach only owned sessions; close only the harness's pages/contexts and disconnect from the browser. Root retains process custody. No immediate OS-reclamation guarantee from Worker retirement.

All observation failures/overflow are recorded independently from semantic success. The after-whole ledger must mark required coverage incomplete instead of fabricating a successful cost measurement. Instrumentation itself adds work; this is an instrumented attribution run, not uninstrumented latency/phone/WAN/cold-load qualification. Root chooses any future SLA/safety threshold separately; this packet creates none.
