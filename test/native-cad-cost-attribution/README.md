## Cost outputs and interpretation

`receipt.json` binds inputs before/after, exact served/runtime pins, actual public operations, semantic state and byte files. `cost-events.ndjson` is a bounded append-only passive observation stream. `cost-summary.json` records custody/profile, phases/targets/limits and final observer counts. The after-whole `oracle.json` includes independently reconstructed per-entry costs and a `costLedger`.

* Public command timing starts **after** observer boundary sampling and ends when that actual public call settles. `sync-metadata` separately polls existing mirror `stat` / server `version` SHA+size until the same normal generation is synced. No new Files API. A metadata hash response can itself require server work; it is not inferred free.
* Browser/server actual byte equality is then checked in explicitly named `harness-artifact-copy` phases. These necessarily materialize small evidence bytes; they are outside the respective Save/export call wall intervals. `harness-state` snapshots likewise remain visible. Node-held receipt/source copies are excluded from Chrome-tree PSS; browser temporary audit buffers can persist until ordinary GC and are not hidden. Background sync and allocator retention can overlap later phases.
* Main long tasks/RAF use document-start hooks for future owned frames and an after-login outer installation. Old/staging-frame removal, startup/hidden RAF gaps and unsupported APIs remain explicit. The ledger maps browser `timeOrigin`+event times against Node phase wall times rather than assigning a delayed drain's tasks to that drain's phase. It never sums overlapping outer/iframe work.
* Passive per-target CDP sessions report actual completed encoded receive bytes/cache flags and V8 heap-used/total, without recording bodies/headers or mutating payloads. Network diagnostic buffers are explicitly limited to64KiB total/16KiB per resource per attached scope, post-data inclusion limit1byte; no response-body reads or durable-message mode. This small diagnostic overhead remains measurement overhead, not a zero-copy theorem. Native-capacity reads inspect only existing own-data heap views in an actual Worker; the Worker URL/scope identifies which runtime owns them. A different Worker's heap is not automatically Native OCCT capacity. Startup requests or transient heaps can be missed; missing data is unavailable, not zero.
* Process sampler verifies PID lifetime and records each process's RSS/PSS/private, traversal coverage and sampled totals. Per-phase in-wall samples and boundary samples are reported separately. Short phases may have **no** complete in-wall memory sample. Sampled PSS/private maxima are lower bounds on continuous maxima; RSS is not physical unique-page usage. Heap-used, Native buffer capacity, logical owner counts and process memory are separate quantities.
* The main observer reads only small existing resource counters, processing/epoch/history/model counts; no mesh copy/Native call/solve. Worker retirement is actual CDP target destruction, not an OS-memory-reclamation assertion. Observers detach only their own sessions and remove only their own hooks. A 1.5s observation read timeout records a coverage failure and does not cancel product work.
* Semantic/artifact `status:PASS` and `costLedger.status` are separate. Missing required process/heap/Native-capacity/network/long-task coverage produces `PARTIAL_OBSERVATION_COVERAGE`, never a fabricated zero or unqualified cost pass. Even fully recorded scoped observations are not continuous peak/cold-load/phone/uninstrumented latency qualification.

All existing128MiB/native/per-format bounds and1GiB installed-code inventory stay unchanged; no new RAM/SLA threshold. Encode changed-entry UTF8, reused compressed spans, whole prepared SHA and committed rebase SHA are distinct. Actual uploaded/wire/delta/OPFS/full-integrity scan totals are marked `notObserved` rather than inferred from ZIP savings. Optional caches are not produced here. Large meaningful authored-source/surfacing and actual128MiB CAD capacity remain a separate missing input/qualification gate.

On ordinary success/failure with settled commands, the driver closes its own pages/contexts, waits for observed codecs and samples post-close idle; root retains Chrome process custody. On an uncertain write or write-command transport timeout, it preserves the owned context for root settlement review, records that fact, detaches passive observers and disconnects; it does not retry, rollback or falsely report clean retirement. Root must resolve any such retained context before other work.
