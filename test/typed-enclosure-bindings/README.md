# Research: derived typed field bindings

`physicalBindings.mjs` accepts an explicit version-1 computational manifest assembled from a captured, current authored history and sketch. It is not persisted and does not prove that the caller included every dependency. Feature targets carry index, stable positive feature ID, exact operation type and the complete allowed dimensional field set; rectangle targets carry a face ID and both stable driving segment IDs. Returned values carry explicit `length` dimensions and canonical millimeters. Duplicate identities, sparse lists, unknown operations, nonnumeric/non-name expressions, wrong units, invalid domains and inconsistent V1/V2 enclosure geometry refuse. Existing `enclosurePlan` checks coupled dimensions; Native Mesh precision and actual OCC/Manifold solids remain the engine's responsibility.

The optional parameter Worker request `{version:1,revision,source,manifest}` evaluates source and manifest together, returning `{revision,ok:true,result,bindings}`. Existing requests and responses remain unchanged. The recipient must authenticate the returned revision and exact captured source/manifest, validate lifetime and complete supported-consumer discovery, and deep-copy any cross-thread result before atomic publication. A worker response is neither an accepted document nor a material/geometry proof.

The experimental common participant derives the manifest from bounded full-tip history and one supported rectangle source, checks the returned identities, and uses the existing private replay/publication boundary. Explicit feature field edits and the existing depth and rectangle/corner commands route into it; the journal stores bounded authored field/source changes and at most one exact sketch pair. Enclosure V1/V2 and centered/corner diameter fields are annotated lengths. A material or appearance change is captured and guarded; existing assignments remain intact and the existing save flow requires a review/rebind after geometry changes. Tests cover real OCC enclosure roles and geometry, shared plate/enclosure dependencies, cancellation, invalid edits, undo/redo and native reopen. One parameter-bound rectangle is supported; arbitrary sketch dependencies, extra unrecognized consumers and configurations are not qualified. This branch requires independent review and integration with the separately developed typed sketch editor path.
