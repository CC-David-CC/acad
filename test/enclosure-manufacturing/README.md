# Enclosure manufacturing mesh candidate

Integration review: `6833729d` carries this candidate alongside the existing material/hash-worker code. The integration owner inspected surface classification, area/overlap, edge/link closure, volume and worker/controller ownership checks and reran both Node suites on R730 and the integrated workstation checkout: 16 tests passed on each. These are captured-mesh and writer controls; the integrator has not independently rerun the real-engine Chromium fixture. No desktop export or deployment is implied. The declaration merge retains both manufacturing hash and enclosure manufacturing modules.

Research-only and not integrated into the desktop export flow. A newly reconstructed checked enclosure mount provides readEnclosureManufacturingMesh({op:'solid.enclosure.manufacturing-mesh',version:1,handle,maxDeviationMm},{signal}). The pinned engine Worker freshly interrogates its live private shape; it never reuses the preview buffer. The caller must capture and guard the exact authored revision, feature/role, account and window, verify the live pair before publication/write, and close the disposable owner. No handles or pointers are serialized.

Each BODY/LID result contains separate Float64 vertex and Uint32 triangle arrays and planar-boundary-checked-v1 evidence. Exact native numeric coordinates are indexed without tolerance-based welding or repair; inconsistent seams refuse. The Worker checks a maximum 128 triangles/384 vertices, finite nondegenerate coordinates, unique classification onto eleven expected oriented planar surfaces, axis limits and void exclusion, per-surface area/overlap, oriented paired edge incidence, connected vertex links, one component and signed analytic volume. The main-thread controller checks live mount/role association, bounded byte lengths/counts, finite indices/coordinates and exact evidence fields, then returns independent copies. Geometric qualification remains in the trusted pinned Worker; if that asset is untrusted its evidence is not authoritative. Different deviation requests require a fresh reconstruction.

OCC accepts maxDeviationMm between 1e-6 and 0.01 mm. Manifold accepts max(1e-6, max(width,length,height+lidThickness)*2^-22) through 0.01 mm and also retains its stricter Float32 dimension/feature domain. Wall, clearance, lid/lip thickness, lip dimensions and axial gap must exceed sixteen times the requested deviation. This is an algorithmically checked nominal planar boundary tolerance for these limited shapes, not a general kernel, material, printer or physical fit guarantee. observedPlaneDeviationMm measures only normal-coordinate residual.
