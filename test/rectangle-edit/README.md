# Atomic rectangle dimension edit

Integration follow-up: the edit's source guard now uses bounded sketch-key
membership/write versions rather than the whole RAM-workspace revision. An
ordinary project-cache save during private solve preparation must not cancel
an unchanged authored sketch. The browser control now injects that real cache
save before the private solve; it awaits a matching rebuilt integration run.
The existing prepared-write participant still checks its complete workspace
revision immediately before the synchronous commit. The metadata guard limit
is 256 sketch records; this is a narrow CAD edit limit, not the Files size cap.

The private core method `editRectangleDimensions({revision,faceId,width,height},{signal?,valid?})` edits only the two unambiguous driving SegmentLength constraints of the supported authored rect-0…3 sketch. It solves a copy in the real headless sketch worker, verifies residuals and authored identities, and replays the full current tip against an evaluation-only read-only sketch view. Only after the complete dependent replay succeeds do the existing prepared-workspace and model publication participants commit. Other authored constraint records remain intact; unsupported sketch geometry or relations are refused. The original receipt reported `authoredUndo:false`; the later bounded journal qualification below supersedes that limitation for the in-memory authored journal. Native history pointer navigation alone is not undo for a sketch-byte edit. Signed parent qualification and production packaging are separate.
