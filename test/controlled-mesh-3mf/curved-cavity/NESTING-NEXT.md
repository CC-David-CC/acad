# Confirmed general shell-nesting gap; proposed next contract (no implementation)

The genuine Native cavity is valid/one solid/two shells and passes independent bounded geometry/void/approximation checks. The current encoder refuses UNSUPPORTED_MESH_DOMAIN with actual cause `Ambiguous overlapping shell bounds`: core3mf.validateShellNesting permits overlapping shell AABBs only when both shells satisfy exactBox. Each actual cylindrical shell has252vertices/500triangles, so that shortcut does not apply. This is a writer-domain gap, not invalid geometry. Do not bless it with sourcePreserved:true or a native solidCount alone.

Recommended common derived-mesh contract: replace only the exact-box nesting restriction after a separately qualified Worker-side embedded-shell validator exists. Its inputs remain the same finite indexed oriented closed mesh; it creates no design model/identity. Output is either a complete shell-containment forest with depth/orientation proof for every triangle component, or an explicit geometric contact/intersection/refusal/resource reason. No guessed centroid, AABB-only inside test, floating winding threshold or tolerance welding. Existing32objects/150kvertices/250ktriangles/64shells/XML caps remain; add an explicit bounded candidate-pair/predicate-work budget and deadline, reporting RESOURCE_LIMIT rather than invalid geometry when exhausted. Actual32-hole/treated curves must qualify under measured budgets before adoption.

Required algorithm obligations:

1. Preserve existing index-based manifold edges/vertex-link cycles and duplicate/degenerate guards. Build exact edge-connected shells. Use a bounded BVH/AABB broad phase solely to prune triangle-pair tests.
2. Establish geometric embedding: robust exact/adaptive orient3d/2d predicates over the actual Float64/dyadic coordinates; handle coplanar triangle intersection explicitly. Across distinct shells of the SAME mesh object permit no intersection/contact. Separate printable parts are not silently subjected to an arrangement/nonoverlap certificate. Within one shell permit only the actual shared indexed vertex/edge as the exact geometric intersection; reject any extra overlap or contact, including nonadjacent duplicate coordinates. No proximity adjacency or component-count certificate. A numeric predicate/dependency must be inspected/qualified first; do not silently substitute ordinary epsilon arithmetic.
3. After disjointness is established, classify one actual existing vertex of each shell against each relevant other shell using robust ray parity with a complete half-open/tie rule or symbolic perturbation. The disjointness proof makes it a strict inside/outside query. Do not use sampled centers or solid-angle rounding to infer containment. Build a consistent acyclic containment forest, derive full depth, require shell orientation sign to match depth parity using stable/exact signed-volume sign. Preserve cavities with multiple boundary shells, nested islands and separate positive components where the serializer's existing domain admits them.
4. Resource exhaustion/uncertain predicate or unqualified domain must refuse without repair/fallback. Mesh approximation may itself introduce contact in a very thin wall even when source BRep is valid; Native validity is not a universal certificate for the derived triangles. Source authority remains the private producer/orchestrator boundary.

A scoped Native-evidence alternative requires actual shell-role/geometry validation AND exact source-shell→emitted-triangle/component correspondence from the same controlled tessellation, plus a defensible derived-mesh embedding check. A serialized sourcePreserved flag, solid count, shell orientation alone or a source-valid boolean is insufficient. Existing binaryv1 has no shell labels, so any Native-side certificate/sidecar must be versioned, size-bounded, source/build/full-buffer-bound and privately issued; no inferred map from bounds/nearest positions. This is a separate design decision, not implemented here.

Acceptance before general adoption: this actual closed cylindrical cavity; off-center curved cavities/multiple voids; boxed nested-island/separate-component legacy controls; genuine valid curved/holed/treated/32-hole artifacts; proper tiny gaps and actual tangent/intersecting shell cases; reversed inner winding and duplicate/nonadjacent contacts; coplanar face/edge/point contacts; large translations/scales and near-degenerate rays; resource/cancel cleanup. Retain the existing spindle-torus self-intersection counterexample as a negative that must no longer be mistaken for an embedded manufacturing mesh. Synthetic predicate/triangle mutations must remain labeled; Native failures in attempted contact fixtures must not be replaced with invented successful geometry. Independent XML/material/void checks remain separate from the general validator proof.

No production writer, Native runtime, app, metadata authority or interface policy is changed by this proposal. Full multi-region single-part and general nesting goals remain OPEN.
