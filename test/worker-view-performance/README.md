# Worker sketch view responsiveness

Direct app source `0ac42887a` on loopback 20492, app SHA-256 `c38de8229fd955a300138b8276aa0a3c7ef39c8664d08cdb7edeab3cbf6aa182`, emitted sketch Worker SHA-256 `a058446bc1fdd8c86b84899e337f3962d7222a8d38b662612819f73b82ef3c08`. Real app, real Worker and real Canvas; no DOM, canvas, solver or rendering stand-ins. Each run creates one owned browser context containing two same-origin CAD instances (top-level and iframe), binds real host lifetimes and closes both. The test instruments Canvas stroke/drawImage calls without changing their behavior and counts real Workers/terminations. Parent-window timer, rAF and PerformanceObserver callbacks record responsiveness while the sibling view opens. These metrics do not prove a separate renderer process or independent device.

The small control creates a plane and point via the public craft commands, opens the Worker view, selects that point and verifies unchanged native bytes and absent numeric cache. The dense case is deliberately different: a test constructs a 514-segment, 512-LockPoint native project source (139,517 UTF-8 bytes) and imports it into the second empty workspace through the actual project restore. It is admitted native test input, not a claim that 1,026 public authoring commands were performed. The Worker view opens using the public craft API, draws actual non-background pixels on a 1069×647 canvas, keeps the source unchanged and does not open the legacy editor. A subsequent open is aborted after its Worker is dispatched; the view is absent and all three created Workers terminate. The sibling remains responsive and accepts inspect calls.

Two single runs are preserved: open wall 2476/2433 ms; inspection Worker 1062/1012 ms, projection Worker 997/1000 ms; max observed sibling timer gap 24.1/23.9 ms; max rAF gap 100/16.8 ms; no observed PerformanceObserver long tasks. Each produced 1,028 strokes and two buffer swaps, including a ResizeObserver redraw; native Canvas stroke calls total 1.0/0.7 ms and swap calls 1.8/1.0 ms, excluding path creation, other JS and GPU/compositor work. These overlapping timings are not additive, statistical guarantees, or an end-to-end manufacturing/Files benchmark. A prior 0ac draft used a default 300×150 iframe and produced a 254×78 canvas; it is not the representative receipt. The older hydration test's much larger synchronous admission stall used a different 2bb app/build and instrumentation, so the numbers are indicative, not a controlled same-build A/B.

Constraint annotations remain source-only in this view. The `inspectWorkerSketchView()` response on this version exposes unsupported objects but not the projector's `unrendered` details; this was reported to the integration owner. `receipt-1.json` and `receipt-2.json` preserve both full-sized runs.
