# Worker save integration review

Separate exporter groundwork: `enclosureManufacturingRead.mjs` reconstructs a v1 body/lid in a disposable caller-supplied pinned engine mount, reads manufacturing meshes rather than previews, and closes ownership in `finally`. Four mock lifecycle controls pass (normal return, stale revision, readiness cancellation, pre-cancel and cleanup refusal). These tests establish orchestration only, not valid geometry. This helper is not yet wired to the desktop exporter; v2 label roles and same-reconstruction contact evidence remain pending. The existing exporter continues to reject unsupported worker geometry.

Integration checkpoint `6e7e615f` carries the complete save-worker sequence, including size-boundary correction `591315a0` and additive capture API `672aa235`. The integration owner reviewed the capture guards and independently ran TypeScript (`tsc --noEmit`) and the three `worker-save.test.mjs` controls: legacy digest compatibility, cancellation/stale refusal, and size/material revision rejection all passed.

The integration owner also ran `worker-save-browser.test.cjs` through Chromium at the agent's live loopback fixture, using a fresh isolated browser context. That fixture served the isolated `672aa235` build, rather than a new build of the combined `6e7e615f` branch. The test passed real OCC enclosure creation, material UI, hash-worker cancellation/termination, fresh native replay, appearance-only edits preserving material identity, captured save currentness/abort, in-flight history-edit refusal, dimension change and explicit material rebind. The test closes only its own context; the agent's browser and fixture remain shared test resources.

Desktop caller `d8a60a427` now uses `prepareHostSave({signal,valid})`, checks the captured authored revision immediately before file dispatch, and records exactly the serialized envelope as its saved baseline. It checks again after the write to identify an earlier-version save when edits happened during the write. The guard is operation-scoped and is not retained as the later dirty-state baseline. Independent signed caller/fault qualification remains pending; the browser test above is a CAD-app fixture, not that evidence.

Limits remain explicit: manufacturing preparation is capped at 8 MiB; Files independently supports representative 128 MiB transfers. Detached capture, workspace serialization, host `JSON.stringify`, dirty inspection, and other unrelated save/export paths still contain main-thread work. This change moves incremental SHA processing to the dedicated worker and removes repeated caller snapshot comparisons during Save; it does not establish a fully worker-serialized 128 MiB CAD path or physical-phone performance.
