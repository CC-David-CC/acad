# Independent review of large sketch history

Reviewed `2f2182240` plus `41bb3ea0c` without product changes. The existing `node test/coreTests/run-sketch-history.cjs` passed in a local webpack-backed run. The independent test `sketch-history-independent-review.test.js` additionally passed repeated mixed patch/snapshot undo/redo and branch truncation, byte accounting within the documented 8 MiB charge, and failed snapshot restore plus failed rollback preserving the cursor and recovery snapshot. Run it with `node node_modules/webpack-cli/bin/cli.js --config test/coreTests/webpack.sketch-history-independent-review.cjs` then `node --test /tmp/codi-independent-history-tests/test.cjs`. Tests use a synthetic viewer for history state, not an actual browser or native file. Prior actual Chromium evidence remains separate.

One exception-path retention gap: `Viewer.dispose()` clears the canvas and calls `this.toolManager.dispose()` before `this.historyManager.init('')`. If a tool's cleanup throws, disposal exits before history reset; the remaining viewer reference retains `lastCheckpoint`, entries and any recovery snapshot. The independent unit uses the actual `Viewer.prototype.dispose` with an injected throwing tool cleanup and confirms a 9 KiB snapshot remains. It is an injected cleanup failure, not evidence that ordinary disposal failed. `InPlaceSketcher.exit()` also exits early on such a throw, so the error must remain observable; clearing history in a `finally` while separately preserving disposal errors would address the retention gap. The baseline test at aaba21310 intentionally asserted the defect. The root follow-up moves the history reset and generator reset into finally blocks after tool cleanup. The regression now makes tool cleanup append another checkpoint and throw, then requires empty entries/checkpoint/recovery and pointer -1 while preserving the original tool error. All three independent tests pass with that change; real-browser large-history evidence remains the earlier separately qualified run.

The 8 MiB is a conservative *entry charge*, computed as twice UTF-16 code-unit lengths for snapshots and serialized patch descriptions, not an exact JS heap bound. It excludes current `lastCheckpoint`, caller-held snapshots, object/array overhead, temporary work, and recovery state. One individually oversized newest transition is deliberately retained as the explicit exception, so the charge can exceed 8 MiB; older entries are evicted. Compact diff inputs are capped at 2,048 code units and library timeout set to 25 ms, but that timeout is not a preemptive deadline on every internal loop. No responsiveness or total-memory guarantee for 128 MiB documents is established. `init` resets retained entries and checkpoint but leaves `_counter` unchanged; this retains no authored text and may cause an earlier subsequent light checkpoint, rather than corrupting undo state.
