# Disposable viewer hydration investigation

This is a diagnostic, not a hydration implementation. A test-only same-origin proxy forwards the unchanged CAD app and supplies the separately pinned, experimental data-only transition Worker. The test creates 514 real serialized segments and 512 accepted LockPoint relations, sends the captured native source and empty boundary to the actual disposable Worker, checks its revision and successful strict replay, then loads its result into an isolated actual browser viewer. It runs two independent fresh contexts: ordinary `IO.loadSketch` and a test-only patch replacing `AlgNumSubSystem.rebuildAdmission` with a no-op. **The patched viewer is an incomplete, untrusted diagnostic and is closed without saving, accepting, publishing, or reusing it.** The experiment never alters production source, existing fixtures, or another context. The patched result is not evidence that skipping admission is correct.

The test-only proxy binds loopback and forwards app requests unchanged to 20480. It enforces pinned Worker and verb asset bytes. The app document retains its existing strict script/Worker CSP (`'self' 'wasm-unsafe-eval'`, `worker-src 'self'`; CSS policy remains the app's); no unsafe-eval, blob Worker, fake viewer, Canvas shim or DOM shim is used. `receipt.json` is one matched observation in a shared Chromium process. The source had 139,424 UTF-8 bytes and 514 authored segments; the live sketch layer additionally contains one non-authored object. The valid Worker replay took 1253/1227 ms in the normal/diagnostic contexts, including Worker startup and copy. Normal `loadSketch` took 726 ms; admission was 435 ms, nested `prepareRaw` 428 ms, `finishTransaction` 586 ms inclusive; three `notify` calls accumulated 243 ms inclusive. The no-admission diagnostic took 255 ms, `finishTransaction` 130 ms and three notify calls 218 ms inclusive. Each load requested 514 refreshes and produced one coalesced repaint (4.0/2.0 ms); `objectsUpdate` was invoked 516 times. These timings are instrumented, overlapping inclusive values and cannot be summed. They are single-run observations, not latency guarantees or a proof of correct hydration. A preliminary test incorrectly asserted the rendered-layer count equalled authored count; the final test asserts the bounded count and documents the extra non-authored object.

The normal system had 1028 polynomials and 514 isolations. The skip diagnostic had zero polynomials and no isolations, yet exposed `solveStatus.success=true`, zero conflict/redundant sets and `dof=null`: success is the constructor default, not established solver evidence. Both had `projectedLastValid=null` for this particular non-projected fixture; projected-direction and rigid tests need separate treatment. Worker time and sync graph creation cannot be added to claim an improved end-to-end path. The 255 ms residual includes graph construction and overlapping notifications, so moving only admission does not meet a responsiveness objective. No live operation was attempted against the incomplete graph.

## Existing ownership and constraints

`IO._loadSketch` validates then calls `cleanUpData`, resets the module-global ID generator and live layers/selection/parametric manager, reserves IDs, constructs objects and index, attaches dimensions, labels, constraints and generators, then `finishTransaction` rebuilds admission and attaches annotations, followed by notifications. Stage solves also regenerate generators. This path has observer and global-ID side effects before it finishes; using it directly as a speculative live publication is not atomic. Viewer refresh is RAF-coalesced, but object-update and parametric notifications remain. Existing UI and mutation paths consume live constraint object identity, `conflicting`, `redundant`, admission hints, `fullyConstrained`, solve status and solver structures. Directional relations additionally depend on `projectedLastValid` and fixed-boundary checks. `dof=null` is unknown and must not be turned into a claimed zero or fully constrained state. Native serialized snapshots are history authority, while object pointers, solver parameters, closures, polynomials and isolations are realm-local and are not transferable Worker certificates.

A coherent next seam is an operation-scoped immutable native source/intent/parameter/boundary/frame capture with editor epoch, stage/reference identities, account/window/lifetime and storage checks. The Worker validates/replays that exact captured source and returns checked native data and admission evidence bound to stage/order/constraint identity. A detached real-model preparation must avoid touching the live viewer, module-global ID allocation, selection or observers, retain one eventual authoritative sketch graph, and support all admitted objects, generated outputs and annotations. Immediately before one atomic install, recheck all guards; batch notifications, preserve a recoverable last-valid source/history pointer, and dispose stale/cancelled candidates. Worker and local staged copies must be transient, not separate durable histories. Candidate graph construction and publication failure must never expose partial state.

A new explicit solver-cache state is required: verified geometry/admission is not a populated live solver. Existing classifier/read paths must either use Worker evidence with exact source/stage binding or state unknown; legacy edit, drag, remove, generator and directional operations must queue/refuse while required cache is unprepared, then use a Worker-backed mutation or a correctly rebuilt cache before touching it. Rebuilding the old cache synchronously would reintroduce the measured stall. No path may present constructor-default success or empty conflict sets as proof, and no legacy operation may observe the diagnostic skip state. The existing standalone Worker evidence has no independently authenticated live object pointers; mapping and coverage must be explicitly validated. Projected last-valid/branch semantics, reentrancy, multistage, generators, rigid groups, saved hints, exception/rollback and subsequent legacy mutation all require actual controls before enabling the seam. This is a bounded contract proposal, not a claim all sketch types or a complete worker-first workflow are qualified.
