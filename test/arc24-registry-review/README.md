# ARC24 candidate registry review

Review base `e321b398c`; subject was the root's uncommitted staged-registry and replay-yield diff, not an integrated release. The review found that the first draft flushed on every subsequent PLANE: `runRequest` eagerly read `operationContext.cadRegistry.shells` to call `assertLegacyOperationInputs`, and the staged registry's `shells` getter flushes. Standard plane has no own `admitGeometry`. Thus deferring `setModels` alone did not remove repeated indexing. This was reported to the source owner before integration. PLANE's optional datum resolution can itself require a registry lookup, and any optimization must retain legacy geometry admission for actual inputs. A separate source-level concern is that eligibility checks the type string `PLANE` while operations are registered dynamically; any claimed standard-plane-only behavior needs a trusted descriptor/registry-identity boundary or a narrower documented assumption. This is a hypothesis, not a demonstrated exploit or product failure.

The added browser test is prepared for a matching candidate build and is not yet claimed as run. It constructs actual plane models, checks that staged reads flush and initialize, forces worker-identity collision and reentrant sketch-read refusal, and checks a fresh staged candidate can recover after each refusal. Its artificially tagged worker identity is a registry unit control, not a native kernel proof. Separate actual native restore/cancellation and retained dependent-plate tests are needed to qualify the craft integration. Run with `PUPPETEER_CORE_PATH=/path/to/puppeteer-core CODI_TEST_CDP=http://127.0.0.1:19329 JSKETCHER_TEST_URL=http://127.0.0.1:PORT node test/arc24-registry-review/staging-browser.test.cjs` using an isolated matching fixture.

The negative same-face retry reproduced the inherited bug: the failed reentrant `readSketch` left the face marked initialized; retry returned the face without invoking `readSketch` again (`sameFaceRetried:false`). Set `EXPECT_RETRY_FIXED=1` to require the corrected behavior against the next matching candidate.

The known 10,000-feature cancelled-restore issue was not retested against this candidate. These are bounded browser controls, not a general feature-history or responsiveness certification.
