# Four-corner through-hole geometric planner

`planFourCornerHoles(preparedProfile, centeredRequest, request)` is a synchronous, bounded, data-only planning component. It does not create geometry, inspect a BRep, prove a solid/parent exists, resolve model references, or authenticate ownership. Its future caller must establish that `preparedProfile` and `centeredRequest` are the exact captured original source and centered-hole intent of the current live same-mount parent, and must reject changed document/account/window lifetime or stale handles. A caller-provided center or body is never treated as proof.

The first argument has the exact data fields returned by the existing `prepareRectangleExtrusion`: version 1/2, operation, OCC engine, millimeter unit, revision/digest/face/region, principal frame, positive depth/direction, separate body policy, four ordered authored edges and their world vertices. The second is the exact version-1 input to `planCenteredHole`; the new planner recomputes that center/radius and checks the same source binding. The new request contains exactly `{version:1,unit:'millimeter',featureId,parentFeatureId,centerFeatureId,revision,sketchDigest,faceId,regionId,sideIds:{minX,maxX,minY,maxY},offsetX,offsetY,diameter}`. Feature IDs are distinct canonical positive safe-integer strings; source IDs/digest must match the prepared profile. The canonical region contains exactly the four supplied source edges. The explicit side IDs must match their current geometric side roles, preventing a rotation/rebinding from silently changing an authored side's meaning. The planner does not decide or authenticate these IDs on behalf of the document.

The frozen output repeats the feature and source binding, side IDs and parameters; gives `clearance` (1e-5 mm), positive depth, exact +Z direction, bounded tool margin, recomputed `existingHole:{center,radius}`, analytic expected volume and four frozen `{role,center,radius,sides:{x,y}}` records. Role order is `MIN_X_MIN_Y`, `MAX_X_MIN_Y`, `MAX_X_MAX_Y`, `MIN_X_MAX_Y`. Each center is the intersection of inward-offset actual supporting lines; source vertices are never snapped. Its finite-side foot must lie on each displayed side, each circle must be strictly more than its radius plus the clearance from every side, and every new pair—including the existing centered hole—must be strictly separated by the sum of radii plus the same clearance. This is a numerical geometry margin, not a manufacturing tolerance. Exactly touching at the clearance boundary is refused.

The supported first slice is an exactly constant-Z rectangle and exact +Z through direction; even a tiny actual tilt/oblique direction is refused rather than flattened. Small unsnapped XY deviations still go through the centered planner's rectangle/orthogonality/axis/center checks and the new side and finite-segment checks. Coordinates and dimensions are bounded by the same relevant 1e6 mm center-planner domain; positive radii must exceed 1e-5 mm. General rotated datums, arbitrary boundary curves, more than one prior hole, material or manufacturing semantics, and multi-hole native topology remain unsupported. Output positions/role indices are derived result data, not persisted point coordinates or kernel identities.

Run `/tmp/codi-files-move-node/bin/node --test test/engine-hole/plan.test.mjs test/four-corner-planner/plan.test.mjs` (or Node 24 equivalently). The recorded run passes 17 tests: initial/resized/translated cases; 40 independent axis-aligned geometry and volume controls; an actual prior reversed-solver profile passed through `prepareRectangleExtrusion`; unsnapped XY sides and area; 1e-5 clearance, center/corner/touching overlap and finite-side refusal; canonical identity, side-role swap, invalid/stale/degenerate/tilted frame, bounded-data and getter/sparse controls. In particular, 150×30 with offsets 10 and Ø10 corner holes refuses because the vertically adjacent circles touch; Ø4 succeeds. This establishes only the planner contract, not any worker cut, semantic topology, history publication, save/reopen, physical print or the remaining CAD Gate 1.
