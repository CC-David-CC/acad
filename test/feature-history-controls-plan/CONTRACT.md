## Smallest finite capability

The first complete slice admits bounded ordinary **numeric** modern histories consisting of genuine standard independent `PLANE`, `WORKER_SOLID_BOX_V1`, `WORKER_SELECTED_PROFILE_EXTRUDE_V2`, `WORKER_THROUGH_HOLES_V1` and `WORKER_SOLID_EDGE_TREATMENT_V1` entries, on one explicit already staged native build. No new native code or engine substitution. Constructors remain allowed in the history; first suppression targets are selected extrusion, modern through-hole and edge-treatment entries. Planes and box constructors are initially nonsuppressible, with explicit reasons in discovery. Suppression never means deleting the source sketch or recursively suppressing children.

Typed formulas/configurations, Boolean/Join, shell, revolve/sweep/loft and semantic patterns are explicit `UNSUPPORTED_HISTORY` for this **new control capability** until their dependency contracts are integrated. Existing operations keep their support. In particular, a pattern's successful-hole witness cannot be reconstructed from merely seeing a source context; do not advertise pattern history support by dropping a guard. This finite initial restriction does not mark all remaining C07 families complete.

## One persisted graph and safe schema version

Proposed active entry remains `{type,params}`. A suppressed entry is `{type,params,suppressed:true}`; the same original type, exact params, feature ID, source refs, build and ordered position remain. Active state canonically omits `suppressed`; explicit false/nonboolean/accessor/inherited forms are refused. Only the named supported operation types may carry this field. No duplicate original definition, resolved geometry, native name/handle, model snapshot or saved journal is added.

Add optional **`model.historyStateVersion:1`**, required iff at least one entry is suppressed. No marker when none are suppressed. Strict preflight/capture verifies the marker/roster relationship. Existing `projectEnvelope.mjs` model-key allowlist makes older readers reject a document containing this marker; merely adding a flag to entries would otherwise let an older executor silently run suppressed features. This small persisted schema extension requires root approval before implementation. It is not a second parameter/state document or an archive format rewrite. Both ordinary native source and `.cad` use the same project model admission; no ZIP/chunk/client change is proposed. Modern full models stay one `history` array.

All feature IDs, including suppressed entries and future suffix entries, stay reserved during the live document. Prefix branch does not rewind allocator high-water marks. Undo restores the exact serialized original IDs; normal new features allocate fresh IDs. Native Open recomputes and retains high-water behavior from the complete saved roster/counters as it already does.

## Public operations and exact transitions

Proposed shared Craft factory: `createWorkerHistoryControlCommands(ctx,submitHistoryControl)`; private callback implemented inside existing Craft closure. Proposed Desktop transport: `feature-history-commands.mjs`. Public requests contain own bounded data only, exact inspected opaque revisions, canonical safe numeric feature IDs and no caller-authored history arrays.

| Public command / shared method | Exact request | Successful source transition |
| --- | --- | --- |
| `inspect-worker-history-controls` / `inspectWorkerHistoryControls` | `{}` | Read-only: revision, geometryRevision, history position, full-tip index, build, bounded rows with index/featureId/type/state/dependencies/canSuppress/canUnsuppress and reasons; eligible prefix anchors and branch limits. Revision binds full definition, pointer, sources, expressions, material/drawing, document and operation implementations. |
| `set-worker-feature-suppressed` / `setWorkerFeatureSuppressed` | `{revision,index,featureId,suppressed:boolean}` | Full-tip only. Toggle one exact entry; replay complete candidate from zero, preserving all other entries/params/source bytes. Same requested state is an exact no-op: no new journal/revision/allocation. |
| `set-worker-history-prefix` / `setWorkerHistoryPrefix` | `{revision,afterFeatureId:number|null}` | Evaluate prefix ending at that actual feature; null means before the first entry. Keep the full same definition/suffix, publish only the actual evaluated prefix and its pointer, and record one `history-position` journal entry. No feature ID allocation. |
| `commit-worker-history-branch` / `commitWorkerHistoryBranch` | `{revision,afterFeatureId:number|null}` | Require exactly the currently inspected accepted prefix. Replace the active definition with that exact prefix, discard suffix from the **active graph**, keep allocator high-water, and record one `history-branch` journal entry containing only the detached authored removed suffix and anchors. No new feature or geometry alias. |
| Existing `undo` / `redo` | Existing `{revision,direction}` in Core / existing host API | Route new exact journal kinds through shared dispatcher; no additional public Undo stack. |

Returning to full tip uses the same prefix command with the last feature ID. It is a real evaluated navigation transaction, not an undocumented pointer mutation. In prefix mode, existing new authoring commands remain refused until explicit branch commit or return-to-tip. No change to `addModification` insertion semantics is required for this first slice. Existing successful full-tip append then naturally records the new feature in the same journal and truncates any existing journal redo tail.

Session journal kinds:

- `feature-suppression`: exact index/feature ID/type, prior/next suppression state and immutable definition/source anchors; no copied feature params when retained source already supplies identity. Travel checks the exact current row and whole definition.
- `history-position`: immutable definition identity/chargeable bounded signature, before/after feature anchors and pointers, exact source/material/drawing anchors. It stores no meshes or snapshots.
- `history-branch`: retained-prefix identity and removed suffix **definitions only**, prior prefix position and next full-tip position, before/after neighbor/feature identities. Charge every retained string and suffix byte to existing 64-entry/8MiB journal budget; no uncharged full-history copy. Reuse existing strict operation captures for this finite vocabulary.

The journal remains session-local; Save/Open persists only the resulting authored graph/state. Save/export remains refused during prefix mode rather than saving a misleading prefix display alongside the entire graph. Save a committed branch or full-tip suppressed document normally. Open resets the session journal and genuinely rebuilds exactly that source state.

## Dependencies, source ownership and failures

Build one bounded dependency inventory from validated feature schemas plus actual reconstructed source/producer custody. Hole `producerFeatureId` and `sourceFeatureId`, edge-treatment `producerFeatureId`, and selected profile's actual source face/owning standard plane are explicit references. Corroborate opaque face/body membership against the source records/candidate registry, never parse arbitrary IDs, match names, use coordinates/ordinals or guess that neighboring features are parents. Require parent-before-child for active dependencies. Suppressed entries keep structurally valid references; they do not run or grant a substitute output.

If an active descendant depends on the target, refuse suppression with `ACTIVE_DEPENDENTS`, listing bounded actual dependent feature IDs. Do not silently retarget `target` to a predecessor, auto-cascade suppression or reinterpret output IDs. A child must be explicitly suppressed first. Restoring a parent then a child uses their unchanged definitions and genuine native ancestry, so stable surviving authored selections are preserved only where existing lineage actually proves them. Unknown dependency kinds refuse before evaluation.

At replay, a suppressed entry is skipped **before** operation materialization/admission/native reservation; it neither consumes nor creates models or lineage. Leave existing constructor source faces in the candidate and keep original originating-operation indices for executed rows. The result after skipping a leaf hole is its real reconstructed predecessor solid, not a copied display mesh labeled as the hole's output. Validate supported suppressed params and source identities without attempting to resolve its currently unavailable live output. Full tip still checks complete saved source ownership. Budgets validate backend consistency for all source entries and account actual native cost only for active ones.

Branch commit initially requires that every discarded entry be one of the supported **solid** operations, no discarded source-plane/assembly/surfacing/typed definition, and that all saved source records still resolve to retained constructor faces. Otherwise `BRANCH_SOURCE_OWNERSHIP` refuses without deleting raw storage. Do not weaken `assertSketchSourcesResolved`, delete unrelated sketches or introduce hidden branch-local source copies. A later source-plane branch extension requires an explicit atomic source-store participant; it is not in this proposal.

Preserve manufacturing/drawing definitions, exact bindings, materials and their independent revision semantics. At prefix navigation they are retained authored metadata; read/export must not treat them as current full-tip facts. Before branch removes an authored producer, detect material bindings and refuse `REFERENCED_MANUFACTURING_OUTPUT` rather than create an envelope that cannot reopen. Before suppression removes an assigned current output, use the same conservative refusal. Unrelated assignments remain byte-identical and require existing real review/rebind when the document revision changes; no automatic reassignment. Existing valid drawing definitions may remain unresolved and must say so through the actual reader, not draw fabricated dimensions. No new metadata transaction is needed for this first conservative policy.

Every requested command is transactional. Capture current document/manager/registry/services, exact source inventory/frames/versions, expressions, material/drawing tokens, accepted models/metrics, counter identity/high-water, operation implementations, history/journal/pointer and current build. Candidate work runs under existing `pipelineTail` / `evaluatePipeline` and candidate owner, with native/solve/hash work in Workers. Prepare journal + definition + pointer + registry/model publication together. No callback between participant writes; only then notify. Notification fault after commit stays committed/Undoable. Stale/cancel/failure closes only its candidate; accepted source, history position, journal/redo, metrics, metadata, counters and file association stay unchanged. Cleanup uncertainty remains latched; no retry with a different engine.

Proposed failure envelope retains the original typed native/source cause and separates `requestedFeatureId`, `originatingFeatureId`/index (whose actual operation refused) and any proven dependency path. Only attach an originating index at the actual caught `runRequest` boundary; do not infer the root cause from the requested edit. A bad hole edit is originating at the hole; a valid smaller base edit followed by a hole outside that base is a downstream hole failure. A preflight dependency refusal is not a failed native solve. The accepted document does not become a saved failed candidate merely because this guarded edit refused. Native Open of independently authored invalid intent retains existing failed-regeneration policy; this proposal does not purge it.
