# E18 modern physical parameters — source checkpoint

This slice extends the existing typed project source, physical dependency Worker,
prepared expression publication, full candidate replay and `physical-transaction`
entry in the single authored journal. It is source-ready, not application-qualified.
No per-step tests, probes, typechecks or builds accompany this checkpoint. The
complete public driver is the next qualification boundary.

## Exact scope

One canonical rectangle created by the ordinary rectangle operation, one explicit
version-3 selected extrusion and source-matched modern centered/four-corner through
holes. The existing project typed definitions remain authoritative. Formula names
may drive the rectangle's actual width/height constraints, selected extrusion
`depth`, and through-hole `diameter`/`offsetX`/`offsetY`. Units are canonical mm.
Definitions form a directed expression dependency graph: this is not a replacement
for the sketcher's simultaneous geometric constraints or a configuration optimizer.

Saved feature fields retain either their original positive numeric literal or a
bounded typed identifier. No solved tools, quantity table, native pointers/ordinals,
new backend marker or second parameter document are saved. The existing exact
engine revision is retained throughout.

`inspect-physical-parameters` adds `selectedRectangles` rows with actual authored
index/feature/source/opaque region/build identities. Eligibility explicitly says
`sourceQualification: requires-worker-validation`; discovery does not certify a
polygon as a rectangle on the main thread.

New public `apply-physical-selected-profile` takes exact
`{revision,index,featureId,width,height,depth,definitions}`. Width/height/depth are
typed names. Source face/region/build come from the actual current authored feature.
Existing `apply-physical-bindings` binds modern hole fields and updates formulas;
empty `changes` edits definitions without inventing a feature. Definitions preserve
the existing source schema and configured-source behavior, with no configuration
selection in this workflow.

## Transaction and ownership

The quantity Worker validates units, undefined dependencies and cycles. It parses
the captured selected rectangle source to qualify/resolve its driving lengths.
The sketch Worker binds and genuinely solves the rectangle. Complete candidate
replay independently reconstructs that captured source twice with the identical
typed source, then uses unchanged semantic profile preparation and numeric native
requests. Only dimension-aware schema fields resolve typed names; each operation
cross-checks its materialized value against the current prepared expression facade.
`captureOwnedHoleIntent`, the private ledger and all native/Worker shape requests
remain numeric-only. Authored capture is separate and proves no geometry.

Prepared expressions, sketch writes, accepted geometry, full-tip ownership and one
existing journal proposal commit through the current publication transaction.
Refusals and no-ops do not adopt parameter sources, journal branches or geometry.
Undo/Redo restores exact saved binding/source intent and replays the same backend.
Numeric edits refuse bound fields instead of erasing a formula. Creation append
Undo remains the existing journal operation and is exercised after undoing bindings.

Heavy formula evaluation, source parsing, solving, digesting, semantic/native work
remain Workers. Existing bounded metadata/history capture, journal charging and
source-byte custody on the coordinator remain existing main-thread work; this slice
does not claim removal or timing qualification of that work.

## Readers and persistence

Native Save persists the existing expression source plus authored name bindings and
the actual source sketch. Open restores the prepared physical result before the
same feature replay. Source-ancestry classification accepts the authored names but
does not reinterpret them as numeric geometry. Numeric history inspectors retain
name fields as metadata and refuse numeric mutation of bound features.

The existing public point query admits only this exact integrated typed history.
It re-evaluates captured source/history with its observation-only owner, classifies
real native points, checks exact accepted native measurements and retires candidate
resources before returning. No accepted handles are borrowed.

**Still OPEN:** typed STEP, protected manufacturing 3MF and linked drawing readers
retain their explicit unsupported guards. The next shared-reader integration must
close this gap; this checkpoint does not claim complete typed manufacturing handoff.
Other generic feature families (box/Boolean/edge treatment/pattern/shell/revolve/
sweep/loft), noncanonical selected polygons, local sketch constants and arbitrary
named sketch fields remain unsupported in typed generic histories. Numeric paths
and retained legacy typed families keep their existing capabilities.

## One complete public qualification

`desktop-driver.mjs` authors all successful geometry through registered commands.
It creates a 100×50 rectangle, selected depth20, centered D10 and four corner D4
holes at offsets8 on a supplied exact staged build. It binds width, height=width/2,
depth=width/5, hole=width/10, corner=hole*0.4, edge=width*0.08; edits width, then
offset and hole formulas. Independent expected native volume/bounds and material/
void points include the old corner location after moving the holes. Actual native
point replies, state and resources are captured before assertions.

The same run covers an earlier literal depth edit, mixed parameter/creation
Undo/Redo, stale revision, no-op, dimension mismatch, undefined dependency, cycle,
invalid placement, bound-field numeric refusal, mm/inch display without physical
change, normal Save/server sync/fresh Open/reedit/resave and a second fresh Open.
Saved files must preserve actual feature/source/opaque region IDs, exact expressions
and binding names. There are no raw successful source seeds or fabricated native
replies, no unrelated-account probes and no deployment.

Run only against a parent-frozen composed runtime. Required environment follows the
ordinary public harness: `CODI_DESKTOP_SOURCE_ROOT`, `CODI_SIGNED_PINS`,
`CODI_EXPECT_SOURCE`, `CODI_EXPECT_DESKTOP`, `CODI_ENGINE_REVISION`, `CODI_TEST_URL`,
`CODI_TEST_CDP`, `PUPPETEER_CORE_PATH` (24.35.0), and fresh `CODI_EVIDENCE`.


Whole-run refusal comparison scope: evaluated candidate failure may refresh the
four recorded opaque inspection tokens (host, physical parameter inspection,
solid inspection and journal inspection). Exact source/history/definitions,
geometry, journal contents/targets, counters, association and resource counts
must remain unchanged. A public Undo/Redo following failed candidates proves
that no hidden authored undo step was inserted. No-op and read-only comparisons
remain exact, including all inspection tokens. Historical failed runs are kept.
