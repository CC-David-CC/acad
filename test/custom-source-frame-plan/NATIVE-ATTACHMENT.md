Source review extension against ACAD32ae. Proposal only; no product edit or execution. This is required for the C08 extruded-parent-depth exercise. Earlier-source-plane attachment in phase A is useful infrastructure but is not a substitute or a completion claim.

## Required saved parent union

Keep phase A source parent form. Add a discriminated Native parent form inside SOURCE_FRAME_V1:

```js
{
  kind:'native-planar-face', engine:'occ', engineRevision,
  bodyId, featureId, selectionId, originFeatureId,
  sourceFeatureId, sourceFaceId, sourceRegionId,
  framePolicy:'extrusion-cap-source-datum-v1'
}
```

The public creation request supplies an inspected revision plus actual `bodyId`, `featureId`, `selectionId`; service infers and corroborates the other immutable source/build fields from genuine current history/selection/Native observation. Public callers cannot provide a claimed plane/frame/cap ordinal as parent authority. The saved expanded record is a locator, not a trusted witness: all fields are revalidated on replay. No analytic plane, native index, handle, matrix, mesh or solved measurement is persisted. Parent is an earlier current result in the authored replay, on the same exact whole-part backend. Source feature is the selected-extrusion constructor; sourceFaceId/sourceRegionId refer to its real retained sketch/selected region, not a generated fake region.

First success domain is an actual selected-extrusion `last-cap` (and optionally `first-cap` only if separately qualified) with a unique current native planar descendant. For descendants, require the complete actual Native lineage to resolve the same opaque origin face uniquely, plus the real constructor source. Descriptor role is authored origin, not proof that a descendant remains planar. A newly generated flat face is not an automatic replacement. Other planar faces may be listed as ineligible with a precise reason; general face-coordinate-system choices are not silently inferred. This finite initial cap policy must include genuine last-cap success, not only refusals.

## Minimal new protected read

Proposed private mount operation:

```js
{op:'solid.face.frame.read',version:1,unit:'millimeter',
 handle,sourceHandle,producerFeatureId,originFeatureId,selectionId,
 framePolicy:'extrusion-cap-source-datum-v1'}
```

Both handles remain private. Worker checks current token/name ownership, exact producing feature and runtime, source-profile identity, real descriptor membership, origin/sourceContext and private `resolveFace(selectionId)`. It then calls the existing `_ReadOwnedTopologyV1` on that SAME owned result, validates the full bounded catalog and selects the resolved actual member privately. Require plane analytic support and ordinary FORWARD/REVERSED orientation; unsupported/internal/external/degenerate/uncertain cases refuse. No Native result allocation, shape mutation or persistent name is needed. Read limits remain1024/512/256 catalog members; return one small frame/fact record, <=4KiB, no catalog/ordinal/native name.

In-plane orientation comes from the real constructor's solved source x/y, not arbitrary Native plane parameterization. Corroborate the cap's actual plane and normal against that source orientation using a separately documented dimensionless direction policy compatible with the existing frame admission. For last-cap use +source.z as the frame normal and preserve source.x/source.y. Native topological orientation is checked separately, not assumed identical to analytic surface normal. Derive the origin by projecting the constructor datum origin along its source normal onto the actual Native plane. This obtains the measured cap position from BRep; do not simply use authored `sourceOrigin+depth*z` as authority. Independently check that measured location matches the current constructor request within the current 50pm small-design placement criterion. Native source/cap boundary analytic checks corroborate identity/finite support as needed, never replace the proven membership with nearest geometry. A frame plane can extend beyond the trimmed cap: the definition is attachment to its supporting planar datum, not a promise that every later sketch point lies inside face material.

Proposed result is a small exact bound record `{version,unit,status,reason,binding,frame,quality}` with binding matching the above producer/origin/selection/source/build fields and quality `native-planar-face-provenance-v1`; unresolved has no frame. Any inconsistent ownership/currentness/protocol is fatal integrity failure, not a fabricated unresolved success. Actual reference loss/split/merge/type change is a typed reference result. There is no public NativeID/caller `trusted:true` flag.

Add private `readCandidateWorkerAttachmentFrame` in solidLedger: validate its real `s.outputs` item/model/producer/build/registry, `s.sources` constructor, actual accepted/candidate operation definitions, positive valid Native facts and unchanged binding before/after executing the read. During regeneration it requires current model-purpose candidate authority and does not publish/accept on its own. During public discovery/repair preview it additionally requires the pool's permanent observation-only authority; use the current shared read evaluator and compare expected accepted metrics where appropriate. A parent edit legitimately changes its new candidate metrics: do not incorrectly demand equality with the old accepted metrics during regeneration. In neither case can a caller switch owner roles or borrow accepted retired handles.

Public discovery adds `inspect-source-frame-attachments` for the actual current part: captured document/geometry/J revisions, exact staged engine, real eligible face descriptors and bounded native frame observations. It is advisory and revision bound; commit redoes the private read in its new candidate. No new raw-buffer or topology public command. Reuse the existing observation pipeline rather than a second replay executor.

## Transaction, failure and explicit repair

The new source producer reads the genuine earlier parent in the fresh candidate ledger before making its independent planar source shell. Worker-only preparation computes all affected source frames from this Native face witness plus the saved local placement. It then updates only `metadata.boundaryFrame` in affected saved sketches and uses the SAME atomic source/model/J publication described in CONTRACT.md. A parent extrusion depth or pose edit must include this Native-dependent closure, not just the phase A source-parent closure. The candidate must create/replay the parent before any attached source frame is observed; evaluation order is preserved. Bound affected sources at64 and chain depth16; no second graph or cache.

Proposed implementation route is ONE model candidate, with a narrow private pre-source-initialization hook. Current `preparation.prepare` runs after replay and is too late: `cadRegistry.setModels` initializes a new source immediately. After the new source operation returns its genuine face/frame but BEFORE registry initialization or any dependent feature, Craft invokes its privately constructed frame-preparation participant. It uses the original captured source bytes plus the actual protected Native frame witness to reconstruct/reframe/independently verify that source in sketch Workers, then installs the bounded returned bytes into an evaluation-private overlay and records the frame witness. `candidateSketchStorage.mjs` needs a new private factory variant exposing an installer only to the Craft closure; operationContext receives ONLY the immutable read interface, never the installer. Reject duplicate/unexpected source installation and any source already read; preserve all existing static-overlay API behavior. A declared affected-source inventory must be completely installed/observed before candidate sealing. Final preparation creates one storage write set and complete J delta from those verified outputs before the existing synchronous publication. No accepted storage write happens during evaluation. This is an explicit additional shared-file ownership dependency requiring root approval. It avoids prefix rebuilds, a duplicate feature executor, a second Native graph, extra simultaneous mounts or an already-acquired observation owner changing role. Public attachment discovery independently uses the existing observation-purpose replay and closes before returning its advisory facts.

Missing parent/output, unavailable ancestry, zero descendants, split, merge, nonplanar type change, source/region mismatch and unsupported cap policy produce distinct `ATTACHMENT_*` reason codes with the original failed producer. Preserve first failure; never silently choose another planar face, flip axes, detach to world or use the prior world frame as if still attached. A failed edit preserves the last accepted source/history/Native state/J; diagnostic binding describes the failed candidate truthfully. Native Open with a malformed/dangling attachment must refuse before adoption, preserving the current healthy document. This does not erase otherwise valid authored failed-feature intent under any existing supported failure-persistence semantics; such compatibility must be reviewed rather than invented by this new service.

Add a separate public `repair-source-frame-attachment` operation: exact current source identity/revision plus an explicitly selected new *eligible actual earlier* parent body/feature/face. Independently read it, preserve all local source placement/geometry and stable source identity, and atomically replace only the saved parent locator plus derived descendant frames through the same J. Normal frame edit cannot erase/retarget the parent. No automatic repair or retry. A target that is itself missing/ambiguous refuses; explicit repair requires a uniquely resolved current alternative. After a parent topology edit is refused for losing a reference, the user may explicitly repair the source onto an existing eligible earlier parent, then retry the original edit. This closes an actual ordinary repair path without publishing a dangling graph or inventing a successful ambiguous case.

Dependents must be inventoried by actual saved Native parent producer as well as source-parent IDs. Deleting/suppressing/reordering the referenced producer must refuse before allocation/publication unless the existing bounded shared operation explicitly supports this new family. Descendant-body consumption is not automatic retargeting: a consumed/missing saved producer fails unless the user explicitly repairs to a genuine current earlier result carrying its verified origin face. Same part/same build throughout.
