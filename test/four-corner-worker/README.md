# Four-corner Worker research

The Worker retains each validated centered-hole result's private profile,
center request and native topology under that Worker's token. The separate
`research-four-corner-cut` operation resolves that exact token, recomputes the
four-corner plan, verifies the record after asynchronous module imports,
constructs four native tools in the same Worker, and runs
`validateFourCornerTopology` before registering a result token. Planner
refusals occur before allocation. Any failure after native-name allocation
terminates the candidate Worker; the four cutter names are additional native
allocations associated with one logical lifetime result. No native pointer is
returned. The existing center-only c397 runtime explicitly refuses the new
native capability and has no fallback.

The Worker can authenticate its private centered-result token, source profile
and center request. The existing centered request does not contain authored
feature IDs: the host ledger must independently bind the echoed parent and
center feature IDs to the candidate before publication. Mount ownership,
publication-time document/session checks, projection, atomic history and
accepted-owner retention are separate contracts.

`prepare-fixture.py` assembles a disposable strict-CSP fixture from the exact
Worker source, reviewed helper modules, separately pinned native research
runtime and packaged sketch inputs. `--variant line-frame` uses 8c incremental
JS `81996d394b9fd2fcd7b02a0448bf7968c2decc04969d2be7ace4512cbfc5620a`
and WASM `0e08888f09c34f79b858cefc2859cbb59fbea1af6505b04686343eac7f9efc5b`;
`--variant centered-only` checks the current clean c397 runtime. The fixture's
`worker-partial.js` is a deliberate test-only fourth-tool displacement; it is
not an emitted application asset. Serve the output with the self-only CSP
fixture server and run the browser tests using `CODI_TEST_URL`, `CODI_TEST_CDP`
and `PUPPETEER_CORE_PATH` pointing to loopback services.

Real Chromium tests passed normal and resized authored rectangles, retained
center wall, expected native volume, typed stale/touching refusals, wrong prism
parent and disposed centered parent, and real partial-cut validation failure
with the Worker target gone before a token can be returned. The c397 runtime
refused the new operation twice with `ENGINE_CAPABILITY_UNAVAILABLE`, without
fallback. Twenty-seven planner/topology/provenance unit controls passed. This
uses an incremental research native build, not the new clean runtime. Production
asset packaging and the embedded-worker source hash must be updated only after
clean native pins and independent review; no desktop deployment is implied.

The same real Worker tests were rerun with the `line-clean` fixture variant,
WASM SHA-256 `13617eda9a2118edfd1244b5d46523e7d9628a87ec995a0237b2b5cc58d532f2`.
This runtime links exact 8c shape-io against a freshly built identical OCCT
source subtree; the clean-library provenance receipt is in the separate CAD
probe branch. This is not a second independent full clean build.
