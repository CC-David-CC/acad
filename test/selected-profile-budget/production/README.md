## Policy and ownership

The controller selects32 only for the existing selectedProfile capability and
retains8 for all other configurations. The Worker selects32 only for existing
nativeOwnership2. Selected owned mode admits the generic selected-profile, box,
Boolean, mesh-read and disposal protocol; it does not expose legacy DRAW
research routes through this mode. Result token reuse cannot replace an owned
input. Name counters remain monotonic; release never replenishes a lifetime
quota. Root's owner/model history remains the single source of authored intent.

The Worker obtains valid native tessellation evidence, then charges each new
native result name once. Profiles, boxes and Booleans all participate, including
intermediates later consumed or disposed. Before publishing an over-budget
result it erases that newly created native name, verifies erasure and returns
typed RESOURCE_LIMIT. Earlier inputs remain owned/readable. Large Float64 and
display-buffer transfer occurs only for a charged result with the same triangle
count. Mesh inspection does not add another charge, and disposal does not refund.
The controller independently charges validated result metadata before issuing a
handle; malformed over-budget peer evidence closes that candidate before handle
publication. Its accounting is cleared on mount shutdown.

This is an admitted unique-result work/display policy. Native construction and
initial tessellation necessarily occur **before** their triangle count is known.
A refused attempt can do native work, and repeated reads can transfer the same
already charged mesh again. This is not a pre-allocation, total-CPU, cumulative
inspection-bandwidth, native-used-memory, JS-heap or OS-RSS bound. Existing
per-request30s deadlines remain. Normal failed candidates close through the
existing owner; the previously accepted generation is retained separately.

## Pure public-cost contract for root integration

`selectedProfileBudget.mjs` exports frozen SELECTED_PROFILE_BUDGET and
`selectedProfileHistoryBudget(history, engineRevision)`. The latter is metadata
only: dense bounded history, own data type/runtime fields; no geometry, callbacks,
source copying, solver, or publication.

- PLANE costs0 for this particular mount.
- Known legacy rectangle, centered/four-corner hole and enclosureV1/V2 feature
  descriptors cost0 here because they use separate pinned mounts. Their count
  is reported as separateMountFeatures, not whole-document native allocation.
- Registered generic selected-profile/box/Boolean descriptors cost1 only for
  `engine:'occ'` and the exact target selected engine revision.
- Another generic engine/build reports compatible:false,
  INCOMPATIBLE_ENGINE_BUILD and explicit incompatibleOperations. Unknown types
  report unsupported estimation. Neither can imply append availability.
- Output includes scope/maxLifetimeNames/maxCumulativeResultTriangles, supported,
  compatible, reason, planned/remainingNativeResults, withinLimit, canAppend,
  separateMountFeatures, unsupportedTypes and incompatibleOperations.

At32, an existing history remains withinLimit while canAppend is false. Readonly
source-region inspection must remain independent from append availability.
Root owns using this contract in public discovery and creation preflight.
