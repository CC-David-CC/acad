# Multi-sketch parameter transaction — candidate, not qualified

The common physical transaction now asks its existing parameter Worker to inventory up to 64 sketch records, at most 1 MiB UTF-8 each and 4 MiB UTF-8 total. These are transaction bounds, not My files limits. A private sequential sketch Worker verifies a captured unconsumed open-plane frame, resolves supported length/diameter names, and solves each affected sketch. Reference-bearing boundaries, unknown history schemas and unsupported named fields refuse. The existing consumed rectangle path remains separate and is deduplicated. The staged candidate read view, one prepared workspace write and one physical journal entry hold the exact changed sketch set; undo/redo validates every source before replay. The existing 8 MiB journal limit applies to both before/after values and may refuse well below the 4 MiB input limit.

A private editor-entry capability only adopts changed saves when full-tip/document/source/key-version/face/history/streams/material checks hold and the explicit history allowlist proves no reference-bearing features. Storage and invalidation of incompatible RAM journal are installed synchronously before observers. Unknown/consumed histories retain the prior save behavior but cannot advance the full-tip baseline. No-op saves preserve source bytes. This is not persistent sketch-edit undo.

At this checkpoint TypeScript, 24 focused parser/inventory/journal/atomic-save/no-op/view controls, real disposable physical Worker inventory and real sketch Worker D12→14 and frame/mismatch controls pass. The editor capability staging unit uses real volatile workspace and a test batch, not a real browser publication. No combined app, signed D0/D14 counterexample, native save/reopen, multi-source integration, cancellation, or existing rectangle regression has yet been qualified. Review is required before any build or promotion. Worker inventory and sketch solve parse data off the UI thread; existing snapshot serialization and journal byte charging still run on the UI thread and need measured performance on large sketches.

## Async validated editor save candidate

`InPlaceSketcher.save()` now returns a Promise. After recovery/frame checks and the exact no-op fast path, a changed source is captured with the active editor epoch/history/intent, document/key/namespace/face/expression guards, and independently solved in a disposable Worker; the Worker validates authored intent, domains, residuals and unchanged geometry before any write. Source edits, replacement, abort, close, busy tools and duplicate Save refuse; the draft and old stored bytes remain. A successful eligible unconsumed save enters the preflighted synchronous workspace+journal publication; other validated legacy saves do not adopt that baseline. Unsupported Worker domains fail closed. `sketchSaveAndExit` and `sketchOpenInTab` await the Promise; actionService returns the original Promise and attaches a non-rethrowing observer for UI event handlers. The shared test helper now returns it. Historical test callers are being migrated independently.

Task-specific client validation was also fixed: the prior WIP's serialized-only `typed-sketch-transaction` response was incorrectly rejected by the generic sketch+evidence validator. A real client→Worker test covers that response, save validation and held Worker cancellation. Disposable Worker controls pass for typed D12, D14 geometry mismatch, angle/zero refusal and frame mismatch. Six focused staged-save/action/guard controls pass. These do not yet prove an actual app editor save, DOM button error reporting, native save/reopen, spline/rectangle support, same-bundle epoch cancellation or the signed D0/D14 counterexamples. No full app build has been run for this candidate.

## Explicit independent feature lineage and no-op race

The generic source/save guard now traces the exact authored worker rectangle → centered hole → four-corner chain using the existing semantic LID/HOLE_WALL identities and their original source face and region, rather than refusing every history containing an unrelated worker plate. Duplicate IDs, malformed semantic identities, wrong/missing parents, unsupported or implicit schemas and related source faces refuse. Legacy pattern operations are not admitted by this new guard. Pure controls cover related/unrelated sources and malformed ancestry; real combined plate+circle qualification is still required. The original consumed rectangle continues through its existing dedicated path.

Duplicate Save is blocked even for the no-op microtask. That fast path still launches no Worker and writes no source, and rechecks editor, document, source key/version, frame, expression revisions and mutation epoch before resolving. Same-bundle real-editor proof is still pending; the ephemeral unit action check cannot replace it.

## Exit receipt follow-up

A successful Save now returns a private receipt. Changed saves verify the exact same active draft after synchronous commit notifications and the action verifies it again immediately before exit; a notification-time or intervening same-viewer edit keeps the editor open and raises `AbortError` with `committed: true` when bytes were already installed. No-op receipts recheck exact strict draft, epoch, source/version, frame and lifetime across the microtask and before exit without claiming a write. Both paths refuse a replacement editor or another pending save. Frame checks reject extra keys. Focused tests simulate same-viewer edits in the publication notification and a no-op microtask; they are not actual browser publication evidence. TypeScript and 21 focused transaction/save controls pass. Real UI reentrancy, native/signed parameter propagation, and carried-feature Worker support remain unqualified.
