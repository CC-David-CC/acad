# Physical quantity research boundary

This version-one data-only request accepts up to 256 named definitions, each with a declared dimension and a bounded expression. Constructors `mm(x)`, `inch(x)`, `rad(x)` and `deg(x)` convert to millimeters and radians; dependencies may be forward references. Addition and subtraction require equal dimensions, while multiplication/division track bounded length and angle exponents; supported published dimensions are scalar, length, area, volume and angle. Counts are bounded nonnegative integers distinct from scalars and booleans are distinct. Unknown references, cycles, incompatible units, unsupported syntax, nonfinite values, unsafe input and resource-limit violations fail with structured error codes. Existing untyped expressions are not reinterpreted.

The candidate facade is a private integration ingredient: it requires a result from the pinned worker and a caller-checked request revision, and refuses generic untyped expression evaluation for typed values. Only dimension-aware consumers may resolve a quantity; canonical radians must never be passed to a degree consumer implicitly. This module alone does not authenticate a caller-supplied worker result, publish a document, change an existing UI, or implement parameter transactions, undo or restore. Those remain dependent on an owner-bound worker client, expression participant, transactional replay and restore adoption. Current sketch-worker scalar table intentionally excludes typed length and angle values.

The versioned source string uses `codi-physical-parameters:1` followed by a newline and a JSON array of definitions, preserving the native v2 envelope's existing expressions string. The project validation Worker recognizes and evaluates this source; the research restore path described below adopts its result through a private, source-bound one-shot capability. Legacy sources remain on the existing parser. Parameter editing and transactional replay are not yet wired, so this is not complete native support.
