Proposed bounded E22 contract — not implemented

One authoritative part definition, linked drawing metadata

Add a versioned `drawings` section to the existing native envelope, outside `project` so drawing layout is not accidentally added to the current geometry digest. Prefer a new envelope version emitted only when drawings are present; continue reading current version2. Guarded older readers must reject unsupported drawing-bearing versions instead of silently discarding drawings. Coordinate the future native.CAD container adapter rather than introducing a second drawing document/file authority now.

One drawing stores: version/unit (`millimeter`), drawingId/title, target `{featureId,operationType,engine,engineRevision,output:'complete-native-result'}`, one source datum `{featureId,faceId,regionId}`, sheet physical mm/scale rational, up to3 view definitions and up to16 dimension definitions. IDs are bounded own-data identities; region/selection IDs are opaque discovered values. The initial target is one current unplaced, measured positive single solid at the authored tip with no unsupported assembly placement. It is a fixed authored producer: it follows edits/replay of that feature, not an unqualified "latest body" search. Consuming/replacing the producer requires explicit reference migration or becomes broken.

Views save viewId, a named source-relative basis (`top`,`front`,`right`), paper placement in mm and visibility policy. Source frame is reconstructed from the actual source, not saved as duplicate solved geometry. Dimension definitions save dimensionId/viewId/type and stable semantic references plus paper-label placement. Save no 2D projected curves, solved measurement values, transient digests, body handles, native/HLR ordinals or renderer positions. A derived cache is disposable and bound to full current source/history/build+metadata revision; it is never authoritative after reopen.

Stable dimension references

1. Source datum dimensions: an explicit source feature/face/opaque region/curve ID plus real endpoint `a` or `b`, or source circle center. Capture in the real solve Worker, corroborate exact membership in the selected feature's solved input and actual constructor witness. Project the resulting datum using the same view transform. Label these as source-datum dimensions; a fillet shortening a visible edge does not silently turn them into that edge's length.
2. Current native edge/face dimensions: use an actual discovered authored selection key and expected geometric type. Resolve only via current private selection index; require a unique descendant and actual native line/circle/plane measurement. Do not persist current native index or rebind by nearest geometry, array order, bounding box, string parsing or equal-looking coordinates.
3. Semantic through-hole diameter/center: use the genuine hole feature/source reference and an explicitly defined hole slot (center first). This requires a NEW authenticated construction/measurement witness that resolves the original semantic hole to the actual final cylinder/axis and demonstrates unique survival through supported later cuts/treatments. Existing private seed witnesses and captured parameters are useful inputs, not sufficient proof of current hole-wall membership. Until qualified, refuse this dimension type; do not present a nominal parameter as a measured final hole diameter. Pattern/corner slots need a separately specified order/causal witness and are outside first centered-hole stage.

Source/feature removal, region replacement, split/merge/deletion, wrong geometry type or unavailable provenance yields explicit broken references. Retain the original reference/first failure; never silently heal by proximity or sourceContexts. Some final holes/silhouettes may remain valid drawing geometry while unavailable as dimension anchors. A broken dimension keeps its definition and reason, shows no current measured value, and blocks "complete manufacturing drawing" export until explicitly repaired or removed.

Heavy read path

Proposed internal native read: `solid.drawing.orthographic.read`, version1/mm, current owned handle + bounded orthonormal projection frame + request-local measurement references already resolved by the owning Worker. Read creates no DBRep result name. A detached native copy, if required for HLR mutation isolation, is operation-local and released before reply. Capture input BRep/catalog/tolerances and name count before/after; validate projection/result budgets without declaring source geometry invalid on projection failure.

Use `HLRBRep_Algo` with nonperspective `HLRAlgo_Projector(gp_Ax2)`, Add, Update, Hide, then explicit visible/hidden sharp/outline filters. No isoparameters initially. Declare smooth/seam policy and coincident-line behavior; do not blindly concatenate all overlapping filter categories. Retain analytic 2D line/circle/ellipse/trimmed-curve parameters, or bounded exact spline poles/knots/weights where qualified. Unsupported output curves fail the view explicitly; an optional tessellated preview must be labeled approximate and cannot supply dimensions. Native HLR segmentation/silhouette ordinals remain response-local. New projection-local fragment IDs are regenerated and never saved as model references.

Worker returns strict bounded own-data: exact source/build/request binding, view basis, visible/hidden curve sets, measured dimension records or typed broken-reference records, explicit quality `native-brep-orthographic`, tolerance policy and projection diagnostics. Canonical model/measurement values are mm/radians; paper coordinates are distinct mm-on-sheet. Curve categories, fragment multiplicity and same source edge's hidden/visible intervals are retained. A rendered SVG/Canvas/PDF is a consumer of this record, not the geometric authority.

Shared service proposal: `inspectLinkedDrawings()`, `createLinkedDrawing({revision,...definition})`, `editLinkedDrawing({revision,drawingId,...boundedPatch})`, `refreshLinkedDrawing({revision,drawingId})`, and inspect/read current records. These are proposed names, not advertised commands. Creation/edit/removal use the existing shared authored transaction/journal; dimension values are read-only derived facts. Refresh is read-only with respect to part history/counters/epoch, and atomically replaces only the matching derived drawing cache after native cleanup. Agent and human operations invoke the same service/submit/currentness boundaries.

Extend the existing exclusive read-only Craft pipeline seam to a typed observer instead of duplicating evaluatePipeline. Capture complete history, source bytes/frames, expressions, model IDs, requested producer/build, metadata and authoritative documentSignal. Reconstruct in temporary owned Workers, resolve the exact requested producer/output/build, corroborate accepted native measured facts against the reconstructed candidate as the existing point observer does, compute HLR/measurement inside its owner, close resources and restore ID context before returning. No fallback to accepted dead handles, display mesh or a live mutable sketch. Check source/document/account/window/current revision before each async phase and final installation. Close/cancel/late replies dispose candidates; uncertain cleanup fences further work through the established cleanup latch. Read queries consume0 persistent result names, but replay/native-copy/HLR transient work still needs explicit resource admission.

On upstream model publication mark related drawing records stale immediately; never label the old value current during asynchronous refresh. A successful refresh binds the new model revision. A truthful failure preserves the last valid part and saved drawing definitions, with stale/broken drawing status. Model edit Undo/Redo must restore the corresponding definitions and permit deterministic refresh; drawing metadata edit Undo/Redo uses the same user-visible chronology. Do not add an independent history or a synchronized generation flag when currentness can derive from existing document/source/history tokens.

Initial proposed admission ceilings (must be measured before promotion): one drawing/one native solid,3 views,16 dimensions, current256-feature shared history bound, existing32 cumulative native-result budget, source512edges/256faces,≤8192 output curve fragments/≤65536 spline scalars/≤4MiB UTF-8 reply, bounded60s read job and one queued observer. These are workload/transfer caps, not a hard HLR WASM-used-memory guarantee. Native expansion may hit an internal resource limit before reply serialization; budget this explicitly. No silent source/history truncation, changing default limits or per-feature backend switching. Initial native-constant source support may refuse typed bindings; typed dimensions remain a later explicit qualification, not nominal support.

Failures and publication

Transport/data: `INVALID_REQUEST`, `RESOURCE_LIMIT`; lifetime: `AbortError`/stale document or `BUSY`; backend: `ENGINE_REVISION_MISMATCH`, `ENGINE_CAPABILITY_UNAVAILABLE`; target: `UNSUPPORTED_TARGET`, `UNSUPPORTED_HISTORY`, `UNSUPPORTED_PARAMETERS`; reference: `DRAWING_REFERENCE_MISSING`, `_AMBIGUOUS`, `_DELETED`, `_TYPE_CHANGED`, `_SOURCE_CHANGED`; native: `DRAWING_PROJECTION_FAILED`, `DRAWING_CURVE_UNSUPPORTED`, `DRAWING_NUMERIC_RANGE`; ownership: existing `ENGINE_CLEANUP_FAILED`/evaluation-context failure. Exact proposed codes require root approval. Broken-reference observations are data within an otherwise valid drawing read, not fake overall success/part invalidity. Unexpected malformed native envelopes are terminal integrity failures. Ordinary native exceptions/resource failures never substitute zero/old measurement as current.
