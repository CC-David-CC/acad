# Pure source-bound through-hole layout

Base CAD `3451730e56c8fb604213eeba86e4a8f8e135f32e`. Ownership is only new `modules/engine/mount/ownedThroughHolePlan.mjs` and this directory. Implements agreed `test/mechanical-profile-app-integration/THROUGH-HOLES-NEXT.md`; no native, Worker transport/controller, ledger, registry, model or UI changes.

`planOwnedThroughHoles({request,sourceProfile,targetMetrics})` captures own plain data, uses `captureOwnedHoleIntent` and qualified V3 polygon preparation, and requires a single exactly source-local axis-aligned four-segment rectangle without source holes. World rotation/translation is supported through the current qualified orthonormal frame. Source-region identity must match exactly; no encoded identity is parsed. The source face/feature/handle relationship is deliberately not inferred here.

Target metrics are exactly the five-field `InspectOwnedSolidV2` shape: `{version:2,valid:true,solidCount:1,nativeVolume,nativeBounds}` with positive finite volume and positive native AABB extents. It never uses display bounds or substitutes source depth for the target extent. All eight native AABB corners are projected relative to the current source origin along its qualified z axis. `axialSpan` retains the RAW min/max projection. Derived tool origin is shifted to min−1 mm, tool depth is max−min+2 mm; a representable endpoint check confirms that the actual additions cross both extremes. Every ephemeral circle request is revalidated against the qualified V3 construction domain.

Exact frozen result: `{version:1,sourceRegionId,centersLocal,radius,toolProfiles,expectedRemovedVolume,axialSpan:{min,max},scope:'rectangle-source-native-aabb-through'}`. Centers are 2D tuples in source-local coordinates. Deterministic internal labels are `derived-through-hole:<featureId>:center` or the four `MIN_X_MIN_Y`, `MAX_X_MIN_Y`, `MAX_X_MAX_Y`, `MIN_X_MAX_Y` anchors; curve IDs append `:circle`. These are derived construction labels, **never authored source contexts or a second model**. Output tool depth/coordinates remain ephemeral and are not added to saved authored intent.

Placement uses the existing qualified polygon relationship clearance, **0.0001 mm**. Touching/exterior/insufficient-clearance placements return `HOLE_OUTSIDE_PROFILE`; current four-tool pairs must be strictly separated or return `HOLES_OVERLAP`. Offsets retain their authored anchors even when rows/columns reverse. H15 with offset10/radius2 is accepted; H12 tangent placement refuses. A domain refusal does not claim that no mathematical geometry exists.

Expected removal is exactly `count*pi*r²*sourceProfile.depth`, **not** tool span or inferred target volume. The planner cannot prove target ancestry, source face/feature linkage, existing bores or remaining material. It checks pairwise overlap among the current four tools only; overlap with earlier target cuts and the supported prismatic material case belong to runtime before/after removal verification. A positive target volume alone is not material proof.

Malformed input uses `INVALID_REQUEST`; region mismatch `STALE_SOURCE`; unsupported source/frame `UNSUPPORTED_PROFILE`; unsupported measured target `UNSUPPORTED_TARGET`; unrepresentable/out-of-domain tool `TOOL_DOMAIN`; bounded capture excess `RESOURCE_LIMIT`. Capture caps actual UTF-8 input at 524288 bytes, depth24/nodes131072/arrays4096/record keys32/text16384 units, without invoking getters/toJSON. Authoring/source/tool field bounds remain those of the qualified parsers. Required ±1 mm tools may refuse even when the source itself sits at a V3 coordinate/depth boundary; no bound is silently widened.

These are mathematical fixtures and native-inspector-shaped metric data, not actual native observations or public authoring.
