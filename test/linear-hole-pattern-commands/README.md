# Shared linear through-hole pattern commands and history

This candidate connects the component-qualified `solid.holes.pattern.linear`
operation to the ordinary Craft service, authored edit journal and append undo.
It does not establish an actual browser, signed host, native Save/Open or
full integrated Gate1 result. Those require the next source-matched app build.

`inspectWorkerLinearHolePatterns()` reads only private ledger-owned successful
hole witnesses. An advertised seed must be a genuine centered-through feature
on the current target's qualified constructor→holes/edge-treatment path. A
consumed seed's geometry need not remain live. `sourceContexts`, coordinates,
body appearance and caller metadata cannot supply a witness. Discovery's
`canCreate` means request admission with minimum cost2; rectangular geometry,
layout and result validity remain Worker-validated. Read-only discovery remains
available when capacity is full.

`createWorkerLinearHolePattern` accepts exactly
`{revision,version:1,unit:'millimeter',engine:'occ',engineRevision,bodyId,
seedFeatureId,axis:'source-local-x-positive',count,spacing}`.
Count includes the seed. Counts2–17 are syntactically supported, subject to
full-part capacity `2*(count-1)` and native placement/material checks. Count1
refuses before ID allocation because an owned identity result is unqualified.
The facade captures all scalar fields, authenticated witness/source identities,
exact source bytes/frame/version, runtime, services, streams and caller/document
lifetime. The shared evaluator owns replay, native handles and publication.
Receipts contain semantic IDs/count/spacing, measured runtime and charged cost;
no tool geometry, handles or local topology indices are saved or returned.

`inspectWorkerLinearHolePatternHistory` and
`editWorkerLinearHolePattern({revision,index,featureId,count,spacing})` use the
same authored transaction as edge/through-hole edits. Only count/spacing change.
The seed, target, producer, axis, engine/build, units and feature identity remain
exact. No-op edits add no journal entry. The journal kind is `linear-hole-pattern`;
creation uses the existing `operation-append` delta with an explicit two-operation
allowlist (edge treatment and pattern). `travel-authored-edit` supplies undo/redo.
Edits preflight complete replacement-history native cost before delegation.
Typed/project-expression bindings remain unsupported explicitly.

The reference-only unconsumed-sketch classifier now recognizes this exact known
path. Dependent source edits still require full replay; unrelated sketches can
retain their fast-save path. Booleans and pattern outputs deliberately do not
propagate centered-seed eligibility. Stored intent references the original seed
and current target, so source/depth and seed-diameter replay can regenerate
copies without changing the pattern definition. The pure serialization control
only proves semantic capture/reload, not native file persistence.

Reproduce from repo root with Node24 and installed TypeScript:

```
node --test test/linear-hole-pattern-commands/coordinator.test.cjs
node --test test/linear-hole-pattern-commands/{journal,history,craft-source}.test.mjs
node node_modules/typescript/bin/tsc --noEmit
```

Custody tests use explicit model/publication doubles and real parser, catalog,
budget, shared source/currentness guards. Pure journal/history tests use real
bounded capture and chronology. AST checks verify wiring/write boundaries, not
application execution. Retained controls and exact source hashes are recorded
in `evidence/receipt.json`. No default, binary, solver, Worker or native geometry
implementation changed in this phase.
