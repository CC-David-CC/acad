# Full-app centered-hole history fixture

On source `be1aceb1` (including the history-factory and modeler-registration changes cherry-picked as `715cd037`, `6fef49b3`, `d1fd1f15`), a rebuilt full JSketcher application passed `history-browser.test.cjs` in real Chromium. The application uses its real craft service, sketch editor, model registry, project snapshot and dedicated sketch/semantic/OCC workers. This is an isolated test fixture with a test host lifetime and the incremental research OCC runtime; it is not the pinned release runtime or a deployed WebOS integration.

The test creates a 100×50×20 mm prism and separate centered diameter-10 through-hole via the craft API, with history `PLANE`, `WORKER_RECTANGLE_EXTRUDE_V1`, `WORKER_CENTERED_THROUGH_HOLE_V1`. It opens the actual sketch editor and changes the two dimension constraints to 150 and 30 using browser interactions, replays the hole at center (75,15), then edits parent extrusion depth to 35. It checks 7/15/10 model counts, bounds and both circular rim points, undo to the six-face prism, redo, rejection of a diameter-100 edit of the existing hole without changing history, and repair by replaying the original 10 mm hole. A new browser page restores the native project snapshot and verifies operations, bounds and rim locations; the snapshot contains no mount ID, worker URL or worker-geometry object. A separate visible wizard is opened using the application's test helper, with parameters set through the wizard context, and commits the same history operation. This is not a physical pointer-only wizard test, signed My files integration, manufactured solid validation, or proof of broader geometry/engine support.

A preceding negative test incorrectly attempted a second hole on the already-drilled parent and got `The selected parent has changed`; that did not test oversized diameter. The final test edits the original hole in history and receives `Profile request was refused`, preserving the authored history and allowing the previous valid hole to replay.
