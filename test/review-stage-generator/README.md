# Stage and generator admission research

At 17d62200e, `assertSemantics` refuses multiple stages and any serialized generator before the headless solver. `IO._loadSketch` does restore stages, each object's stage, constraints, and generator references; `SketchGenerator.read` resolves Mirror's selection and generated-object IDs against the same object index. Mirror is the sole registered serialized generator. Its `regenerate` changes the existing generated objects after its owning stage solves; output IDs persist. `solveSketch` currently calls the underlying solver directly, bypassing `SolveStage.solve()` and hence generator regeneration. Simply removing the refusal can silently accept stale generated geometry. Later stage systems treat objects from other stages as external; correct admission must verify stage ownership, ordering, generated IDs, dependencies and all retained constraint residuals after the last change, including prior stages.

Offset is a tool, despite its menu's `Generator` label. It creates ordinary Segment/Arc objects, Parallel/P2LDistanceSigned/RadiusOffset and coincidence relations, and an `OFFSETn` sketch constant; it is not a serialized generator. Existing offset tests include unimplemented cases, and this investigation has not established the baseline tool's complete UI/Save behavior. It must be qualified independently before changing the carried-support claim.

The committed fixture is an actual rectangle created with `createRectangleSketch`, opened in the editor, passed to the registered `Mirror` action with the real `rect-0` reflection line and `rect-2` source, then given a second stage through `newStage()` and serialized by strict IO. Fixture capture used the earlier b4 direct test app at port 20462, not a signed application. It establishes real source shape, not successful native persistence or interactive acceptance. The Worker control makes two copies, removing Mirror for the multi-stage case and removing the second stage for the Mirror case; it adds an empty boundary because strict editor serialization in this capture omits a face boundary. Reuse actual stage execution in the Worker and compare intended identities and generator records exactly; recheck every accepted relation and fixed earlier-stage/boundary geometry after regeneration. Reject unknown generators, same-stage cyclic references, unsupported shape mirror implementations and ambiguous ownership. Validate two-stage and dependent Mirror edits, corrupted mappings, stale outputs and failed solver/atomic no-write with real Worker and actual editor sources before widening admission.
