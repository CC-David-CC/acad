## Ownership, Save and costs

One codec owner is bound to one actual document signal. It owns one previous archive and at most one pending output. Protocol sequences/credit order are exact; terminal protocol/codec failures discard that owner's reuse state. Cancellation terminates only this codec; it does not revoke accepted geometry or assert immediate OS memory reclamation. A thrown terminate/cleanup failure is latched/fenced, not reported as healthy release. The host retains its source lease until codec shutdown is established.

The existing host DocumentOperations, scoped settlement, file128MiB/account limits, version CAS, local-write linearization, committed/unknown outcomes and same-file version checks remain authoritative. `.cad` is the default only when the actual compiled PM archive API is present; historical JSON stays an explicit suffix/path, with no automatic conversion. Archive decoding never substitutes for real model regeneration. A failed Open does not adopt its hidden frame. Successful Open retains the verified source lease; detach closes its codec before releasing backing ownership.

A committed Save reacquires the actual verified file generation and the Worker compares its full bytes against its issued output hash before rebasing its private span records. Only then is the previous host lease released. Rebase failure drops reuse; it never rolls back or retries a committed file write. A normal preparation release discards only pending output. No plain caller hash or `trusted:true` flag grants compressed reuse. Optional derived records may only come from that same prior verified archive owner, remain opaque/non-authoritative, and are retained or missing-discarded explicitly. No automatic public cache producer is implemented.

Receipt accounting: `changedEncodedBytes` is changed-entry uncompressed UTF-8 input to content SHA/compression, excluding manifest; `reusedCompressedBytes` is actual compressed-span pass-through; encode `archiveVerificationBytes` is the complete prepared-output SHA scan. Decode uses that field for decompressed manifest/entry CRC+SHA-verified bytes. `archiveRebaseVerificationBytes` separately reports the complete committed-generation comparison scan. **Files still performs its own complete outer integrity/delta scans.** This is not zero-total-hashing, zero-I/O or an observed network saving. Actual delta literal/copy/network and peak/long-task measurements remain root whole-workflow work.

ARC23 remains: existing snapshot/dirty baseline comparisons still serialize authored JSON on main. New Save does not introduce a second archive encoding there; the baseline is independent of container/cache bytes. Cooperative source traversal and restored metadata hydration are still main-thread work and are not claimed zero-cost. Nonempty surfacing/cooperative source responsiveness,128MiB capacity, automatic derived-cache acceleration and physical devices remain unqualified until measured. Session Undo journal remains session-scoped; source definitions and counters persist.
