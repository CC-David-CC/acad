# Worker B-spline render projection

This candidate extends the existing detached Worker projector. For supported nonrational native B-splines it calls the existing `BSpline.bsplineToBezierSegments_full` and `BSpline.getPoint` methods on a private data receiver. No `BSpline`/Shape constructor, viewer, parametric manager, global ID allocation or solver state is created by the projector. It retains the complete exact native source, object ID, role and stage. Subpoint handles remain empty; editable spline controls are not implemented here.

`geometry` is `{kind:'polyline',points:[{x,y},...],approximation:'bounded-bezier-chord-v1',tolerance:0.01}`. Existing Bezier extraction is checked against the existing basis evaluator at degree+1 interior points per span. Adaptive de Casteljau subdivision checks every control point's distance to the finite chord segment, including coincident endpoints; by convexity, each converted Bezier span lies within 0.01 mm of its accepted chord in exact arithmetic. Bounds expand that polyline by the tolerance. Floating-point conversion and finite sampling checks are not a formal global error certificate for the original B-spline; this is a display approximation, not manufacturing accuracy.

The existing native spline policy limits degree to 1–5 and controls to 64, validates finite knots and identity, and rejects weights. Positive knot gaps at or below `1e-12`, mismatch/invalid converted coverage and nonfinite calculations are explicitly unsupported. Each spline has a 4,096-point, 16,384-subdivision and depth-24 cap; the sketch has an 8,192-point and 250,000-work-unit cap. Limit exhaustion returns an unsupported record rather than a partial polyline. These are projection limits, not new native sketch limits. A Worker client must still enforce the source/revision/lifetime guard and terminate the actual Worker on cancellation; this synchronous calculation does not itself receive a signal. The receiving owner and Canvas must explicitly implement and validate this new geometry kind before use.

Strict-CSP actual Chromium Worker test used genuine existing spline evaluator and two previously saved native records, plus loop, cusp, repeated knot, linear, quadratic and closed controls. Each was sampled at 2,001 parameters against the projected polyline; maximum observed error was 0.007407 mm. It also checked exact stored source and IDs/role, finite conservative bounds, unsupported weighted/degenerate/tiny-span cases, no global ID allocation, a 900-spline cap control (31 supported / 869 explicitly limited), and terminating a genuinely started heavy Worker before its result. These finite samples are evidence, not proof for all splines.
