# Named configuration source — research checkpoint

Version 2 is `codi-physical-parameters:2\n` followed by an object with exactly `version: 2`, `definitions`, `configurations`, and `activeId`. The definitions remain the sole base parameter definitions. A configuration has a stable bounded `id`, display `name`, and sparse `{name, expression}` overrides. `activeId: null` selects the base. Overrides change formulae only, never dimensions or model/history copies. The current implementation allows 256 definitions, 32 configurations and 64 overrides per configuration. The entire encoded source is limited to 65,536 UTF-8 bytes and characters; the capture budget is conservative and can reject inputs below that limit. Arrays must be dense and records own enumerable data fields only.

The physical-parameter Worker validates the base and every effective configuration, including inactive formula dependencies, cycles and units; it returns only the selected effective quantities. Geometric validity is evaluated only by the later selected candidate replay. The sketch and project-validation Workers use the same evaluator. Version 1 remains supported. Switching never rewrites base formulae or accumulates overrides.

This is a research checkpoint, not a supported authored feature or a release-ready format. A follow-up routes structured configuration changes through the existing private transaction and preserves v2 on ordinary definition edits; that integration has not yet been qualified in a real app. The UI and desktop agent adapter do not yet expose configurations. Save/reopen, geometry replay, journal/undo, source-bound lifetime, public UI and agent actions remain unqualified. The dependent-sketch Worker from the parallel typed-editor branch must also use the shared evaluator when merged. No source migration or configuration history persistence is claimed.
