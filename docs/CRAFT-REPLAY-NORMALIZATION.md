# New craft requests and replay

A new `craftService.modify` or `modifyInHistoryAndStep` request is detached and checked for JSON-safe values before the first operation run. It is passed through the same schema field-fill used when project history is reopened. A missing optional CAD boolean modifier is authored explicitly as `NONE` with the schema's simplify default and empty targets; explicit kinds, target IDs and simplify choices are retained. The exact normalized request becomes the authored history entry used by private candidate replay. Old project files are not migrated by this change.

The request copy rejects non-finite numbers, unsupported values, cycles, accessors, sparse arrays, non-plain objects and malformed recognized boolean modifiers. It has a bounded 20,000-node / 64-depth / 1,048,576-character validation budget. This is a synchronous request guard; it is not a heavy general file processor. Input objects are copied synchronously so later caller edits cannot change an accepted request. Schema resolution still validates entity references before the operation is accepted.

`test/webos/craft-replay-omitted-boolean-negative.cjs` is the original independent failure control. It failed on parent 794 because an omitted boolean became an empty object on load; it passes on this candidate. `test/webos/craft-request-replay-browser.test.cjs` checks omitted versus explicit NONE, independent input copying, invalid request rejection, preserved datum ID, and exact geometry/history through worker-backed reopen. Standard primitive wizard and sketch/extrude snapshot tests also pass. This does not claim every operation or every nested optional schema is qualified.

A direct caller's positive safe-integer feature ID is claimed in the project counter before the operation runs; IDs already present anywhere in the history, including the rewound future, are rejected. Consumed IDs cannot be reused even after deletion and reopen; preallocated wizard IDs can be claimed once. Outstanding reservations are cleared on project load, released when a wizard is canceled or replaced, and capped at 256; evicted reservations remain skipped. A history replacement must retain the replaced entry's ID. Concurrent mutations are rejected while an operation or pipeline is active; legacy kernel evaluation is serialized. Failed operations can leave skipped internal IDs; no feature is published under those skipped IDs. Tests cover a direct ID 1 followed by allocator use, duplicate rejection, history editing, future-history conflicts, and simultaneous calls. This does not change feature IDs in existing saved files.
