## Correct timing and parameter authority

`AlgNumSystem.evaluatePolynomials()` already eliminates fixed parameters and substitutes affine aliases. `Isolation` constructs residuals from those **actual reduced polynomials**; `beingSolvedParams` comes from their SolverParam dependencies, then `prepare()` can filter constants via `wrapConstants`. Only the numerical system's actual nonconstant `system.params` are writable free variables for initialization. Original `constraint.params` is not proof of freedom: it can include eliminated locks or aliases absent from the numerical system.

Current `Isolation.solve()` first calls each schema's `initialGuess()` on original object Params, then overwrites SolverParam values from each `objectParam.get()`, runs the numerical solver and copies solved values back. After all isolations, the enclosing system restores eliminated values and materializes substitution order in reverse. A naive DistancePP schema initialGuess that writes all original point coordinates can therefore violate locks or have aliases immediately overwritten.

Conversely a SolverParam-only seed inserted after object→solver copying is fragile: existing failed-dogleg fallback calls `System.rollback()`, whose `SolverParam.rollback()` resets from `objectParam.get()`, discarding that seed before LM. Do not fix this by inventing a second fallback or changing rollback globally.

**Proposed seam:** an isolated DistancePP initializer after existing legacy schema guesses, immediately **before** free object→SolverParam copying. Compute from captured reduced polynomials/current free-object values; write only actual chosen free representative `objectParam` values. The existing copy and ordinary dogleg/LM fallback then share the same starting point. Existing outer admission/transaction snapshots own failure restoration. No eliminated/aliased original field is written directly, no accepted model mutation is published, and normal post-solve substitution remains the only reconstruction of derived parameters. Legacy non-DistancePP guess behavior is unchanged.

## Smallest defensible deterministic initializer

Its private input is actual isolation polynomials, `polyToConstr` membership, numerical system free SolverParams and current values; no caller-selected coordinates, public seed flag or saved initialization metadata.

Unrelated components and already eliminated linear locks may exist. This is **initializer eligibility**, not a new public admission refusal: other coupled/nonlinear cases still run the existing solver and remain honestly unqualified for this escape. Endpoints on nonlinear entities may require further branch/domain reasoning; no silent rejection of their otherwise ordinary noncoincident path.
3. Read the actual reduced polynomial using current values of actual free representatives. Require finite negative residual C and an exactly zero reduced gradient at this start, without a broad near-zero epsilon. This identifies the stationary interior seed; it is not a rank/DOF/feasibility certificate. Skip if reduction provenance indicates discarded nonzero terms (`usedApproximateReduction`) rather than pretending an exact escape follows a modified row.
4. Scan actual participating free representatives in deterministic source-derived order: direct surviving B.x, B.y, A.x, A.y first, then remaining actual free representatives in canonical numerical-system order. The latter handles a coordinate expressed through a real affine alias. Never use debug/UUID ordering, proximity or arbitrary user direction. Check membership in actual `numericalSolver.system.params`, nonconstant status, and absence from eliminated/substituted representative keys; bound the scan by the existing isolation/input limits. A point can be free only through another representative; its old object value alone is not authority.
5. For each candidate **without mutating state**, extract exact-in-structure univariate restriction of the actual reduced degree<=2 polynomial along that one representative: `r(z+delta)=A*delta²+B*delta+C`. Coefficients come from existing monomials/known integer power functions and captured values, not finite-difference sampling. Reject unsupported monomials/degree/nonfinite/underflow cases for initialization. The stationary condition requires B=0; seek A>0, finite `-C/A>0` and finite representable `delta=sqrt(-C/A)`. Choose the first in-domain representable positive displacement; no epsilon jitter, iterative search or hidden clipping.
6. Apply **one** selected seed to that representative before the normal free-value copy; leave other free values unchanged. If no candidate is eligible, do nothing and retain ordinary solver/refusal behavior. No repeated reseeding during dogleg/LM, no alternate-branch retry loop and no residual/tolerance change. DistancePP itself has no directed branch intent; the deterministic seed branch becomes actual solved geometry, not a new persisted branch flag. Every retained original equation/domain must still pass after the same ordinary solve.
7. Do not return success from the initializer. Native solve status, original-equation radial residuals, actual admission classification, exact intent/unrelated geometry, independent request verification, physical replay bound and lifecycle/publication guards remain decisive. A numerically usable seed can fail the complete system; preserve that real failure and do not call it infeasible without independent evidence.

For the free coincident fixture the direct B.x representative is available: A=1,C=-1 gives delta=1, yielding A=(0,0),B=(1,0) as a starting point and leaving the unrelated Point exact. If B.x is fixed but B.y free, B.y is selected. If the only freedom is an affine representative with scale k, A includes k², so the requested target rather than an arbitrary world-coordinate nudge determines displacement. If both coordinates of both points are locked or q is forced equal to p by aliases, the reduced separation row is a nonzero constant for d>0; it exposes no movable representative and **must refuse**, not unlock or split identities.

The square root and binary arithmetic still round. This proposal does not claim real-exact roots, 1 pm geometric accuracy, a new normalized precision backend or universal nonlinear convergence. Original-equation accuracy requirements are unchanged. Proper compensated/normalized precision work remains separate.
