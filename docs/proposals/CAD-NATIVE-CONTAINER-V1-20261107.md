## Decision and boundaries

Implement one versioned native container around the **same** authored project. Keep current feature/sketch schemas, IDs, ordered history, quantities/units, counters, materials, display preferences, surfacing and drawing definitions. Reconstruct the existing internal envelope in a Worker and call its existing `preflight`; the container is not a second design document or new evaluator. No Native-handle serialization, foreign-format import, Files rewrite, legacy migration, new dialog or separate agent route. Native Save/Open remain explicit user operations, with current shared lifetime/write-outcome guards.

The first packet comprises codec+source bridge+host integration as one coherent workflow. It does not introduce an automatic geometry-cache generator. Optional derived entries are discardable or retained as opaque verified bytes; using a cache for rendering/manufacturing needs its existing real source/build/quality verification, not just a hash in the archive.

## Concrete v1 on-disk contract

ZIP32, single disk, unencrypted, deterministic known writer profile. Recognition requires the supported `manifest.json` marker/version, not the filename or generic PK signature. `.cad` is the normal Save/Open extension. No executable/plugin entries, filesystem extraction or credentials. Reject unsupported methods, duplicate/ambiguous paths, directory/file aliases, inconsistent local/central metadata, overlapping ranges and undeclared required entries before adoption.

Manifest exact top-level proposal:

```
{format:'codi-cad-project',version:1,unit:'millimeter',
 envelopeVersion:2|3,designRevision:<authored-root-SHA256>,
 writerProfile:'zip32-zipjs224-json6-binary-store-v1',
 entries:[{path,role,logicalId,bytes,sha256,required,encoding,attribution}]}
```

`logicalId` is the original opaque source identity or a fixed role identifier, never a topology ordinal. Each role has an exact discriminated descriptor; absent optional fields are absent rather than arbitrary extras. `attribution` is null for authored entries; a derived descriptor can identify its source root, exact engine/build, producer/format and quality profile. It is **not** an authority flag. The root hashes the ordered authored descriptor set plus format/unit/envelope version; derived entries and ZIP timestamps do not define the authored document revision. No self-hash loop in the manifest.

Required authored entries: `authored/model.json` (complete current model including history, expressions and counters); one `authored/sketches/<SHA256-of-canonical-JSON-string-ID>.json` per sketch, with manifest's exact original ID mapping; optional authored `surfacing.json`, `manufacturing.json`, `presentation.json`, `drawings.json` only as present in the current envelope. Drawings remain definitions, not projected output. Preserve array order, source ID spelling, formulas/annotations, unresolved-but-valid drawing references and all current typed/material domains. Do not infer identities from the entry filename. Hash-based paths are container addressing only. Hash the encoded JSON string identity without Unicode normalization, so even escaped source code units are not silently replaced or merged.

Sketch entries store exact accepted raw sketch text where the source store supplies it; parsing/validation is Worker-only and the corresponding restored raw storage bytes are retained. Other authored JSON uses one fixed Worker canonical encoding; it never sorts semantically ordered arrays. Manufacturing metadata is prepared through the existing verified save path. Unit is canonical millimeter; inch display preference remains a separate authored presentation field and never rescales history/source.

Optional binary entries: `derived/<SHA256>.bin`, scoped manifest descriptors and independent content hashes. Missing/unsupported/stale optional entries cannot prevent opening the authored design; corruption of bytes actually declared present is an explicit integrity error, not a source override. A present optional entry is never adopted as an owned kernel shape or a trusted manufacturing mesh merely because its digest matches. Retain-or-drop behavior is explicit and bounded. No new cache ABI or automatic cache producer is needed to deliver editable `.cad` first.

Proposed limits: outer file/output128MiB; aggregate declared/decompressed content128MiB; current native tree/history/sketch limits unchanged; at most10032 entries (10000 sketches plus bounded metadata/derived roster); manifest and central-directory/name accounting each8MiB; names128 ASCII bytes within fixed prefixes; at most16 optional derived entries. All constraints apply together: a resource refusal is not invalid CAD geometry. No quota increase: existing128MiB user file,1GiB per-account budget and trusted package inventory ceiling remain unchanged. Limits do not imply a fixed JS heap footprint; measure actual peak and ownership on the complete workflows.

Writer metadata is fixed:1980-01-01 DOS timestamp, no comments/UID/GID/NTFS/extended timestamps, fixed UTF-8 flags and attributes, serial entry writes, no randomized values or current-time field. JSON entries use the pinned deterministic deflate profile; already encoded binary entries use STORE. Explicit options must prevent codec substitution. Pin streaming options as part of that profile: `zip64:false`, `bufferedWrite:false`, signed32-bit `dataDescriptor:true`/`dataDescriptorSignature:true`, `extendedTimestamp:false`, `useWebWorkers:false`, `useCompressionStream:false`; JSON level6 and binary level0. Reader checks descriptor/local/central agreement. This avoids relying on a whole-entry buffering default. Same content/profile gives the same bytes. Pin the actual library/build recipe; do not assume CompressionStream output is cross-version deterministic.

## Layout and exact unchanged-entry reuse

Place sorted content-addressed derived entries **before** authored entries; put the manifest and central directory at the end. A small authored edit then does not relocate unchanged large binary payloads. Rebuild only changed authored local records, the small manifest and directory. The directory may change offsets; cached data itself does not. No append-only dead-entry log, duplicate current filenames, unbounded archive growth or history-dependent serialization.

A private codec owner issues reuse records only after it encoded an entry or validated its local/central metadata, CRC, uncompressed SHA and role/reference binding while opening the exact immutable leased source. Record compressed span/encoding/CRC/sizes plus uncompressed content identity in Worker-owned state. Reuse requires the same owned immutable source/entry record and unchanged current authored component identity where applicable. A JSON hash supplied by a caller, a ZIP central-directory checksum, or a persisted `sourcePreserved` flag never authorizes reuse.

Use the library's compressed pass-through/entry-copy support with its complete metadata contract, or direct Blob slices of validated canonical local records where appropriate. Do not forward only method/size and silently corrupt copied records. Unchanged compressed entries need no archive-level decompression, content rehash or recompression. New/untrusted Open validates them once. Reopened files never receive a zero-validation fast path from saved manifest claims. If ownership/currentness is unavailable, validate afresh or omit the optional entry; never guess that a similarly named Blob is unchanged.

At most one previous archive lease and one pending output per frame. After a committed Save, rebase the codec's private span table to the newly committed **verified** snapshot before dropping the older lease. Release the previous generation only after output capture has finished and the new backing is independently owned; do not retain a chain of historical archive leases across saves. Frame disposal/account lifetime and failed staging release only their owned leases after codec shutdown. A codec-worker failure drops its reuse records; it does not terminate an accepted geometry owner or erase the design.

**Important cost distinction:** no rehash/recompression of reused entries applies to the native encoder. Current Files capture and upload-delta still read/hash the complete outer Blob to prove publication integrity. Preserve those checks. Report separately: changed entry encoded bytes, reused compressed bytes, archive verification bytes, outer storage integrity bytes scanned, delta literal/copy bytes and actual network bytes. Do not report zero total hashing or zero I/O. Eliminating those integrity passes would need a separate issued-content API in Files and is not part of this packet.

## Worker/service and host contract

New Core `nativeProjectArchive` service owns one document-bound codec owner and one pending seq. No public job framework. Main-to-worker source capture is version/lifetime guarded, descriptor-only bounded metadata plus owned parts: raw strings are sent in<=256KiB credits; structured authored data is detached cooperatively under existing native limits, never a giant main JSON string. Any changed stamp aborts. The Worker alone performs UTF-8/JSON parse/encoding, role/ref validation, CRC/SHA, compression/decompression, archive traversal and layout. Do not send a single giant clone just to call it streaming.

Suggested private jobs `encode` / `decode`, bounded `part`/`ack` flow, one deadline and actual AbortSignal cancellation at the client; wrong/duplicate/out-of-order messages close the operation. Stream credits bound in-flight bytes; immutable Blob slices are preferred for backing data. A completed write returns an intrinsic Blob plus bounded receipt/source seal, never a whole Uint8Array or a second Base64 string. The seal is issued by the actual owner, not accepted as plain caller JSON.

Core API proposals:

- `prepareHostNativeArchive({signal,valid}) -> {blob,receipt,isCurrent,release}`. It captures the same authored state and manufacturing verification as current Save. Source guards are rechecked before and after asynchronous work. Receipt includes authored root, format/profile, entry/work counts and source revision; no native handles. `isCurrent` is operation-scoped, not a permanent dirty flag.
- `restoreNativeArchiveBytesInEmptyWorkspace(blob,{signal,valid})`: Worker inspects the manifest/closed roster, validates all declared content/refs, reconstructs the complete internal envelope, calls existing `preflight`, and uses existing real restore/evaluation in the isolated frame. Keep manufacturing, presentation and drawings; do not restore just model+sketches. Unknown engine/build remains unavailable/refused by existing policy; optional cache does not replace replay.

Preserve `requireEmptyWorkspace`, `DocumentJob`, source-frame verification, restore cancellation/cleanup and final same-file-version/stat checks. Only after full successful replay and action/watch preparation does the host adopt the frame, path/version/title, command document token and save baseline together. A failed archive/Open keeps the accepted document, journal and source intact. Transient journal is not persisted; normal Open resets it as today. There is no hidden future timeline or automatic model repair.

Host uses the existing `DocumentOperations` and `settleCadFileExport`: prepare is cancellable; `enterLocalWrite()` immediately precedes actual `files.write(blob, expectedVersion)`; keep phase through finish. Preserve exact committed or unknown outcomes, even if finish/currentness fails, with no blind retry or rollback write. Archive success alone is not a file commit. Retain a format-independent authored dirty/savepoint representation; never compare `.cad` bytes (including optional caches) to decide authoring dirtiness. Existing JSON baseline comparison can remain temporarily, but its main-thread cost must stay explicitly partial under ARC23; no archive cache becomes a second editable model.

## One complete qualification after coherent implementation

No test-at-each-step campaign. Root runs the source-pinned complete public original-rectangle plate chain, pattern/dimensions/regions, units/materials and drawing references through `.cad` Save/server sync/fresh login Open/reedit/resave/second Open, plus unchanged qualified STEP/core3MF exports from the same source revision. Independent ZIP reader and JSON/schema/source oracles verify the actual whole files, references, source IDs/formulas/branches/counters and raw sketch text. Export does not substitute for native persistence.

Group ordinary malformed/unsupported/version/CRC/hash/duplicate/missing-entry refusals into normal Open of own derivative files from an actual saved healthy archive; verify no adoption/state loss and healthy continuation. Do not inject a successful model or resume filesystem/security/account-race probes. Include actual cancellation and operation cleanup only through normal user operations; preserve first failures.

For cost, use genuine unchanged derived artifacts produced by the same workflow where a private producer is available. A codec-only retained optional-payload fixture must be labeled as such, not public geometry-cache acceleration. Make one small actual authored edit, compare local records/compressed payloads, then measure actual My files changed-block transfer, integrity passes, peak memory/long tasks and released leases/workers. Missing delta support reports full upload honestly; do not infer transfer savings from ZIP alone. A stale/unsupported optional cache is ignored/regenerated or explicitly unavailable while the authored project remains editable. Final capacity/performance claims follow measured evidence;128MiB admission is not a responsiveness or heap theorem.
