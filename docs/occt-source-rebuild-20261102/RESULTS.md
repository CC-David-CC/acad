# OCCT source-built replacement research — 2026-11-02

This is research evidence, not a release approval. The npm binary cannot currently be proved to correspond exactly to the indicated source. The publisher script derives its version from `git rev-parse HEAD` but does not attest that the source tree was clean or that the binary was freshly built from it. No build attestation or original full build environment was found.

A fresh source build was run in isolated R730 scratch, from the exact unmodified Autodrop3d/occt-interpreter commit `5efaf53accb45bac475155fc4d5552642c19e91e` (tree `f820351dd52207a3ad757bdeaf5510f7b4ae01fc`), with Emscripten 2.0.30, CMake 3.28.3, Node 24.19.0 and path-prefix mapping. Compiler/link subprocesses were restricted to CPUs 0–3, make used `-j4`, and a 15 GiB free-space guard covered install/build/link; free space stayed above that floor. See `build.sh`, `guard.py`, build-environment and toolchain hashes. The original project Dockerfile's compiler image is examined in `IMAGE-TOOLCHAIN-EVIDENCE.md`; original apt package versions and full build state remain unknown.

The npm tarball from the official registry was independently verified against SHA-1 `5103019257b16eef58be662d37f0ae6c091cf1c7` and its registry SHA-512 integrity. Its JS SHA-256 is `3c56e74e6e08411436a68fb930bab38aedd3137e4369af2bc67fd382e568787e` and WASM `fee4624786bb114de1d381340f05f0cdf47e6700b9fd62ef8a5dace82c8fda77`.

Fresh candidate JS matches npm byte-for-byte. Its 34,918,350-byte WASM SHA-256 is `a2b2f7daf6a4eb98b975f8aec136f6cbaf2720295ea32e71edb13ff4c5ceaecb`: same length as npm, with six changed byte positions. Prior independently compiled candidate WASM `7a7f927d4552eec7561ff0899d841cfabfdf49fe62e3ce7abfb91640c698be73` differed from npm at four positions. Thus independent builds have **not** yielded the same WASM hash, and no exact npm-byte/source correspondence is claimed. Both diffs are localized in the same defined function body 18834 and appear as permutations of branch-table labels and associated constants; the previous profiling link suggested `ShapeFix_Wire::FixGap2d`, but that identification was only provisional and behavior equivalence is not established. Compact current and previous WAT diffs are included. Full >1 GiB module disassemblies are omitted; the extraction script retains the single relevant function. The current individual function WAT SHA-256 values were `edd582344edbfb7fca741e72ac4f0e493a53be2873aee6126b7f0ecedaf1d8a2` (npm) and `49fac753051981539f4ba2dbc0a045ed79806e43dd0b625946be32f1524ca34a` (candidate).

A second relink of the **same compiled objects** using Node 14.15.5 extracted from the verified original Docker image produced exactly the same JS and WASM as the Node 24 link. It is not a separate full clean Node-14 build. `node14-npm-comparison.json` and `node24-node14-comparison.json` record the results.

Strict-CSP testing (script-src permits `wasm-unsafe-eval`, excludes JavaScript `unsafe-eval`; no CSP bypass):

- A real upstream OCCT `screw.step` fixture (`occt/data/step/screw.step`, SHA-256 `4b3649a4f5c4f05c7a06a402a91fe2fd7e3cba1615520fbd8c62a62610ad3e69`) imported with both npm and source-built WASM. Each reported 10 faces, 22 edges, 14 vertices, the same bounds, a valid shape and volume shown as 3788.27. `test/webos/occt-source-step-browser.test.cjs` asserts these baseline metrics. Importing this fixture does not establish that the differing function was called.
- The source-built candidate passed existing standalone stable topology/history, real plane/sketch/extrusion snapshot/reopen, and DXF import/undo/redo/reopen tests. These ran against a disposable local test distribution built from combined source `b63feabb`, not the live site.
- A separate throwaway desktop bundle `89bea91d205b9c1edbfb9bf2af47feee18641fdf4f879d0e37b3478fc4f8db14` was rebuilt with candidate hashes and a clearly marked test-only receipt. An isolated registered-account test passed native and OCC box actions, history, save, close/reopen, Files reopen and account isolation. The copied runtime predates the rotation tool; rotation was deliberately excluded. This did not alter production pins or live account state.

Reproduction for STEP test: serve the app/test assets on a loopback URL with the captured strict CSP; set `JSKETCHER_TEST_URL`, `CODI_TEST_CDP`, `OCCT_STEP_FIXTURE` and `NODE_PATH` (if needed for `puppeteer-core`), then run `node test/webos/occt-source-step-browser.test.cjs`. Both fixture hash and loopback endpoints are checked. The same test can be pointed at an unmodified npm build and a separately prepared source-candidate build.
