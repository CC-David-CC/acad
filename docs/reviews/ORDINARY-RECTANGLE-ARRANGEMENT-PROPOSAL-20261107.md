# Ordinary crossing-rectangle arrangement: bounded implementation proposal

Read-only source investigation,2026-11-07. **Unimplemented; no product edits, microtests, builds, Native compilation or browser qualification.** One new proposal document only. Branch base fresh ACAD97352a876e691c89ade2e4c0b021af371e1164c7, with current source read in `/tmp/codi-acad-main-20261107`; implementation would use the existing R730 checkout. Old JSketcher history, drivers/oracles and current services remain untouched.

## Smallest coherent outcome

Support the complete source→arrangement→explicit cell→real V3 polygon extrusion→source edit/reselection→shared travel→native Save/Open path for **two actual individually closed, exact axis-aligned Segment rectangles with positive-area overlap**, retaining all eight authored Segment identities and their original coordinates/constraints. Keep one authoritative sketch; derive intersections and split intervals only in Workers. Never rewrite/weld the source, invent sketch Segments, select the whole source as a fallback, parse an opaque public ID or create another authored model.

Required fixture A=[0,0]..[10,10], B=[5,0]..[15,10] has three bounded cells, not two source loops and not one union region:

| Cell meaning | Exact extent | Area mm² | Depth2mm volume mm³ |
| --- | --- | --- | --- |
| A only | [0,0]..[5,10] |50|100|
| A and B | [5,0]..[10,10] |50|100|
| B only | [10,0]..[15,10] |50|100|

This fixture also has **collinear overlapping top and bottom edges**. A proper-crossing-point-only algorithm cannot qualify it: top/bottom interval x5..10 has two genuine source owners and must appear once as a geometric boundary span. Internal vertical x5 andx10 spans are each shared by two adjacent cells with opposite traversal. Requesting separate bodies yields three bodies touching at faces; no one-solid Join/manifold-union claim is made.

Use the existing V3 Native polygon builder for each cell. No new C++/Native export, Boolean approximation of planar cells, Native default or binary-pair promotion is needed. There are real polygon requests and actual construction-history bindings; source spans must not masquerade as whole authored curves in selection metadata.

## Proposed exact Worker representation

Add NEW `modules/engine/extrusion/rectangularArrangement.mjs` and a small NEW `selectedArrangementDescriptor.mjs`. The first is a bounded geometry producer; the second defines strict data/identity capture reused by semantic preparation and metadata consumers. They are not a general geometry framework or independent saved store.

1. Admit only two independently validated four-Segment, exact local axis-aligned rectangle loops with nonzero edges/area, actual distinct source curve IDs and no additional ordinary curves in this initial arrangement branch. Points/construction curves retain their existing ignored-role semantics and original data. Existing non-overlapping/nested/disjoint/current exact-contact branches stay unchanged. Self-crossing source loops still refuse as invalid loops, not become inferred regions. Other crossing polygon/Arc/Circle sources retain explicit unsupported topology. Never silently select eight curves out of a larger source.
2. At most eight original endpoints and all actual pairwise intersections/overlap endpoints create a finite event set. Horizontal/vertical proper intersections use the actual represented x of one support and y of the other; collinear interval overlap uses exact sorted represented endpoints. No approximate intersection/weld epsilon, coordinate displacement or arbitrary extended grid lines. Reject zero/tiny intervals under the existing declared profile resolution; do not drop them as repair.
3. Split each original Segment at every event lying on its **finite** extent. Coalesce only geometrically identical atomic spans while retaining the complete sorted actual owner set. For the required fixture this gives V8/E10/Fbounded3. Each original Segment's intervals must cover its complete finite extent exactly once; a shared span contributes once geometrically and once to each genuine covering source's inventory.
4. Form two directed halfedges per atomic span, sort axis directions with exact discrete ordering (no atan-angle tolerance), and walk the left-face cycles. Preserve all actual graph incidences. Reject duplicate traversal, incomplete cover or non-simple bounded face. The unbounded face is not a selectable cell. Use the existing exact simple-polygon checks/area policy for positive cycles; this initial proper-overlap slice needs no holes. Opposite arms for generally offset axis-aligned rectangles may yield up to five bounded cells; do not invent grid subdivisions or combine disconnected same-coverage faces into one body.
5. Bind each bounded cell to which original rectangle interiors contain an actual strict interior witness. Witness selection can use finite midpoint candidates between sorted **actual event coordinates**, then exact point-in-polygon/interior tests; those probes create no graph edges and are not persisted. Require strict representable interior coordinates or refuse. This coverage is descriptive A-only/both/B-only via actual source loop memberships, never a positional array index or caller flag. Cross-check total bounded area against independently calculated rectangle union and each rectangle's covered cell-area sum. This is internal algorithm consistency, not the external acceptance oracle.

### Stable span and cell identity, no solved geometry saved

An arrangement event is described by the sorted **actual source curve IDs incident at that exact represented point**, including curves passing through its interior and all coincident support owners. Require each event description to be unique within the admitted graph. If two distinct events have the same description, refuse that identity domain; never append a coordinate or ordinal to guess a match. In this two-rectangle domain every required overlap endpoint has distinct incident side/top/bottom identities. This reference also survives simply reversing Segment traversal because it does not depend on `a` versus `b` spelling.

A source-span reference is strict data:

```text
{kind:'source-span', owners:[actualCurveId...],
 ends:[{incidentCurveIds:[actualCurveId...]},
       {incidentCurveIds:[actualCurveId...]}]}
```

Sort owners and endpoint descriptions canonically. `owners` means the curves covering the **entire** atomic span, not every curve meeting its endpoints. Derive a bounded opaque span key by SHA256 of a domain-separated canonical reference **in the Worker**; preserve the canonical reference alongside it for evidence/capture. No source coordinates, numeric interpolation parameters, solved area, Native index or new UUID are stored as authored intent. Event/owner references regenerate from actual current solved source each replay. The key is a reference, not proof; current Worker reconstruction and incidence/membership checks establish its meaning. Main-thread metadata capture checks bounded strict data/source membership; no main-thread geometry or hashing.

Canonicalize each cell's cyclic boundary sequence using span references and directed traversal; choose an orientation-independent canonical cycle for identity, retaining the actual oriented sequence privately for geometry. Include actual source face identity and coverage loop identities in the domain-separated cell signature. The public region ID should retain the existing **canonical metadata serialization** approach (`sketch-region:` plus the new versioned reference descriptor, within8192characters), not require new main-thread hashing. The Worker derives it and maps it to a current cell; strict main-thread admission can recompute its metadata serialization from the captured descriptor exactly as today, without interpreting geometry or parsing the opaque ID. Internal short span keys may still be hashed in Workers for the256-character Native geometry-request key limit; their source-span references stay attached and independently reconstructed. An edit preserving the same incidences/covering loops keeps the semantic cell key even when coordinates move; an incidence/coverage split/merge/removal changes the key and requires explicit reselection. Do not promise stable identity through every arrangement transition.

Add a strict descriptor union: leave old exactly-two-field descriptors unchanged; arrangement rows use an explicit new version/kind with `outerBoundaryRefs`, `holeBoundaryRefs` (empty initial slice), and canonical `coveringSourceLoops` using real local source curve IDs. Every boundary ref carries its opaque span key and captured canonical provenance. Public callers choose the actual returned descriptor/coverage and pass the opaque region ID unchanged. No fabricated compatibility `outerCurveIds` containing fragment keys. Keep overall64KiB metadata,8192-character supported regionID and existing source/count limits; a descriptor that exceeds them stays an explicit unsupported row, never raises ceilings silently.

Add a strict sourceAnalysis alternative `policy:'v3-extrusion-axis-rectangle-arrangement-v1'`: complete original-loop curve census once, complete source-interval partition/owner inventory, bounded-cell boundary/coverage membership. The old `v3-extrusion-isolated-open-chains` schema and its each-curve-once proof remain unchanged. The new proof accounts for every source curve once in the **source inventory**, not once across all cell boundaries; shared spans/curves appearing in several cells are deliberate and observable.

## Native and selection integration without false authored labels

Keep the saved `WORKER_SELECTED_PROFILE_EXTRUDE_V2`9-field intent unchanged: sourceface/opaque region/depth/bodyPolicy/exact engineRevision and actual featureID. Original eight Segments remain in the original native sketch. Save no new derived Segments, arrangement graph, interpolation values or alternate model. Existing native validation remains revision/schema based; actual Open replay must reconstruct and match the cell before publishing.

Extend **ephemeral** V3 region request capture with a strict optional arrangement boundary-provenance record binding each geometry curve's bounded span key to its full source-span ref. Existing V2/V3 whole-source requests stay byte/schema compatible. The two semantic Workers produce the same detached geometry/provenance from the captured source; the existing operation compares the complete signature. `captureSolidProfile`, SolidKernel types, controller request capture and resource limits preserve that data; no public geometry setter is added.

`bindPrismSourceSlots` still validates actual Native constructor edges against the supplied ordered endpoint pairs. For this branch its binding uses an explicit `sourceSpan` alternative, **not `curveId`**, and connector bindings reference the actual adjacent spans/event incidence. A NEW small arranged-prism selection builder can return planv2 directly with the existing real `sketch-profile` source context, featureID and opaque regionID. It exposes opaque selectable keys with `boundaryRef` metadata; private Native edge/face resolution remains inside the Worker. Extend strict v2 descriptor admission/equality/type contracts to retain `boundaryRef` across real Boolean/edge-treatment ancestry. Never relabel it `curveId` or infer an owner from a Native position/index. Generated blends require the same unique real attribution rule as today.

An actual selected arrangement cell may geometrically be a rectangle but is **not automatically** the existing canonical authored rectangle family. Typed rectangle bindings, semantic through-hole planning, corner recipes and drawing source endpoints must not infer that family from a four-edge cell. Keep those consumers explicitly unsupported/unresolved for new span references until they prove their semantic source/extent contract; actual generic Boolean/edge treatments can operate using the new truthful selections. Generic Native projection/STEP/controlled mesh reads may use the actual geometry, preserving normal producer/build guards. Do not disable a whole build's other capabilities or borrow legacy source bindings.

## One complete acceptance workflow after coherent integration

No tests are run at source steps. Freeze the full driver/source/oracle, then parent qualifies the composed app once:

1. Public constrained rectangleA10×10 plus four public returned Segments forB[5,0]..[15,10] on that same source; unrelated actual Point/source control. Inspect actual8 curve IDs. Raw source IDs/coords/constraint intent stay exact; no inserted intersection object.
2. Discover exactly three cells; independently verify each coverage/complete finite-span incidence from the actual saved source. Deliberately select middle, right, left using discovered descriptor provenance, each depth2/separate. Expect three valid bodies,100mm³ each, exact stated bounds; no whole-source150-area extrusion substitution. Query actual material/void/boundary points where declared.
3. Move B's four inspected left-boundary endpoint objects x5→6 through one real batch edit. A source data remains exact; cells become areas60/40/50, volumes120/80/100 and retain keys where actual incident-source provenance is unchanged. No kernel or feature IDs allocated by source edit; shared source UndoRedo restores all3 bodies and raw source. Reverse Segment traversal/source object order only through actual supported public edits, proving either invariant keys under the declared reference contract or explicit refusal; never a raw JSON reorder.
4. Same-feature reselection on a separately authored one-consumer setup: middle→left, depth2→3, interleaved region/depth travel, actual feature/outputID unchanged. Supported compatible unchanged Boolean child replays; incompatible removed span selection refuses atomically rather than retargeting.
5. Atomic source+region repair: begin with selected middle cell on the actual drivenA. Width10→4 removes overlap; ordinary source edit must refuse old cell. Existing proposed-source dimension API discovers the new disjoint full-loop regions; explicitly choose actualA orB candidate and commit one source override/region replacement, same feature. No transient accepted invalid model. Mixed repair/depth/region UndoRedo crosses new span-descriptor and existing whole-loop-descriptor branches. Other current consumers with stale cells must cause atomic refusal; do not silently repair them.
6. Unknown/stale/proposal-digest/unsupported/cancelled requests retain all accepted source/history/native/metadata/journal/counters. Nonrectangular crossing, self-crossing loop, full coincident loop and tangent Circle do not become accidental successes. No arbitrary failure accepted as unsupported.
7. Normal native Save/browser+serverSHA/fresh signedOpen re-derives exact cells and Native metrics; positive source/depth/reselection reedit, shared travel/resave/Open. Check saved intent is original sketch+9-field features only, no graph/cache/derived source or raw Native indices. Real viewable outputs, exact current build, bounded candidate/Worker/native cleanup.

Freeze independent analytic tolerances before observation: source/event incidence and raw source retention exact; volumes absolute1e-6mm³; Native bounds absolute1e-6mm; points away from ambiguous boundary except explicit boundary probes. Recomputed geometry is not the oracle: derive the three rectangles/changed intervals directly from actual authored source and literal interval intersection arithmetic outside production modules.

## Later cases and honest limit

This initial axis-aligned polygon slice is **not** full C02. General Segment polygons need robust exact represented-coordinate intersections and uniquely qualified source interval events; do not widen by tolerance. Circles need their own typed oriented arc-interval/source branch references and true line-circle/circle-circle intersections, not sampled polygon approximations. Tangency produces a contact event without positive-area lens; exact coincidence produces one geometric boundary with multiple owners and explicit duplicate intent. Their event uniqueness, interval branch, no-area-change and Native curve binding must be qualified before being offered. Existing source-span schema can motivate those additions but must not pretend straight intervals already implement curved ones.

Full coincident rectangles/loops and arbitrary overlaps are explicitly not implicitly repaired by the initial producer. Retain exact exterior point-touch and nested/disjoint paths already proved. Each later ordinary case follows the same one-source/current-cell/semantic-provenance/history contract; no migration, foreign import, assembly or advanced drawing framework is added.
