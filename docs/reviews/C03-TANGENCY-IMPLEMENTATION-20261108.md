## Finite classification follow-up

Root source review identified a prospective uncertainty in the first draft's raw atan2/modulo and exact rounded-contact endpoint fallback. No execution reproduced it. The follow-up replaces membership authority with `finiteTangencyPredicates.mjs`: existing bounded exact dyadic arithmetic operates on the represented binary64 source endpoints. It computes positive S=D·D, N=(C−A)·D and W=(A−C)S+DN; exact N versus0/S classifies Segment extent and exact half-plane/cross signs of Arc start/end/W classify the directed CCW sector. There is no division, angle tolerance, snapping, nearest-point/weld or rounded q equality in that decision.

Same-ray Arc endpoints or zero radial direction are unqualified, and a collapsed actual native represented positive sweep explicitly yields `FINITE_CONTACT_UNCERTAIN`; these are distinct from an exactly outside finite foot. The native positive sweep is only a refusal guard, never an inclusion authority. Existing arithmetic8192-bit and this constant-work10,000-operation budget fail as RESOURCE_LIMIT before classification; no truncated arithmetic or invalid-geometry inference. Original native F/Polar/ArcConsistency/domain validation and residual policy remain unchanged. Reported contact/parameters are ordinary rounded read-only observations from the endpoint foot, not saved coordinates or exact-real/trig certification. A rotated3–4–5 endpoint/interior and an actual publicly edited ambiguous-seam control belong in the complete workflow.


The narrow taxonomy/normalization follow-up uses one pure own-data code selector at the existing direct/deferred domain catch sites: RESOURCE_LIMIT retains resource-limit, finite uncertainty/unsupported retains retained-validation-failure, ordinary invalid domains retain invalid-domain. No success, equation, order or threshold changes. Direct errors keep their code/message.
