## Distinct reachable policies

1. `authoredHistoryState.mjs:4–5` defines the explicit history-control vocabulary:
   ordinary PLANE, box, selected extrusion, selected extent, through holes and
   edge treatments. Suppression itself is a smaller subset; planes/boxes cannot
   be suppressed merely because their rows are inspectable. Boolean is absent.
2. `historyControlAppendReason` at :28 rejects an unsupported new type ONLY when
   `historyStateVersion(history)===1`, which derives from an actual retained
   `suppressed:true` row. A previous session history-position/branch journal
   entry does not by itself activate that rule. With no suppressed row, a
   normal Boolean append passes this particular guard. `workerSolidCommands.ts`
   :33 reports the same conditional Boolean admission and :37 checks it before
   allocation. With a suppressed row, Boolean discovery/append truthfully refuse.
3. `workerHistoryControlCommands.ts:77` always calls `captureJob`; that calls
   `validateControlledHistory` before returning metadata. The validator's :15
   rejects ANY history row outside `HISTORY_CONTROL_TYPES`, including an active
   Boolean. It validates the complete definition, so a Boolean suffix also
   prevents inspection while reviewing an earlier prefix. This is stronger than
   the append rule because editing/prefix/branch needs complete dependency and
   suffix semantics, not just permission for ordinary unsuppressed construction.
4. The control planner derives dependencies only for its admitted selected
   constructors/through-hole/edge-treatment families. It has no Boolean two-input
   consumption/source-inheritance/suffix rules. Removing the vocabulary guard
   would therefore advertise control behavior the planner does not implement.
   `inspectWorkerHistoryControls` labels its own scope
   `numeric-modern-feature-history-v1`; it is not a general history API.
5. C11 `example.mjs:9–12` calls that service in `target()` to get `row.type` for
   the latest successful producer. The ordinary union at :66 is allowed; the
   next `retarget` at :67 re-enters this restricted metadata route and reaches
   the guard above. Normal current solid discovery in `workerSolidCommands`
   already handles actual solid/empty outputs but does not expose an authenticated
   producer operationType association, explaining the recipe's wrong dependency.
