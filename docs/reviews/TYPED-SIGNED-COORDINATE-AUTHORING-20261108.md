## Creation travel through the existing journal

A signed coordinate can legitimately move its free connected component when
created. Removing it numerically need not recover that earlier free geometry.
The typed journal previously tried only that numerical removal direction for
an insert/remove delta; it was not a complete proof of creation travel.

After the EXISTING exact one-row dimension classifier, the new private
headless/typedSignedCoordinateTravel.ts handles only SignedDistanceX/Y
insert/remove. For an actual numeric one-constant row, it derives the original
x/y numeric request from that row and recomputes addSignedDistanceTransition
from the SMALLER captured source. This is the actual original forward insertion
for either Undo or Redo direction. It succeeds only if the full larger source
bytes match the genuine reconstructed result. Row/delta structure is routing,
not solver/domain/ownership/publication authority; the real constructor proves
all retained source geometry/intent/admission and every actual inserted field.

If this genuine insertion proof does not match, the pre-existing independent
verifyDrivingDimension removal proof remains available. This preserves older
supported removal pairs, literal-string rows and custom annotation cases. Both
are bounded actual operation proofs; neither accepts a merely solvable source
pair, retries optimization toward a target, widens tolerance or substitutes
geometry. Scalar edits retain their old route. Typed Fix/coordinate/other
registered travel remains untouched, with no second journal or persistent flag.
