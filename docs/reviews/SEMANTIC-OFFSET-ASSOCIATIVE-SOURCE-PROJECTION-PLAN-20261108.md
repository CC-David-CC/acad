## A. One bounded offset generator

Reuse the existing source stage/SketchGenerator lifecycle and one sketch-bytes J transaction. Add one registered `Offset` generator with one actual source root and one allocated output root per record; begin with independently owned nongenerated Segment or full Circle only. Source discovery returns actual root ID/type/stage, current source revision, output ID if already present, semantic side choices and refusal reason. A generated or foreign source is refused before allocation in this initial closed domain. Existing Mirror and legitimate human prior-stage behavior remain unchanged; do not globally narrow their policies.

Proposed persisted record uses the existing generator container:

```text
{typeId:'Offset',stage,
 params:{objects:[actualSourceRootId],distance:<literal mm or existing named length>,side},
 generatedObjects:[actualAllocatedOutputRootId]}
side = 'left'|'right' for Segment; 'outward'|'inward' for Circle
```

The actual output root ID is the stable operation target exposed by discovery, not a parsed generator string or array ordinal. Stage/index are current revision-bound locators only. Distance is positive finite within existing length bounds; exact zero refuses a duplicate-source offset, negative/nonfinite/wrong-dimensional/unknown/cyclic values refuse without publication. The actual accepted expression service resolves names; raw bindings survive edits/travel. No numeric edit erases a name. If named generator fields need a new shared scanner branch, add precisely `Offset.params.distance` to the existing dimensional inventory, not a second expression evaluator or recursive string-as-name policy.

For a source Segment A→B, `d=B−A`, `n=(-dy,dx)/|d|`. Left output is `(A+distance*n)→(B+distance*n)`; right uses negative n. Preserve directed endpoint correspondence, physical finite segment length, source role and explicit side when endpoints reverse; do not silently swap side to preserve old world placement. For Circle C/r, output center is C and radius `r+distance` or `r−distance`; inward requires the represented derived radius to remain inside the existing positive Circle domain. Exact collapse, unsupported small output and numerical overflow have distinct domain/resource refusals; no epsilon welding, clamping or zero-radius success. No Arc/full-turn heuristic, line joins/miter/trim/corner synthesis or arbitrary chain offset is implied. Touch/intersection with another independent curve is a derived predicate, not a persisted flag or automatic merge; it must not silently change source or profile selection.

Persisted output object coordinates follow the existing Mirror cache pattern: required for ordinary source readers, **derived and verified against the generator and actual source**, never independent editable truth. A direct point/radius edit of a generated offset must refuse; editing/removing the generator uses the same shared transaction and exact original-request two-Worker verification as existing closed generators. Remove rejects live downstream consumers or carries an explicitly approved grouped source delta; no dangling constraint deletion as a side effect. Source edits regenerate the actual Offset output in Worker before final full-suffix proof, then atomically publish source/cache/model/J; read/inspection validates and never regenerates accepted bytes. All other original authored fields/IDs/stage order/frame/names are exact; unrelated free geometry remains exact. Failed generation publishes nothing.

Public proposal: `inspect-sketch-offsets`, `create-sketch-offset`, `edit-sketch-offset`, `remove-sketch-offset`, with exact current document/source revision, faceId and discovered actual source/output ID; numeric or named distance and finite side enum. No caller grouping, `trusted`, source JSON or generated-output coordinate field. Human invocation uses the same pure admission and transaction, with explicit side and full-precision distance; do not route this shared operation through the legacy integer prompt.

## B. Associative sketch source → principal XY reference projection

Use an **earlier genuine source producer and its actual source objects**, not a display mesh, sampled BRep, arbitrary CAD Face index or Native name. Initial source roots: Segment and full Circle, with actual `PLANE`/`SOURCE_FRAME_V1` owner, real source face ID and object IDs discovered under current accepted source/frame. Target is explicitly principal world XY atz0; projection direction is worldZ. Parent source local coordinates map through its current authored source frame into world, then orthogonal XY projection. This must be a genuine cross-source association, even if source/target frames happen to be parallel in the first example.

Smallest owner is a new **source-producing authored entry** `SOURCE_PROJECTION_V1` in the existing history, producing one independent target source face through the existing model source-plane representation. Reusing an existing source face while mutating it from an unrelated operation would require a broader hidden boundary writer and is rejected here. Proposed exact intent:

```text
{version:1,unit:'millimeter',featureId,
 source:{featureId:<actual earlier producer>,faceId:<actual source>,objectIds:[actual IDs]},
 target:{plane:'XY',depth:0},
 outputs:[{sourceObjectId,referenceId:<actual allocated boundary identity>}]}
```

`outputs` records stable ownership, not geometry; all actual source objects are listed and must map1:1 to output refs, with deterministic order and bounded duplicates/domain validation. Do not parse or expose existing internal `boundary/…` conventions as a selector API. Discovery returns revision-bound actual projection/reference descriptors and their original source bindings. Explicit repair can replace a particular source binding only with another actually discovered compatible earlier source object, preserving the existing output identity through an authored J delta; no nearest/coincident/first-item remap. Changing the source producer or selection is explicit repair/replacement, not ordinary numeric edit.

Public proposal: `inspect-source-projections` lists actual earlier source producers/owned eligible roots plus current projection/output bindings and reasons; `create-source-projection` takes current revision, actual source feature/face/object IDs and the fixed XY target; `repair-source-projection` takes a current discovered projection feature/output locator plus a new actual compatible source locator; `remove-source-projection` takes the current feature locator and refuses surviving dependents. Runtime inspection can return `available` or a precise reference/domain failure, never stale geometry labeled current. No generic `project`/OCI command executor or public frame/native name field. These are proposed operations, not claims about the present public registry.

Each projected Segment must remain nondegenerate in XY. A Circle whose source plane is parallel to XY projects as the same physical circle, with actual world center XY and radius. A tilted Circle projects an ellipse; first implementation must either include a real analytic Ellipse boundary representation and all consumers, or precisely refuse before publication. **Recommended initial finite domain: parallel-plane Circle and ordinary noncollapsed Segment**, because current `boundary` has no ellipse category. The complete success exercise uses a real source atz5 and pose/depth changes that retain this declared domain; it does not claim arbitrary circle-plane orientation, Arc branch or Native face projection. Source frame validation retains its current orthonormal/rigid contract; this proposal creates no new global frame threshold.

### Storage and candidate authority

The source entry/actual earlier source sketch + authored pose are the only geometry authority. Target `metadata.boundaryFrame` is the existing derived XY cache witness, and target `source.boundary` is a **persisted derived projection cache**, not an independently authored second pose or copy. New projection cache metadata records its version and deterministic captured source/frame/intent digest; no runtime epoch, Worker owner, handle or native pointer is persisted. Cache IDs/geometry must exactly match the deterministic Worker derivation from current authoritative inputs on validate-only Open/read; mismatch refuses instead of silently healing. Independent after-whole physical arithmetic uses the50pm source budget; digest/branch/ownership/identity checks remain exact. Existing relative `boundaryGeometryClose` is not sufficient authority for this new producer.

A static pre-evaluation overlay is insufficient after an earlier source pose/parameter edit. At the genuine current `SOURCE_PROJECTION_V1` history entry, the evaluator must receive the **earlier candidate's** validated source bytes + exact current produced frame. Reuse the candidate source-storage view and lexical source-producer installer pattern from `sourceFrameReplay.ts`, but with a separately reviewed operation type/run/owner/index binding; do not reuse/expand the existing Native attachment permit to arbitrary callers. One captured history/evaluation owner, monotone earlier-source dependency, one per-entry visit, strict finite source/output census, same engine-resource owner as all suffix consumers. Never use stale accepted registry faces when evaluating the changed candidate or prefix with future sources missing.

Mutation preparation issues the private one-use capability only for the exact captured proposed projection entry and actual registered run; Worker returns the bounded derived boundary/source delta before a child can read it. Normal source change, explicit repair and Undo/Redo all derive the exact complete closure, independently prove the original request, then publish the entire storage/history/J/model delta once. Validate-only native Open, diagnostics, source view, DXF/STEP/manufacturing/drawing reads may verify the cache but cannot acquire a writer or install accepted bytes. Unrelated Native graphs/pairs/catalog defaults/archive owner/Files never change. Existing observation-purpose pools remain unable to accept geometry. No temporary full-tip publication, second replay graph/journal or caller-frame overlay.

Projected references may be displayed/inspected/exported as actual reference geometry. They do not automatically become authored profile edges. Initially selected-profile consumption of Offset generators or projected-boundary-only sources must remain a precise prepublication unsupported-domain refusal unless its complete semantic ownership and source read path is explicitly integrated. Do not secretly flatten generated/reference objects into ordinary authored objects to bypass `extractSource` guards. Public primitive/constraint mutation of projected references is read-only; changing their parent or removing them goes through the semantic operation.

### Broken-reference policy requiring explicit approval

Recommended first contract uses existing last-valid transaction semantics: a public source deletion/suppression/branch that removes a live projection target refuses a precise dependency code before allocation/publication; a collapsing/out-of-domain source edit refuses its own originating domain reason. A failed reference resolution is reported as **missing/ambiguous/changed-type/frame-domain**, never a successful stale cached curve. No accepted unresolved geometry or persistence is invented.

To exercise a genuinely broken stored projection, derive an own malformed copy of a genuine publicly created `.cad`, removing the selected original object or changing only its authentic binding to another actual incompatible object; rebuild canonical CRC/hash descriptors independently. Normal public Open must reject at semantic pre-adoption `PROJECTION_REFERENCE_MISSING`/`PROJECTION_REFERENCE_TYPE` and preserve the healthy current document. This is a negative Open fixture, **not** a successful source seed or proof that an accepted unresolved projection can be saved. The main whole flow must also perform an actual explicit repair to another genuine same-source Segment/Circle and Undo/Redo restoring the old source-bound intent. If C01 requires an accepted unresolved projection to survive normal Save/Open, root should approve that additional failed-feature model contract before implementation; it cannot be silently approximated by this negative Open or ordinary deletion refusal.
