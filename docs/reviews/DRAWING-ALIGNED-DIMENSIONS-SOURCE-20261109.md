## Collision and uncertainty semantics

Lane geometry is derived in binary64 paper coordinates. Exact dyadic predicates decide represented segment/text intersection and proper/interior/overlap line crossings; floating lengths only order/search derived lanes. Grid integers are bounded to 1200 bits, with bounded orientation products/differences (at most 2404 bits). Coordinates remain within the existing finite paper domain. This is presentation arithmetic, not a new CAD/Native tolerance, snap, weld or accuracy claim.

All declared dimension/annotation/form text boxes and qualified caption boxes are known before lane planning. Text ink is still the existing conservative declared 3 mm paper policy, not a certificate for arbitrary installed-font glyphs. Real emitted projection segments detect text/stroke conflict; a view envelope that overlaps a label without that direct evidence produces `VIEW_ENVELOPE_UNCERTAINTY`, not an impossibility finding. Filled-section/hatch or conic-envelope uncertainty is not silently declared empty space.

If a bounded clear lane cannot be established, the renderer retains the complete original reference span/rays and actual text, with an explicit uncertain layout status. If a candidate lane exists but its fixed label has a declared-box conflict, it emits that improved lane while still declaring uncertainty. No label moves, hidden text, font shrinking, substituted anchors or omitted physical values occur. Uncertainty never changes physical reference availability or becomes an authored unresolved feature.

SVG metadata adds `dimensionPresentation:{version:1,role:'derived-paper-layout',status:'available'|'uncertain',dimensions:[{dimensionId,status,reason}]}` for the available dimension rows. Each dimension path and label has exact `data-dimension-id`, `data-dimension-layout` (`aligned-v1` or `uncertain-original-v1`), `data-dimension-layout-status` and optional finite `data-dimension-layout-reason`. The footer visibly adds `LAYOUT UNCERTAIN (N)` when needed. Detailed reasons are machine-readable metadata/label attributes; this is a count/status diagnostic, not an invisible replacement of a purported full warning legend. Existing full unresolved-reference warning text/membership/layout remains unchanged. Conservative uncertainty does not introduce a new mandatory legend whose own placement could refuse a previously valid export.

Reasons are finite: `DECLARED_TEXT_OUTSIDE_SHEET`, `DECLARED_TEXT_BOX_CONFLICT`, `DECLARED_TEXT_GEOMETRY_CONFLICT`, `VIEW_ENVELOPE_UNCERTAINTY`, `PROJECTED_SPAN_COLLAPSED`, `DERIVED_SPAN_UNREPRESENTABLE`, `NO_CLEAR_BOUNDED_DIMENSION_LANE`, `DIMENSION_LANE_OUTSIDE_SHEET`, `DECLARED_TEXT_STROKE_CONFLICT`, `DIMENSION_LINE_CROSSING`, `PROJECTED_GEOMETRY_LINE_CROSSING`, `ANCHOR_OR_PORT_BLOCKED`, `NO_ROUTE_IN_BOUNDED_GRAPH`. None claims no continuous layout exists. Graph obstacles for earlier diagonal strokes are deliberately conservative; graph failure remains uncertainty.
