# CAD-WORKER-DISPATCH-BLIND-01

Confirmed by source inspection before the first blind-hole browser workflow.
The frozen blind source and root267dd3d contain init/handler/controller routes
for `solid-blind-hole`, but OCI's safe-owned operation allowlist and fresh-result
token roster omit it. The first guard therefore rejects every otherwise valid
blind-hole job before Native work. This is a confirmed unreachable operation,
not an observed runtime failure or bad geometric result. The completed build
and staging of that source are not functional qualification.

Repair adds exactly the new kind under `blindHoleMode` to safe-owned admission
and adds it to the existing fresh-result-token check. No generic DRAW route,
default capability, unknown kind, token overwrite or unregistered Native pair
is admitted. The already-reviewed init still requires the exact manufacturing
pair, planar attachment, selected v3, owned shapes and Boolean history.

| State/event | Invariant |
| --- | --- |
| Unenabled/other cohort receives blind kind | Existing unsupported-operation refusal; no Native job |
| Enabled exact cohort receives blind kind | Enter the actual reviewed handler only after ordinary message admission |
| New result token | Nonempty bounded string and absent from owned shapes before any result allocation/publication |
| Result/refusal | Existing ownership, source preservation, two-result charging, cleanup and exact result capture remain |

The changed OCI source is hashed after the edit; all nine existing exact
bootstrap guards are updated together. Native JS/WASM, ABI, work quota,
geometry equations, history/J and other kind policies are unchanged. Root must
normally rebuild all graphs and run the ENTIRE corrected blind workflow plus
its FIRST independent after-whole oracle. Its real creation/edits/travel/export/
native Open phases exercise normal dispatch and retained result ownership; no
standalone injection/probe or unsupported claim of duplicate-token fault
coverage is made. Previous radius/tangent qualifications remain separate.

## Eliminate the duplicated policy

The follow-up replaces the two parallel kind arrays with ONE closed local
kind-to-creates-result policy. Every admitted kind explicitly declares whether
it produces a new owned token; the same lookup controls admission and freshness.
It is derived from the existing initialized capability modes per request, never
persisted as another flag or supplied by the caller. The old operation set and
every old result/read distinction are retained exactly, plus the repaired blind
entry. Initialization, handler dispatch and capability validation are unchanged.
There is no plugin framework or generic execution route.

This prevents a partial future repair that admits an operation while omitting
its ownership requirement from a separate list. Root reviewed every original
kind against the new table. Normal complete rebuild and public workflow remain
required; source repair does not qualify injected private messages or all other
capability modes. Later derived-drawing/counterbore integrations must extend
this same table instead of restoring parallel arrays. All nine guards track
the actual OCI source after this change.
