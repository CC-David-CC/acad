# Embedded OCI Worker and restrictive CSP

The earlier `4ed4a5ec` engine test used a fixture that allowed blob scripts. In the signed desktop fixture, the actual Worker response instead has `script-src 'self' 'wasm-unsafe-eval'`; the previous bootstrap's `importScripts(blob:)` failed with a `NetworkError`. That is a real policy incompatibility, not evidence that the profile is invalid. The desktop negative control is `tests/jsketcher-worker-csp-negative.test.mjs` in the corresponding host research branch.

This candidate keeps that CSP unchanged. The build validates the original bootstrap SHA-256 `3a02ee99f673df192c5479782db1dc82fcb7eb71d2aad604fd14a730c89d002a`, the existing derived wrapper SHA-256 `4a53dec0dceb5715d070fa7293f6515ab681f6d3de979099526e616dbd052ddc`, and WASM SHA-256 `a2b2f7daf6a4eb98b975f8aec136f6cbaf2720295ea32e71edb13ff4c5ceaecb`. It embeds that exact glue into the worker, producing SHA-256 `c8071b97322759d8beb8085dab2254fed7010cb56613035d8c3e93a5c6990921`. It rejects changed build inputs, unexpected wrapper identity and dynamic JS evaluation. Runtime fetches and hashes WASM before running the embedded glue. The old JS-path field remains in the mount manifest for interface compatibility but is not fetched or executed by this worker.

The integrity boundary is the already-required trusted, closed, immutable package inventory pin for the *combined worker*. There is no second JS source fetch between verification and execution, and no claim that a mutable server path is immutable by itself. The existing separate `occ-portable.js` remains in this research package for compatibility/provenance and is not loaded by the embedded worker. A release builder must pin and serve the combined worker, WASM, sibling profile modules and semantic/solver workers together; host packaging and source/notice review remain separate release gates.

Tests: `node --test test/engine-extrude/embedded-worker-build.test.cjs` checks reproducibility, changed glue/bootstrap and corrupted build-time WASM. `prepare-embedded-fixture.py` and `embedded-csp-browser.test.cjs` exercise a disposable strict-CSP host. Actual Chromium rejects tampered WASM and wrong wrapper identity, forces WASM heap growth from 16,777,216 to 24,903,680 bytes, confirms the exported heap accessor tracks the new view, and then builds an authored prism with measured volume 50,000 mm³ and 6 faces. The growth hook exists only in the disposable test worker. Worker termination remains the bounded native disposal boundary; this does not establish general interpreter memory safety.

A separate signed issuer/gateway plus real parent iframe fixture passed the rectangle's real width edit, OCC worker extrusion, signed save and native reopen using test-only desktop app bundle `8929536a2ce8947779aacad304a95e0ecf3a15ec87cd6b43f60c4b6076688f62`. It is not an external deployment or a complete mechanical CAD qualification. The independently observed earlier CSP failure and this success are distinct evidence.
