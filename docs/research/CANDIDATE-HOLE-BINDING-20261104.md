# Candidate-owned prism association and hole intent

This bounded package implements the first ownership/input slice in `CENTERED-THROUGH-HOLE-CONTRACT-20261104.md`. It does not construct a hole, derive a center, change native project serialization, add UI or a command, expand topology, or publish a new feature.

`centeredHoleIntent.mjs` validates and returns detached immutable plain data with exact fields: `{version:1,kind:'centered-through-hole',unit:'millimeter',featureId,target,placement:{kind:'rectangle-center'},diameter,extent:'through-all'}`. Feature IDs are distinct canonical positive safe-integer strings. The target contains the exact parent feature/body/LID and canonical four-edge authored region ID; body and LID IDs must encode that parent/region using the existing prism identity scheme and fit the current saved-reference bound. Diameter is a finite positive number no larger than 1,000,000 mm. This first validator does not accept expressions; a future operation may evaluate a separately validated authored expression before this materialized input, without replacing persisted expression intent. There is no center-coordinate field, fallback face selection, implicit direction or assumption that the circle fits. Numerical centering, finite-face containment and actual geometry are separate future validations.

`candidatePrismLedger.mjs` is a private in-process association keyed by the real evaluation owner. The rectangle adapter registers its already-preflighted and worker-validated model, exact captured source profile/binding, worker handle and topology after projection. Registration requires the exact previously created `occ-prism-v1` mount of the current candidate and invokes its real `assertPortableBinding`; it never allocates another mount. It captures bounded source data and topology, checks the actual model/body/LID and every durable traversed ID, refuses duplicate keys across candidate parents, and repeats model, owner and live binding checks on lookup. Repeated traversal of the identical object is permitted; collisions of different objects are not. A failed adapter removes its just-added association. Owner abort/close clears the ledger; accepted, sealed, foreign, stale or disposed owners cannot resolve it. Resolved data contains no handle or mount; a future cut must add its own reviewed guarded worker call rather than hand out a durable capability. The immutable captured profile and model association remain internal to trusted feature code.

This module is not an authentication boundary against malicious code executing in the same JavaScript realm. In particular, registration relies on the trusted rectangle adapter's existing semantic-worker preflight to verify the sketch bytes against their SHA-256; the mount binding independently verifies the revision/digest/face/region and exact topology, but it does not authenticate frame or depth, and registration does not itself hash arbitrary caller-provided sketch bytes. Those fields also rely on the trusted adapter's private capture and semantic-worker preflight. Never expose registration as a host command or treat it as an independent arbitrary-input source validator. The existing evaluation owner still supplies final publication and document/host validity; callers must preserve those guards.

`node --test test/coreTests/centered-hole-intent.test.mjs test/coreTests/candidate-prism-ledger.test.mjs` exercises exact schema, canonical parent/feature IDs, accessor and extra-field refusal, no coordinate-based center, duplicate/colliding semantic IDs, wrong owner/mount/generation, mutable inputs, stale model/LID, close/abort/acceptance and reentrant abort. `candidate-ledger-browser.test.cjs` uses the actual evaluation pool, real embedded OCC Worker, semantic Worker and actual projected model under self-only script CSP. It checks exact model lookup, wrong-owner refusal, owner acceptance/close refusal and document-abort cleanup. The test entry bundle is test-only; it does not expose the ledger to an application user. A strict-CSP local fixture uses the existing pinned engine inputs and the commands in `test/worker-rectangle-adapter/README.md`, substituting `candidate-webpack.config.cjs`, the built embedded worker, and `candidate-ledger-browser.test.cjs`.

Next packages still need a guarded owner-scoped worker cut, actual cylindrical/inner-loop topology and ancestry, center and containment tests, stable cut-result semantics, atomic publication/replay, then the shared visible/API path and signed persistence acceptance. Native Mesh and cross-engine inputs remain unsupported for this proposed operation; no implicit conversion is introduced.

A follow-up adds a bounded 8/12/6 derived-projection invariant at registration and every resolution. It captures the actual wrapper/topology identities, durable IDs, face and edge data/tessellation, incidence, vertex coordinates, analytic-plane/straight-curve functions and evaluated values, model coordinate system/location and registry mappings. It validates bounded lazy face-frame/matrix and straight-edge tessellation caches rather than freezing them. Real model mutation controls cover these paths while normal cache creation still succeeds. Other display-only caches, such as `Face.__2d`, are not an authority for the proposed cut; future worker computation must use the verified source profile and owned engine state. This is not a defense against arbitrary malicious code or prototype replacement in the same JavaScript realm. Revalidation is bounded by a 12,000-visit cap; one real 8/12/6 fixture averaged about 2–2.5 ms per resolution over 20 calls on the test machine, not a general performance guarantee.

The real-model browser regression additionally rejects a sparse cached coordinate, while permitting ordinary lazy frame, plane-polygon and line-tessellation cache creation. Frame/depth/source bytes remain trusted-adapter inputs rather than independently authenticated by `assertPortableBinding`.
