# Authored history menu control

Source is based on CAD d6253ea965f5e4ac489ddeefe9fd1790de5cf8ae. The Edit menu and Ctrl+Z / Ctrl+Shift+Z invoke the same revision-checked `authoredEditTravel` operation as the supported command API. Feature timeline cursor navigation remains separate. Actions refuse unavailable or busy history; a rejected asynchronous operation reports a toast and preserves its original error boundary.

Private R730 build `/mnt/data10tb/codi-authored-menu-20261105` used copied private dependencies and existing matching workers. With Node 24 and `CODI_EMBED_NUMERIC=1 CODI_EMBED_MANIFOLD=1`, webpack compiled and `tsc --noEmit` passed. `dist/static/index.bundle.js` SHA-256 `1dc4bda52e400783ae139389043f0e3d3b7306562cbf3e0fbb10823471de429b`.

`test/webos/authored-menu-browser.test.cjs` passed twice against this app in Chromium on loopback. It creates a real OCC five-hole plate using supported craft commands, exercises rectangle, depth, and corner-hole undo/redo with actual menu clicks and keyboard events, verifies geometry/history, tests that a focused browser text input receives Ctrl+Z, holds an actual OCC request to check disabled/busy behavior, and injects one rejected action to check model preservation and contained rejection. The test's injected input and rejected action are controls, not a real sketch-editor or engine-failure reproduction. The local server was a plain Python HTTP server; this is not a strict-CSP or signed desktop acceptance. Those remain necessary against this exact changed app. The existing d625 signed test passed before these changes, but does not itself qualify this build.

A further browser run opens the actual in-place sketch editor, confirms both document actions are disabled, and dispatches Ctrl+Z while the sketch editor is active; the CAD authored history is unchanged. The text-undo control still uses a test-created input, so it does not establish sketcher text-field undo behavior.

`test/webos/authored-menu-reset-browser.test.cjs` passed against the same app: a synchronous `craft.update` observer resets the document at operation start. The stale operation rejects, the new document has empty history/models and no undo entry, processing drains, and a new rectangle is subsequently accepted. This is an actual application control of the update notification; it is not a broad proof of all reentrant observers.
