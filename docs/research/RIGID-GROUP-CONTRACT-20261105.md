# Planar rigid group: bounded contract and early feasibility

This is a research candidate, not a registered feature. Initial scope is 2–32 nondegenerate authored segments with unique member and endpoint identities and a noncollinear combined profile. Endpoints may have coincident coordinates; identity must remain distinct. Existing coincidence and other external constraints remain authored constraints. No circles, arcs, splines, shared endpoint objects, nested groups, multiple ownership, or cross-stage members are admitted by this first plan.

A group retains stable member and endpoint IDs and captured local endpoint coordinates. Its explicit planar transform is `(tx, ty, angle)`. Each member endpoint `(x,y)` is related to local `(u,v)` by `x=tx+u cos(angle)-v sin(angle)` and `y=ty+u sin(angle)+v cos(angle)`. This supplies three free transform variables before external restrictions; it is not a claim that the current solver reports or certifies rank or arbitrary DOF. Creation, transform edit and dissolve must use one guarded sketch transaction. Rejection or cancellation retains the accepted sketch, constraints, workspace and history; dissolve leaves the member geometry at its current world coordinates. Exact source revisions, no overlapping groups, strict finite inputs, bounded resource behavior, lifecycle and deletion semantics still need enforcement.

Native sketch IO currently persists top-level layer objects and constraints indexed by object IDs. A group-owned transform must therefore have an explicit persisted/indexed owner (or equivalently a carefully designed stage record), with its owned parameters restored before the constraint is constructed. Avoid transient unpersisted Params, fake member IDs or hidden native handles. Same-stage ownership, references, strict validation, deletion, rollback, undo/redo and worker reconstruction must be qualified together. Members retain their real identities and external constraints; construction must not rewrite source entities or impose arbitrary pairwise locks.

`rigid-group-plan.test.mjs` checks immutable data-only planning, stable IDs, rigid-distance preservation and rejection of malformed/degenerate input. `rigid-group-solver-probe.test.mjs` exercises the real algebraic solver with a synthetic stage-owned transform and four points: ordinary external point anchors produce a translated 90-degree rotation. Its private test-only schema is neither a registered group nor a persistence/DOF/UI proof. The solver fell back from dog-leg to Levenberg–Marquardt on that case; interactive drag, failure/rollback, worker and mounted bracket controls remain required.

## Owner and real solver checkpoint

The isolated candidate now has an explicit `RigidGroup` object owning three `Param`s and a fixed, detached local frame; its proposed schema connects actual segment endpoints to that owner. Strict native preflight checks geometry and stage ownership, rejects orphan/overlapping groups, and the headless source checks both transformed geometry and every existing polynomial residual. These paths remain unqualified for release: no creation, pose, dissolve, UI, ID command, actual Worker, mounted bracket, or native browser-history test has yet been provided.

Real solver probes establish unanchored X/Y translations and rotation using temporary pose equations, and existing world-horizontal constraints retain their world-axis meaning. Merely marking group Params interactive does not command a pose: a request `(8,0,0)` was reported successful around `(1.4508,-0.6077,0.01066)`. More seriously, a conflicting synthetic pose plus world-horizontal relation was reported successful even though fresh authored equations showed a 1385.640646 mm maximum residual in both an existing Polar and the new group equation. An ordinary nongroup Polar/Horizontal/contradictory Angle control correctly rejects Angle; this is not proof of a general nongroup solver defect. The independent group geometry and fresh retained-equation checks are mandatory; shared transaction rollback restored exact captured group, members, polar values and constraint set in the probe. The test does not claim production pose publication.

The next isolated source adds shared selection/ID create, absolute pose and dissolve operations. Pose uses temporary equations and verifies the exact transform plus fresh retained equations both before and after removal; dissolve retains member coordinates and other constraints. Tests cover stale ID inspection, independent X/Y/rotation commands, world-horizontal conflict with exact transaction rollback, forced dissolve failure rollback, native preflight and raw nonvisual solver drag. The interactive safety boundary treats groups as guarded relations and restores the last valid state when geometry or retained equations fail. This remains candidate code pending actual browser/UI/Worker tests and careful review of all lifecycle and interactions.

First full-app UI run reached selected create, undo/redo and an actual member pointer drag, but the pose dialog failed its revision guard after applying. The dialog had used `AlgNumConstraint.updateConstant` on a temporary, uncommitted request; that incremented the shared sketch mutation epoch and invalidated its own inspection. The candidate now updates only that private request locally; the guard still checks actual sketch mutation before submission. The corrected browser run remains pending at this checkpoint.

A separate regression found that a directly admitted external point lock can move an accepted group while the drag rollback map still represents the earlier pose. The candidate refreshes the guarded snapshot after successful direct group admission and uses the existing transaction snapshot for direct constraint removal in a grouped stage. The control first observed the stale x=0 map after an accepted x=10 lock, then passed with the new snapshot, an invalid-drag rollback, and an injected readmission failure restoring the lock and exact member geometry. The UI and Worker runs below used the preceding build; a matching rebuild and rerun are required for this source change.

Generic member or owner deletion and direct constraint-row deletion originally left an orphan group. The isolated candidate now refuses those paths before sketch/history mutation and asks for explicit dissolve; generated members are excluded, including generated ancestry. The browser deletion and rebuilt-source reruns remain pending.

These are isolated Chromium contexts, not physical phone or signed My Files tests.

The earlier selected pose dialog failure was due to its ephemeral editor changing the shared epoch; the locally scoped request fix passed in the matching later build.
