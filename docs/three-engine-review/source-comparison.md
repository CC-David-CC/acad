# Kernel and application source comparison — checked 2026-11-05

These are source descriptions, not performance rankings or integration acceptance. A kernel computes geometry. An application supplies its own graph, constraints, history, agent interface and persistence. None of the external applications' advertised features establish those capabilities in Codi.

Its published BREPcode benchmark explicitly permits Rust/JS fallback, so those totals cannot qualify pure SMLib operation coverage or speed here. Codi's current bounded route is the pinned Rando adapter in a private per-evaluation Worker, with same-origin bootstrap and verified WASM. The independently exercised research mount returns actual SMLib solids and tessellation; it has not imported BREPcode, next.BREP.io or ClassCAD application semantics. Comparing alternative wrappers may inform API and ownership design, but switching wrappers or adopting another application is outside this acceptance checkpoint. Redistribution choices still require reviewing the exact source/notice closure; no legal compatibility conclusion is made here.
